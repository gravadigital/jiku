## Story Reference

- **Story:** [S-082](../stories/S-082.web-editor-con-lock-carpetas-busqueda-y-adjuntos.md)
- **Service:** `web`
- **Summary:** Completa el módulo `features/docs/` de la web con la parte de escritura: página
  `/docs` (carpetas por niveles + búsqueda global por texto), overlay O-11 *Nuevo documento*, editor
  markdown con vista previa en `/docs/[id]` con reserva de edición (tomar, renovar cada 60 s,
  liberar; `pagehide` con `keepalive` vía un BFF nuevo), manejo de `version_conflict` y
  `document_locked` sin perder nunca el texto propio, subida de adjuntos (SHA-256 en el navegador →
  `POST /api/docs/attachments` → `putFileToStorage` → `confirm` → enlace insertado) y solo lectura
  para documentos grandes (`contentUrl`).

**Fuera de esta story (no implementar acá):** botón "Compartir" y overlay O-12 → **S-083**.
Historial de versiones, mover, borrar y restaurar documentos, administrar carpetas y permisos →
fuera de la interfaz en esta entrega (REQ-016). El `force` del unlock **nunca** se expone.

**Ya existe (S-081, Completed) y se extiende:** `features/docs/` (tipos, `docsApi.ts`,
`modulesApi.ts`, `useModule(s)`, `useDocument(s)`, `DocsPanel`, `DocsNotice`, `DocumentView`,
`DocumentBreadcrumb`, `DocumentContent`, `DocumentRelations`, utils `paths`/`persons`/`dates`/
`docsUrlTransform`/`moduleInvalidation`), la página `(loggedin)/docs/[id]/page.tsx` y el route handler
`app/docs/attachments/[id]/route.ts`. El ítem de sidebar ya apunta a `/docs`: **esta story cierra la
brecha transitoria** (`/docs` hoy responde 404).

**Datos en tres capas:** componente cliente → hook (`useQuery` / `useMutation`) → Server Action
(`'use server'`, `apiClient`) → api. La única excepción es la liberación con `keepalive` en
`pagehide`, que va por el BFF porque un Server Action no corre en ese evento.

**Manejo de errores:** el interceptor de axios normaliza todo fallo a
`ApiError { code, message, status }`. Esta story le agrega `details?` (aditivo) porque
`document_locked` y `version_conflict` traen datos que la UI necesita (`holder`, `via`,
`expiresAt`, `currentVersion`). Estados de datos de un componente, en orden:
**loading → error → empty → happy path**. Ningún error se muestra como "vacío".

**Logging:** ESLint permite solo `console.warn` / `console.error`. **Nunca loguear token, sesión,
contenido de documentos, `uploadUrl` ni URLs prefirmadas** (REQ-016 §Seguridad).

**Testing:** Vitest + Testing Library; se mockea la capa de **services** (al testear un hook) o de
**hooks** (al testear un componente). Se mockea `apiClient` al testear Server Actions (patrón de
`docsApi.test.ts`), y `fetch` global solo en el route handler y en `releaseLockKeepalive`. Nombres
de test en español; consultas por rol y nombre accesible; timers falsos para la renovación de 60 s.

### Relevant ADRs

- **ADR-009: Token confinado al servidor**
  - Decision: el access token de Zitadel vive solo en el servidor de Next; el navegador nunca lo ve.
  - Implementation Rules:
    - El access token **NO DEBE** llegar al navegador por ningún camino: ni en el bundle, ni en una
      respuesta, ni en una cookie legible por JS.
    - La URL de la api **DEBE** leerse de `API_URL` **en el servidor, en runtime**. **NO SE DEBE**
      usar `NEXT_PUBLIC_API_URL` ni ninguna variable horneada en build.
    - En `web`, toda llamada de dominio **DEBE** ir por un Server Action (`'use server'`) con
      `apiClient`. Un route handler en `app/api/` **DEBE** justificarse por una capacidad que el Server
      Action no tenga (streaming, headers de respuesta, llamada desde componente cliente).
    - En `opus-web`, toda llamada **DEBE** ir por el proxy `/api/opus/[...path]`. **NO SE DEBE**
      agregar un cliente axios que apunte directo a `API_URL` desde el navegador.
    - Todo route handler que reenvíe a la api **DEBE** exigir sesión y responder
      `401 {"error":"Unauthorized"}` si no hay `accessToken`. La única excepción vigente es
      `GET /attachments/[id]/[fileName]` de `opus-web`, cuya autorización la decide la api.
    - Al reenviar respuestas binarias, **DEBEN** propagarse `Content-Type`, `Content-Disposition` y
      `Content-Length`.
    - Al reenviar uploads **DEBE** usarse streaming con `duplex: 'half'`, no bufferizar el archivo
      entero en memoria.
    - Un 401 de la api **DEBE** redirigir el navegador a `/login`.
    - **NO SE DEBE** agregar `NEXT_PUBLIC_*` funcional: rompería la premisa de una imagen por todos los
      entornos.
  - Aplicación en esta story: el BFF `POST /api/docs/documents/[id]/unlock` se justifica porque
    **un Server Action no corre en `pagehide`** (la página se está descargando) y `fetch` con
    `keepalive: true` sí. La subida de adjuntos **no** pasa por ningún BFF: el byte va del navegador
    a la `uploadUrl` prefirmada con `putFileToStorage` (regla de `api-routes`: "no reintroducir un
    handler que transporte binarios").

- **ADR-011: TanStack Query**
  - Implementation Rules:
    - Todo dato que venga de la api **DEBE** manejarse con TanStack Query. **NO SE DEBE** copiar una
      respuesta a `useState` ni a un store global.
    - Las query keys **DEBEN** seguir el patrón por dominio: `['<dominio>', <identificador o filtros>]`.
    - Tras una mutación exitosa **DEBE** invalidarse la key afectada. Al invalidar por prefijo, hay que
      verificar que el prefijo cubra lo que se pretende.
    - Las mutations **DEBEN** mantener `retry: 0`. Reintentar una escritura sin idempotencia
      garantizada duplicaría datos ([ADR-002](ADR-002-comandos-nats-sin-jetstream.md)).
    - El update optimista **DEBE** usarse solo donde el rollback sea trivial y la latencia se note. **NO
      SE DEBE** aplicar por default.
    - El estado propio de la interfaz **DEBE** usar `useState` local. Un Context nuevo **DEBE**
      justificarse por tener consumidores reales.
    - En listados paginados por categoría, **DEBE** evaluarse el costo de montar N queries en paralelo:
      el tablero del portal monta 7 y su `isLoading` es un `some`, así que la pantalla espera a la más
      lenta.
  - Aplicación: el **borrador del editor** (`draft`), la **versión base** (`baseVersion`) y el
    `sessionId` son estado de interfaz → `useState` local. **No** se derivan del query
    `['docs-document', id]`: ese query se refresca (foco de ventana, invalidaciones) y cambiaría la
    base en medio de la edición. Sin update optimista en ninguna mutación de esta story.

- **ADR-010: Sass + CSS Modules sin librería**
  - Implementation Rules:
    - Los estilos de un componente **DEBEN** vivir en su `*.module.scss` adyacente. **NO SE DEBE**
      usar CSS global salvo en `globals.scss` y en la capa de tokens.
    - Los valores de color, espaciado y tipografía **DEBEN** referenciar custom properties de
      `_variables.scss`. **NO SE DEBEN** hardcodear valores hexadecimales ni píxeles sueltos.
    - Los patrones visuales repetidos (tipografía, botones, inputs, tags, focus rings) **DEBEN** usar
      los mixins de `_mixins.scss`.
    - Los breakpoints **DEBEN** declararse con los mixins de `_mixins.scss`. **NO SE DEBEN** escribir
      `@media` crudas con valores literales — hoy hay 14 en `web` con 8 valores distintos, y es deuda
      reconocida (NFR-U03).
    - **NO SE DEBE** agregar una librería de componentes ni un framework CSS utilitario sin un ADR que
      lo reemplace.
    - En `opus-web`, las variantes de componente **DEBEN** expresarse con atributos `data-*`, no con
      nombres de clase compuestos.
    - Un valor de token **DEBE** declararse en un solo lugar.
  - **Precisión vigente (convención `styling`, REQ-013):** los tokens se consumen del **tier
    semántico o de componente** (`_semantic.scss` / `_component.scss`), **nunca** primitivos ni hex.
    El guardia `features/design-system-migration.guard.test.ts` falla si aparecen tokens viejos de
    `_variables.scss`, hex literales, radios fuera de 8/10/14/999, `<button>` o `<table>` crudos,
    `font-size` en px, `font-weight` numérico o `font-family` con `system-ui`/`Roboto` en cualquier
    `.tsx` / `.module.scss` de `web/src`.

- **ADR-002: Comandos NATS sin JetStream** (citado por ADR-011) — sin acuse ni idempotencia: un
  `504` en una escritura significa "pudo haberse aplicado". Por eso **ninguna escritura se
  reintenta sola** (CA-30: "nunca reintenta en silencio").

- **ADR-015 "Módulos opcionales del bus"** (DD-17 de REQ-016) todavía no existe: lo escribe S-085.
  Las decisiones que aplican se copian abajo desde REQ-016.

### API Context

Todas las llamadas salen de Server Actions con `apiClient` (Bearer inyectado por el interceptor),
salvo el BFF de unlock (fetch nativo con el token de `decodedToken()`). El `baseURL` ya incluye
`/api`: se llama `apiClient.post('/docs/documents')`, no `/api/docs/documents`.

**Reglas comunes a todas las rutas `/docs/*`** (verbatim de `api.yaml`): `x-roles: [admin, user]`,
`x-jiku-module: docs`. "La api no autoriza el dominio de documentación (REQ-016, DD-2): jiku-docs
resuelve el ACL con el `actor` (el `sub` del token) y responde `permission_denied`. `requireModule` va
antes que el rol. Las reglas de dominio las valida jiku-docs y su `code` llega sin traducir (DD-7). Un
`id` mal formado responde 404 sin llamar al bus." Un parámetro o campo no declarado es **400
`invalid_fields`**: **no mandar claves vacías ni `undefined`** (helper `definedOnly` ya existe en
`docsApi.ts`). Todas las escrituras tienen `additionalProperties: false`.

#### Lectura (S-078)

**`GET /docs/folders`** — "Llama a `folders.list` con `sort: ['name']` e
`include: ['effectivePermission']`."

| Query param | Tipo |
|---|---|
| `parentId` | string ULID `^[0-9A-HJKMNP-TV-Z]{26}$` |
| `pathPrefix` | string 1-500 |
| `limit` | integer 1-200, default 50 |
| `cursor` | string ≤ 500 — `page.cursor` de la respuesta anterior; **su ausencia es el fin** |

→ `200 DocsFolderPage`. Errores: 400, 401, 403, 404 `ModuleNotInstalled`, 500, 503, 504.

**`GET /docs/folders/{id}`** — "Llama a `folders.get` con `include: ['effectivePermission']` (sin
`acl`). Un `id` mal formado responde 404 `folder_not_found` sin llamar al bus." → `200 DocsFolder`.
Errores: 401, 403 (`permission_denied`), **404 `ModuleNotFound`** (`folder_not_found` |
`module_not_installed`), 500, 503, 504.

### Flow Context

El flujo `documentos-desde-la-web` (`docs/flows/documentos-desde-la-web.md`) es **nuevo y todavía no
está escrito** (lo escribe S-085). La fuente actual es REQ-016, escenarios C y D (verbatim):

**Escenario C — edición con lock y versión base (CA-17, CA-18, CA-29, CA-30)**

**Trigger:** la persona pulsa "Editar" en `/docs/{id}` (con `folder.effectivePermission` `write` o
`manage`).

1. **[web]** genera `sessionId` (ULID) y llama `POST /api/docs/documents/{id}/lock { sessionId }`.
   - `409 document_locked` → solo lectura con "{holder} lo está editando hasta {expiresAt}" (el
     `holder` es un `sub`; la web lo resuelve contra `GET /persons`, con fallback "otra persona").
2. **[api]** `documents.{id}.lock { actor, sessionId, via: "human" }` → `{ id, sessionId,
   expiresAt }` (TTL default 120 s).
3. **[web]** renueva cada 60 s repitiendo el lock con el mismo `sessionId` mientras el editor está
   abierto (CA-29).
4. **[web → api]** guardar: `PUT /api/docs/documents/{id} { baseVersion: 6, content, sessionId }`.
5. **[api]** calcula `checksum = "sha256:" + hex(sha256(utf8(content)))` y publica
   `documents.{id}.update { actor, baseVersion: 6, content, checksum, sessionId, via: "human" }`.
   - Éxito → `200 { id, version: 7 }`; la web libera con `POST …/unlock { sessionId }` y vuelve al
     visor.
   - **`version_conflict`** → `409 { code, message, details: { currentVersion: 7 } }` (CA-17). La
     web conserva el texto propio en el editor, avisa que hay otra versión y ofrece recargarla al
     lado para copiar (CA-30). Nunca reintenta en silencio.
   - **`document_locked`** → `409 { …, details: { holder, via, expiresAt } }` (CA-18).
6. **[web]** cancelar o salir: `unlock`. Cierre de pestaña: `pagehide` →
   `fetch('/api/docs/documents/{id}/unlock', { method: 'POST', keepalive: true })` al BFF nuevo de
   la web (un Server Action no corre en `pagehide`). Si nada de eso llega, el lock vence a los 120 s.

**Outcome:** una versión nueva, sin pisar cambios ajenos.
**Notas:** documento con `contentUrl` (> 256 KiB) → no se ofrece "Editar".
**Manejo de errores (story):** reserva perdida (renovación falla) → sub-estado *reserva perdida* con
el texto propio conservado; `permission_denied` → aviso y editor de solo lectura.

**Escenario D — subida de adjunto (CA-S14)**

"El editor pide `POST /api/docs/attachments { documentId, fileName, mimeType, fileSize, checksum }`
(checksum SHA-256 calculado en el navegador con `crypto.subtle`), hace `PUT` a `uploadUrl` con el
`putFileToStorage` existente, llama `…/confirm` e inserta `![nombre]({link})`. Por dentro jiku-docs
delega en `files.request-upload` / `files.{fileId}.request-download` de core (D-3): el archivo
**nunca** se vincula (RF-11, CA-15)." Errores: `attachment_type_not_allowed` /
`attachment_too_large` → mensaje sobre la zona de adjuntos.

**Esta story implementa:** todos los pasos de `web` de C (1, 3, 4, 5-respuesta, 6) y la subida de D.

  request: NextRequest,
  { params }: { params: Promise<{ id: string }> }

  const token = await decodedToken();
  if (!token?.accessToken) {
    return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });

    return NextResponse.json({ error: 'Server configuration error' }, { status: 500 });

    body: JSON.stringify({ sessionId }),

- **titulo-documentacion** — `"Documentación"`. `ViewHeader` sin breadcrumb propio: el breadcrumb de
  esta vista es el de carpetas, que vive debajo del título.
- **breadcrumb-carpeta** — `"Inicio"` como primer nivel (la raíz), luego un nivel por carpeta de la
  ruta, el último sin enlace. La carpeta actual viaja en la URL (`?folder={id}`), así que el nivel
  sobrevive a recargar y se puede compartir.
- **busqueda-documentos** — placeholder `"Buscar en la documentación"`; ícono search. Busca en todo lo
  que la persona puede leer, **no solo en la carpeta actual**. Debounce de 300 ms; el texto viaja en la
  URL (`?q=`). Vaciar el campo vuelve a la carpeta en la que se estaba.
- **boton-nuevo-documento** — `"Nuevo documento"`; ícono plus. **No se renderiza** si la carpeta
  actual no da `write` ni `manage`. En la raíz (`Inicio`) tampoco: un documento siempre vive en una
  carpeta.
- **tabla-carpeta** — columnas `"Nombre"` · `"Actualizado"` · `"Por"`. Subcarpetas primero, con ícono
  de carpeta y sin fecha; documentos después, con ícono de archivo, ordenados por última actualización.
  Fila entera clickeable y enfocable (`<a>` en la celda del nombre). `"Por"` resuelve el `updatedBy`
  contra las personas de Jiku; si no lo encuentra, `"Otra persona"`. Fecha `DD/MM/AAAA HH:mm`.
- **marca-en-edicion** — `"En edición"`; ícono lock. `Badge` neutro. Nombre accesible `"{persona} lo
  está editando"`. Informa, no bloquea.
- **boton-ver-mas** — `"Ver más"`. Pagina por cursor; no se usa `Pagination` (no hay total).
- **resultados-busqueda** — columnas `"Documento"` · `"Carpeta"` · `"Actualizado"`; debajo del
  título, el fragmento donde aparece el texto buscado, con la coincidencia resaltada. El fragmento
  viene del módulo ya recortado; la web solo lo resalta, **nunca lo interpreta como HTML**.
- **vacio-carpeta** — `"Esta carpeta está vacía."` y, si la persona puede escribir en ella, `"Creá el
  primer documento con «Nuevo documento»."`; ícono folder; `EmptyState` `list`.
- **vacio-busqueda** — `"No hay documentos que coincidan con «{texto}»."` · `"Probá con otras
  palabras."`; ícono search; `EmptyState` `filtered`.
- **cargando-carpeta** — `"Cargando documentación…"`. `Loader` `block` dentro del panel; encabezado y
  búsqueda quedan visibles.
- **aviso-no-disponible** — `"La documentación no está disponible en este momento. Probá de nuevo en
  unos minutos."`; ícono warning. Cuando el módulo vuelve a `available` el aviso desaparece y la
  carpeta se carga sola.
- **aviso-error** — `"No se pudo cargar la carpeta. Actualizá la página."` · en búsqueda: `"No se pudo
  buscar. Intentá de nuevo."`; ícono error; `role="alert"`. Un `403` en una carpeta muestra `"No tenés
  permiso para ver esta carpeta."` en el mismo bloque.

**Estados:**

- **default** — la carpeta actual con su contenido.
- **empty** — `"Esta carpeta está vacía."`; tabla-carpeta oculta, vacio-carpeta visible.
- **loading** — `"Cargando documentación…"`; cargando-carpeta en el lugar de la tabla; búsqueda y
  breadcrumb visibles y operables.
- **error de validación** — no aplica (la validación del alta vive en O-11).
- **error de sistema / sin conexión** — `"No se pudo cargar la carpeta. Actualizá la página."`;
  aviso-error visible; tabla oculta.
- **success** — no aplica (el alta navega al documento).
- **not found** — `"Esta carpeta no existe o no tenés permiso para verla."`; aviso-error con este
  texto; breadcrumb-carpeta solo `"Inicio"`. Disparado por `folder_not_found` / `permission_denied`
  sobre `?folder=`.
- **estado terminal / readonly** (por carpeta) — boton-nuevo-documento no se renderiza.
- **resultados de búsqueda** (parent: default) — resultados-busqueda visible; tabla-carpeta,
  breadcrumb-carpeta y boton-nuevo-documento ocultos.
- **sin resultados** (parent: resultados de búsqueda) — `"No hay documentos que coincidan con
  «{texto}»."`; vacio-busqueda visible; resultados ocultos.
- **módulo no disponible** (parent: default) — aviso-no-disponible visible; busqueda-documentos
  disabled; boton-nuevo-documento disabled; tabla-carpeta oculta.

**Interacciones:** fila de subcarpeta · click / `Enter` → `/docs?folder={id}`; fila de documento →

boton-nuevo-documento → abre O-11 con la carpeta actual fijada; boton-ver-mas → página siguiente.
**Validación:** búsqueda con menos de 2 caracteres → no se busca, sin mensaje (se sigue mostrando la
carpeta). **Feedback:** un `module_unavailable` en cualquier consulta invalida el estado del módulo y
lleva a *módulo no disponible* sin esperar el sondeo.

**Accesibilidad:** `main` con un único h1 (`"Documentación"`); el breadcrumb es
`<nav aria-label="Ruta de la carpeta">`. Al abrir O-11 el foco va a su primer campo y vuelve a
boton-nuevo-documento al cerrarlo. El cambio entre carpeta y resultados se anuncia en una región live
(`"{n} resultados"` / `"Sin resultados"`). (Orden de foco: ver P-12.)

**Decisiones:** navegación por niveles —breadcrumb + una tabla— en vez de árbol lateral; subcarpetas y
documentos en la misma tabla, carpetas primero; la búsqueda es global; "Nuevo documento" solo con
permiso y nunca en la raíz; sin columna de visibilidad; "Ver más" y no `Pagination`. Descartados:
filtros por proyecto/requisito/tarea en esta pantalla; mover, borrar y restaurar.

- **boton-guardar** — `"Guardar"`; en *conflicto de versión*, `"Guardar sobre la versión {n}"`; ícono
  check. Guarda con la versión sobre la que se empezó a editar. En conflicto la base pasa a ser la
  versión actual: guardar ahí es una decisión explícita, **nunca un reintento automático** [CA-30].
- **boton-cancelar** — `"Cancelar"`. Con cambios sin guardar pide confirmación con **O-02**
  (`"Descartar cambios"` · `"Vas a perder lo que escribiste desde la última vez que guardaste."` ·
  `"Descartar"` / `"Seguir editando"`). Libera la reserva.
- **aviso-conflicto** — `"{persona} guardó la versión {n} mientras editabas. Tu texto sigue acá:
  compará con la versión actual y guardá cuando estés listo."`; ícono warning; `role="alert"`.
- **aviso-reserva-perdida** — `"Se perdió la reserva de edición. Tu texto sigue acá; si nadie más lo
  tomó, vas a poder guardar igual."`; ícono warning. Aparece si una renovación falla. Al guardar, si
  otra persona tiene la reserva, pasa a *bloqueado* conservando el texto en el editor (P-14).
- **toast-resultado** — éxito `"Guardaste la versión {n}."` · éxito con aviso `"Guardaste la versión
  {n}. Revisalo: parece contener una clave o un token."` · error `"No se pudo guardar. Tu texto sigue
  en el editor; intentá de nuevo."`. El aviso de posible secreto no bloquea.

**Estados:**

- **default** — lectura.
- **error de validación** — errores del módulo al guardar: `"El frontmatter no es válido: {detalle}.
  Corregilo y volvé a guardar."` (`frontmatter_invalid`) · `"Uno de los vínculos no existe:
  {detalle}."` (`invalid_relation`) · `"El documento supera los 256 KiB que se pueden guardar desde
  acá."` (`content_too_large`) → editor-markdown state=error con el mensaje debajo; boton-guardar
  habilitado. `{detalle}` = `error.message` del módulo, verbatim.
- **error de sistema / sin conexión** — toast error; el editor conserva el texto.
- **success** — toast success; vuelve a *default* con la versión nueva y la reserva liberada.
- **estado terminal / readonly** — sin permiso de escritura: boton-editar no se renderiza; documento
  grande: además aviso-documento-grande.
- **bloqueado por otra persona** (parent: default) [CA-18] — aviso-bloqueado visible; boton-editar
  disabled. Se revisa al volver a la pestaña y cada 60 s: cuando la reserva vence, el aviso desaparece
  y "Editar" se habilita.
- **editando** (parent: default) [CA-29] — indicador-reserva, editor-markdown, vista-previa,
  zona-adjuntar, campo-mensaje, boton-guardar, boton-cancelar visibles; contenido-documento,
  boton-editar, boton-compartir, card-vinculos y card-adjuntos-documento ocultos.
- **conflicto de versión** (parent: editando) [CA-17, CA-30] — aviso-conflicto visible; version-actual
  en lugar de vista-previa; boton-guardar `"Guardar sobre la versión {n}"`; zona-adjuntar oculta.
- **reserva perdida** (parent: editando) — aviso-reserva-perdida visible; indicador-reserva oculto.
- **módulo no disponible** (parent: default) — aviso-no-disponible; boton-editar disabled; contenido
  se muestra si ya estaba cargado.

**Interacciones:** boton-editar → `POST …/lock` con un `sessionId` nuevo; éxito → *editando*;
`document_locked` → *bloqueado*. Editor abierto · cada 60 s → renueva con el mismo `sessionId`; falla →
*reserva perdida*. boton-guardar → `PUT /docs/documents/{id}` con la versión base; éxito → libera y
vuelve a *default*; `version_conflict` → *conflicto*; `document_locked` → *bloqueado* conservando el
texto. boton-cancelar → (O-02 si hay cambios) libera y vuelve a *default*. Cerrar la pestaña o salir de
la ruta con el editor abierto → libera con un pedido `keepalive`; si no llega, vence a los 120 s.
zona-adjuntar → pide la subida, sube, confirma e inserta en el cursor. **Validaciones:** el módulo
valida al guardar; la web no anticipa el formato del frontmatter. **Feedback:** guardado → toast y
vuelta a lectura con la versión nueva en meta-version; navegar fuera con cambios sin guardar →
confirmación del navegador (`beforeunload`).

**Accesibilidad (verbatim):** en edición: editor-markdown → zona-adjuntar → campo-mensaje →
boton-cancelar → boton-guardar. Al entrar en edición el foco va a editor-markdown; al guardar o
cancelar vuelve a boton-editar. aviso-conflicto, aviso-reserva-perdida y aviso-bloqueado (cuando
aparece al pulsar "Editar") se anuncian con `role="alert"`; la renovación silenciosa no se anuncia.

**Decisiones (verbatim):** editor de markdown plano con vista previa al lado, no WYSIWYG; vista previa
en columna y no en pestaña; un visor y un editor en la misma ruta (una ruta `/edit` haría que recargar
soltara la reserva); la reserva es invisible mientras funciona (sin cuenta regresiva); el conflicto
conserva el texto propio y muestra el ajeno al lado, en texto plano (sin diff automático); sin
historial, mover, borrar ni restaurar. Descartados: overlay de edición a pantalla completa; notificar
en vivo que otra persona guardó (la web no escucha el bus).

#### Flujos de usuario relevantes (web `user-flows.md`, Flujo 5, filtrado)

**Flujo 5: Consultar y corregir la documentación de un proyecto.** JTBD: *"Cuando trabajo en un
proyecto, quiero tener a mano lo que está escrito sobre él y poder corregirlo, sin pisar lo que otro
esté escribiendo al mismo tiempo."* Trigger: la card "Documentación" de una ficha, o "Documentación"
en la sidebar.

Happy path: 1-2 (S-081) → 3. Pulsa **"Editar"** → toma la reserva y abre el editor con vista previa;
la reserva se renueva sola [CA-29] → 4. Escribe; si necesita una imagen, la arrastra a la zona de
adjuntos y el enlace queda insertado → 5. **"Guardar"** → versión nueva, reserva liberada, vuelta a la
lectura con `"Guardaste la versión {n}."`.

Alternativos: **buscar en vez de navegar** (búsqueda global en documentacion); **recorrer carpetas**
(breadcrumb + tabla por niveles; la carpeta queda en la URL); **crear un documento** (O-11 pide título
y nombre y abre el editor); **documento grande** (> 256 KiB: se lee, no se edita).

Errores: **otra persona lo está editando** (aviso; "Editar" se habilita cuando la reserva vence)
[CA-18]; **alguien guardó mientras editaba** (texto propio en el editor, versión ajena al lado en texto
plano; `"Guardar sobre la versión {n}"`, nunca reintento automático) [CA-17, CA-30]; **se perdió la
reserva** (aviso, texto conservado, guardar sigue disponible); **frontmatter inválido o vínculo
inexistente** (mensaje del módulo debajo del editor); **módulo caído** (aviso, acciones deshabilitadas,
vuelven solas); **cerrar la pestaña editando** (`keepalive`; si no llega, vence a los 120 s).

Estado final: el documento tiene una versión nueva, sin haber pisado cambios ajenos, y la reserva está
libre.

No aplica a esta story (la visibilidad `internal`/`public` se cambia en el frontmatter desde el
editor; el badge de visibilidad ya existe desde S-081).

### Task 4: Ciclo de vida de la reserva — `useEditSession`

**Status:** Completed

#### Description

Hook que encapsula la reserva de edición: toma con un `sessionId` nuevo, renovación cada 60 s,
detección de reserva perdida y de bloqueo, liberación explícita y liberación `keepalive` en `pagehide`
y desmontaje. Es la pieza que garantiza CA-29 y R-7.

#### Acceptance Criteria

1. `useEditSession({ documentId })` devuelve `{ phase: 'idle' | 'acquiring' | 'editing' | 'lost',
   sessionId: string | null, blockedBy: DocsLock-like | null, start(): Promise<'ok' | 'locked' |
   DocsError>, release(): Promise<void>, markBlocked(details): void, clearBlocked(): void }`.
2. `start()` genera `newUlid()`, llama `lockDocument`; éxito → `editing` + intervalo de 60 000 ms;
   `document_locked` → `idle` + `blockedBy` con `details` (TS-39, TS-40); `module_unavailable` →
   invalida `['modules']`; otros → devuelve el error y vuelve a `idle`.
3. Cada tick renueva con **el mismo** `sessionId`: éxito → `editing` (también desde `lost`); error →
   `lost`; `document_locked` → `lost` + `blockedBy` (TS-41, TS-42).
4. `release()` corta el intervalo, llama `unlockDocument` y vuelve a `idle` con `sessionId: null`;
   cualquier error del unlock se traga con comentario (`lock_not_held` = ya no la tenía; si no, vence a
   los 120 s) (TS-43).
5. Mientras `phase` es `editing` o `lost`: listener de `pagehide` y cleanup de desmontaje llaman
   `releaseLockKeepalive(documentId, sessionId)`; en `idle` no (TS-44). El intervalo se limpia siempre
   al desmontar.
6. La renovación no muestra nada ni se anuncia (estado de UI puro).

#### Technical Details

**Architectural Context References:**
- Flow Context, escenario C (pasos 1, 3, 6) y semántica del lock (renovación idempotente con el mismo
  `sessionId`; TTL 120 s).
- ADR-011: `sessionId`, `phase` y `blockedBy` son `useState` local; no son datos de la api.
- P-3, P-14. Reusable: `lockDocument`, `unlockDocument` (T1), `releaseLockKeepalive` (T2),
  `isModuleUnavailable`.

**Files to Create/Modify:**
- `src/features/docs/hooks/useEditSession.ts` (nuevo) + `useEditSession.test.tsx`

**Implementation Notes:**
- Guardar `sessionId` también en un `useRef` para que el handler de `pagehide` y el cleanup lean el
  valor vigente sin re-suscribirse.
- No usar `setInterval` con closures viejas: el tick lee el `ref`.
- `lockDocument` devuelve `DocsResult`: no hace falta `try/catch` para los errores de la api; sí para un
  fallo de red del Server Action (→ tratar como error genérico: `lost` en un tick, error en `start`).
- No mandar `ttlSeconds`.

**Dependencies:** services de T1 y T2; `@tanstack/react-query` (`useQueryClient` para invalidar
`['modules']`).

## Implementation Notes (S-082 / web)

**Desvíos y decisiones tomadas al implementar**

- **P-2 extendido a las lecturas (delegado por el dueño del producto).** Las Server Actions de
  `features/docs` no tenían un patrón previo de resultado: todas lanzaban el `ApiError`. Un error lanzado
  desde un Server Action llega al navegador sin `code`/`details` en el build de producción, de modo que
  las lecturas de S-081 (`document_not_found`, `module_unavailable`) perdían la señal que usa la UI
  (estado *not found*, invalidación de `['modules']`, no reintentar). Se corrigió dentro de esta story:
  **todas** las Server Actions de docs (`listDocuments`, `getDocument`, `searchDocuments`, `listFolders`,
  `listAllFolders`, `getFolderTrail`, y las de escritura/adjuntos) devuelven `DocsResult<T> =
  { ok: true; data } | { ok: false; error }` y los hooks re-lanzan con `unwrap` del lado del cliente. Los
  tests de `docsApi`, `useDocument` y `useDocuments` se ajustaron a esa forma. Efecto sobre los
  escenarios: TS-8, TS-9, TS-10, TS-13 a TS-15 verifican `{ ok, data|error }` en lugar de un rechazo.
  `getModules` no cambia (su fallo equivale a `not_installed` para la UI y no usa `code`).
- `utils/docsResult.ts` (`toResult`, `unwrap`) centraliza el patrón; no puede vivir en un archivo
  `'use server'` (solo exporta funciones async).
- `sha256Checksum` usa `FileReader` como respaldo cuando `Blob.arrayBuffer` no existe (jsdom).
- `useEditSession` devuelve también `sessionId`, y `markBlocked(details)` deja la fase en `lost` para que
  la renovación reintente tomar la reserva (P-14).
- Los avisos del editor (conflicto, bloqueado, reserva perdida) viven en `DocumentEditor`;
  `DocumentView` muestra solo no disponible / bloqueado / documento grande y pasa `suppressNotices`
  cuando el módulo está caído (prioridad de avisos).
- El BFF de unlock responde `502 { message: 'Unlock failed' }` también ante un fallo de red hacia la api.
- `DocsBrowser` calcula `?q=` con debounce de 300 ms; con `q` < 2 caracteres se sigue mostrando la carpeta.
- Observación del QA sobre ADR-010: `480px` (ancho del diálogo, igual que `ConfirmDialog`) y bordes de
  `1px` siguen la convención ya presente en el DS; no hay token de ancho de diálogo.
