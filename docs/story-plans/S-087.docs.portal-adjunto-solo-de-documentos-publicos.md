### Lo implementado: el código que hay que documentar

#### api — `opus-docs-documents-id-attachments-id-get.ts` (commit `501593e`)

```ts
async function downloadPortalAttachment(req: Request, res: Response) {
  const documentId = String(req.params.documentId);
  const id = String(req.params.id);
  // Los dos ids se validan antes del bus; el del adjunto entra al subject de NATS (ADR-002).
  if (!isUlid(documentId)) return respondDocsNotFound(res, 'document_not_found');
  if (!isUlid(id)) return respondDocsNotFound(res, 'attachment_not_found');

  try {
    const document = await moduleQuery(res, 'docs', 'documents.get', { id: documentId, include: ['attachments'] });
    if (!document) return;

    // DD-3 de REQ-016 aplicado al adjunto (cierra F-13): para todo rol, y sin revelar que existe.
    if (document.visibility !== 'public') return respondDocsNotFound(res, 'document_not_found');

    const belongs = Array.isArray(document.attachments) && document.attachments.some((a: any) => a?.id === id);
    if (!belongs) return respondDocsNotFound(res, 'attachment_not_found');

    const ticket = await moduleCommand<ModuleDownloadTicket>(res, 'docs', `attachments.${id}.request-download`, {});
    if (!ticket) return;
    return redirectToModuleDownload(res, ticket);
  } catch (error: any) {
    logger.error(`GET /api/opus/docs/documents/:documentId/attachments/:id downloadPortalAttachment error: ${error.message}`);
    return res.status(500).json({ code: 'internal_error', message: 'Internal error' });
  }
}
```

JSDoc vigente (texto a reflejar en DD-4): *"EXCEPCIÓN ANOTADA a ADR-006 (DD-4): no hay
`validateProjectPermissions` porque el proyecto no se conoce antes de pedir el documento. El
equivalente es la regla de externos de jiku-docs (`public` + proyecto en sus `project-permissions` +
carpeta sin `externalBlocked`) más el recorte de visibilidad de acá. Un documento que no es `public`

### Flow Context

El único flujo afectado es `documentos-desde-la-web` (ver arriba). Escenario de la story, verbatim:

1. **[opus-web — visor]** `createDocsUrlTransform(doc.id)` reescribe el enlace → `/api/docs/documents/{docId}/attachments/{attId}`.
2. **[opus-web — route handler]** valida sesión y los dos ULID → `GET {API_URL}/api/opus/docs/documents/{docId}/attachments/{attId}` con `Authorization: Bearer <token>` y `redirect: 'manual'`.
3. **[api]** `requireModule('docs')` → `hasAnyRole` → `documents.get { id: docId, include: ['attachments'] }` → `visibility !== 'public'` → 404 `document_not_found`; `attId` ausente en `attachments[].id` → 404 `attachment_not_found`; OK → `request-download` → 302 `Location`.
4. **[opus-web — route handler]** propaga el 302; el navegador baja del storage.

**Manejo de errores:** módulo no instalado → 404 `module_not_installed`; no disponible → 503;
timeout → 504; `external-user` sin acceso en jiku-docs → `document_not_found` / `permission_denied`
traducido por el mapa (sin cambio).

#### ADR-006: Dos frontends, una api

- La regla que DD-4 exceptúa: *"Un endpoint accesible a `external-user` **DEBE** además verificar
