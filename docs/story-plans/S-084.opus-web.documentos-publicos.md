## Story Reference

- **Story:** [S-084](../stories/S-084.opus-web-documentos-publicos.md)
- **Service:** `opus-web`
- **Summary:** Abre el módulo `features/docs/` del portal de clientes: consulta el estado del módulo
  opcional de documentación (`GET /api/opus/modules`), agrega la sección colapsable
  **"Documentación (n)"** arriba de los requisitos en `tablero-requisitos` (lista, kanban y
  acordeones mobile) y debajo del pie de autoría en `detalle-requisito` (página y overlay O-01), y
  publica la página `/projects/[projectId]/docs/[documentId]` con un visor de **solo lectura** cuyos
  adjuntos se resuelven por un route handler propio `/api/docs/attachments/[id]` que propaga el 302
  de la api sin seguirlo (H-4). Sin módulo instalado no aparece nada.

**Fuera de esta story (no implementar acá):** edición, búsqueda global y compartir en opus-web
(REQ-016 §Fuera de Alcance). Escribir el flujo `documentos-desde-la-web.md`, ADR-015 y la
arquitectura de opus-web → **S-085**. Ningún cambio en `api` (las rutas `/opus/*` ya existen, S-078).

> **Dependencias:** S-078 (rutas `/api/opus/docs/*` y `GET /api/opus/modules`) está **Completed**.
> El código de esas rutas está en `api/lib/routes/opus-docs-*.ts` y `opus-modules-get.ts`.

### Service Architecture

`opus-web` es `type: frontend`, `language: nextjs`. Todas sus convenciones son **custom**
(`docs/architectures/opus-web/conventions/`): `data-fetching`, `mutations`, `api-routes`, `auth`,
`state-management`, `styling`, `error-handling`, `testing-unit`, `ci-github`, `dockerfile`.

**La regla central:** el access token se queda en el servidor. El navegador pide a su propio origen
(`/api/opus/*`) y un route handler catch-all reenvía agregando el `Bearer`.

```
navegador ──/api/opus/*──> opus-web (route handler) ──Bearer──> api ──NATS──> jiku-docs
   └── cookie de sesión NextAuth (JWT firmado)
```

**Estructura relevante:**

```
opus-web/
├── __mocks__/react-markdown.tsx       parser de markdown a mano (jsdom) — SE EXTIENDE (Task 2)
├── __tests__/app/api/...              tests de route handlers (única excepción a "tests junto al código")
└── src/
    ├── app/
    │   ├── (dashboard)/               shell con Sidebar + <main>
    │   │   └── projects/[projectId]/
    │   │       ├── requirements/page.tsx                    tablero — SE MODIFICA (Task 4)
    │   │       ├── requirements/[requirementId]/page.tsx    detalle página (compone RequirementInfoPanel)
    │   │       └── docs/[documentId]/page.tsx               NUEVO (Task 5)
    │   └── api/
    │       ├── opus/[...path]/route.ts                      catch-all (NO se toca)
    │       ├── files/[id]/preview/route.ts                  patrón 302 a copiar
    │       └── docs/attachments/[id]/route.ts               NUEVO (Task 3)
    ├── features/
    │   ├── requirements/components/RequirementDetailModal/components/RequirementInfoPanel/
    │   │                                                    SE MODIFICA (Task 4): página Y overlay O-01
    │   ├── projects/hooks/useProjects.ts                    nombre del proyecto para el breadcrumb
    │   └── docs/                                            NUEVO módulo (Tasks 1, 2, 4, 5)
    ├── shared/components/ui/           Button, Spinner, MarkdownRenderer, ...
    ├── lib/axios.ts                    apiClient + ApiError + interceptor (401 → /login)
    └── middleware.ts                   matcher '/((?!api|_next/static|_next/image|favicon.ico).*)'
```

**Módulos de dominio:** cada uno en `src/features/{modulo}/` con `components/`, `hooks/`,
`services/`, `types/` (y `utils/` / `constants/` cuando hace falta). El barrel `index.ts` es la
superficie pública.

**Guard:** `middleware.ts` protege por exclusión. **`/projects/[projectId]/docs/[documentId]` queda
protegida sola** (no hay que registrarla). **Todo `/api/*` está fuera del matcher**, así que
`/api/docs/attachments/[id]` **debe validar la sesión por sí mismo**.

**El rol no corta navegación.** Un `user`/`admin` que entre al portal ve lo mismo que el cliente:
la api recorta a `visibility: public` por superficie (DD-3). El front no filtra nada por rol en esta
story.

**Datos en dos capas:** componente cliente (`'use client'`) → hook (`useQuery`/`useInfiniteQuery`)
→ servicio (`features/{m}/services/{m}Api.ts`, objeto con métodos, devuelve `data`) →
`apiClient.get('/api/opus/...')` → catch-all → api.

**Manejo de errores:** el interceptor de axios normaliza todo fallo a
`ApiError { code: string; message: string; status: number }` (`src/lib/axios.ts:5-9`); un fallo sin
respuesta es `{ code: 'unknown_error', message: 'Error desconocido', status: 500 }`; un 401 redirige
con `window.location.href = '/login'` y nunca llega al componente. Un `catch` recibe `ApiError`, se
tipa con `error as ApiError`. Estados por pantalla en orden **loading → error → empty → contenido**,
con `if` temprano. Sin `error.tsx` ni `not-found.tsx` en el servicio.

**Logging:** solo `console.warn`/`console.error`. **Nunca loguear el token, contenido de documentos
ni URLs prefirmadas** (REQ-016 §Seguridad; la api tampoco loguea la `downloadUrl`).

**Testing:** tests **junto al código** (`Componente.test.tsx`), salvo route handlers en
`__tests__/app/api/...`. Se mockea el **hook** (al testear componentes) o el **servicio** (al testear
hooks); `QueryClient` nuevo por test; consultas por rol y texto; `useIsMobile` mockeado por rama.
`react-markdown` ya está aliaseado al mock global: **no** mockearlo en un test; si falta sintaxis,
se agrega al mock.

### Relevant ADRs

- **ADR-009: Token confinado al servidor**
  - Decision: el access token de Zitadel vive solo en el servidor de Next; el navegador nunca lo ve.
  - Implementation Rules:
    - El access token **NO DEBE** llegar al navegador por ningún camino: ni en el bundle, ni en una
      respuesta, ni en una cookie legible por JS.
    - La URL de la api **DEBE** leerse de `API_URL` **en el servidor, en runtime**. **NO SE DEBE**
      usar `NEXT_PUBLIC_API_URL` ni ninguna variable horneada en build.
    - En `web`, toda llamada de dominio **DEBE** ir por un Server Action (`'use server'`) con
      `apiClient`. Un route handler en `app/api/` **DEBE** justificarse por una capacidad que el Server
      Action no tenga (streaming, headers de respuesta, llamada desde componente cliente).
    - En `opus-web`, toda llamada **DEBE** ir por el proxy `/api/opus/[...path]`. **NO SE DEBE**
      agregar un cliente axios que apunte directo a `API_URL` desde el navegador.
    - Todo route handler que reenvíe a la api **DEBE** exigir sesión y responder
      `401 {"error":"Unauthorized"}` si no hay `accessToken`. La única excepción vigente es
      `GET /attachments/[id]/[fileName]` de `opus-web`, cuya autorización la decide la api.
    - Al reenviar respuestas binarias, **DEBEN** propagarse `Content-Type`, `Content-Disposition` y
      `Content-Length`.
    - Al reenviar uploads **DEBE** usarse streaming con `duplex: 'half'`, no bufferizar el archivo
      entero en memoria.
    - Un 401 de la api **DEBE** redirigir el navegador a `/login`.
    - **NO SE DEBE** agregar `NEXT_PUBLIC_*` funcional: rompería la premisa de una imagen por todos los
      entornos.
  - **Notas para esta story:**
    - El handler de adjuntos **no reenvía binario**: propaga el 302 (como
      `api/files/[id]/preview`), así que la regla de cabeceras binarias no aplica.
    - **Discrepancia preexistente (no se resuelve acá):** ADR-009 fija el cuerpo del 401 como
      `{"error":"Unauthorized"}`, mientras la convención `api-routes` manda que **un handler nuevo use
      `{code, message}`** y el handler más reciente del servicio (`api/files/[id]/preview`) responde
      `{ code: 'unauthorized', message: 'Unauthorized' }`. Este plan sigue **la convención y el
      precedente** (el status 401, que es lo que el ADR protege, se cumple igual). Queda anotado para
      que S-085 (arquitectura) lo reconcilie.

- **ADR-011: TanStack Query**
  - Implementation Rules:
    - Todo dato que venga de la api **DEBE** manejarse con TanStack Query. **NO SE DEBE** copiar una
      respuesta a `useState` ni a un store global.
    - Las query keys **DEBEN** seguir el patrón por dominio: `['<dominio>', <identificador o filtros>]`.
    - Tras una mutación exitosa **DEBE** invalidarse la key afectada. Al invalidar por prefijo, hay que
      verificar que el prefijo cubra lo que se pretende.
    - Las mutations **DEBEN** mantener `retry: 0`. Reintentar una escritura sin idempotencia
      garantizada duplicaría datos ([ADR-002](ADR-002-comandos-nats-sin-jetstream.md)).
    - El update optimista **DEBE** usarse solo donde el rollback sea trivial y la latencia se note. **NO
      SE DEBE** aplicar por default.
    - El estado propio de la interfaz **DEBE** usar `useState` local. Un Context nuevo **DEBE**
      justificarse por tener consumidores reales.
    - En listados paginados por categoría, **DEBE** evaluarse el costo de montar N queries en paralelo:
      el tablero del portal monta 7 y su `isLoading` es un `some`, así que la pantalla espera a la más
      lenta.
  - **Nota para esta story:** la sección de documentos es una **octava query independiente** que
    **no** entra en el `queries.some((q) => q.isLoading)` del tablero (UX: "carga aparte, sin
    demorar el tablero").

- **ADR-010: Sass + CSS Modules sin librería**
  - Implementation Rules:
    - Los estilos de un componente **DEBEN** vivir en su `*.module.scss` adyacente. **NO SE DEBE**
      usar CSS global salvo en `globals.scss` y en la capa de tokens.
    - Los valores de color, espaciado y tipografía **DEBEN** referenciar custom properties de
      `_variables.scss`. **NO SE DEBEN** hardcodear valores hexadecimales ni píxeles sueltos.
    - Los patrones visuales repetidos (tipografía, botones, inputs, tags, focus rings) **DEBEN** usar
      los mixins de `_mixins.scss`.
    - Los breakpoints **DEBEN** declararse con los mixins de `_mixins.scss`. **NO SE DEBEN** escribir
      `@media` crudas con valores literales — hoy hay 14 en `web` con 8 valores distintos, y es deuda
      reconocida (NFR-U03).
    - **NO SE DEBE** agregar una librería de componentes ni un framework CSS utilitario sin un ADR que
      lo reemplace.
    - En `opus-web`, las variantes de componente **DEBEN** expresarse con atributos `data-*`, no con
      nombres de clase compuestos.
    - Un valor de token **DEBE** declararse en un solo lugar.

- **ADR-015 "Módulos opcionales del bus"** (DD-17 de REQ-016) todavía no existe: lo escribe S-085.
  Las decisiones que aplican se copian abajo desde REQ-016.

### API Context

Todas las llamadas salen del navegador con `apiClient` contra el **mismo origen**; el catch-all
`/api/opus/[...path]` reenvía a `${API_URL}api/opus/{path}{search}` con `Authorization: Bearer
{session.accessToken}`, reenvía `Content-Type`, devuelve 204/304 sin cuerpo y el resto con su status
y cuerpo JSON. **Los cuatro endpoints ya existen (S-078); ninguno requiere código en el catch-all.**

**`GET /api/opus/modules`** — `x-roles: [admin, user, external-user]`, `x-jiku-module: docs`

> Estado de los módulos opcionales (hoy solo `docs`). `incompatible` (protocolo no soportado o
> registro inválido) se informa como `not_installed`; `features` se omite con `not_installed`.
> `features.sharing` es `true` solo si `JIKU_PUBLIC_URL` está definida y no vacía. El estado vive en
> memoria por réplica: dos réplicas pueden discrepar hasta 30 s. No pertenece a ningún proyecto, así
> que no verifica permiso de proyecto. Existe porque el catch-all de `opus-web` solo reenvía
> `/api/opus/*`: es el mismo cuerpo que `GET /api/modules`.

```yaml
ModulesResponse:
  type: array
  items:
    type: object
    required: [module, status]
    properties:
      module: { type: string }
      status: { type: string, enum: [not_installed, unavailable, available] }
      features:
        type: object
        description: Se omite con `not_installed`
        properties:
          sharing: { type: boolean }
```

Ejemplos verbatim: `[{ module: docs, status: not_installed }]` ·
`[{ module: docs, status: unavailable, features: { sharing: false } }]` ·
`[{ module: docs, status: available, features: { sharing: true } }]`. Respuestas: 200, 401, 403, 500.
**Esta story no usa `features.sharing`** (compartir está fuera de alcance en el portal).

**`GET /api/opus/docs/documents`** — `x-roles: [external-user, admin, user]`, `x-jiku-module: docs`

> Superficie de solo lectura del portal. Llama a `documents.list` con `filter: { projectId |
> requirementId, visibility: 'public' }`: **`visibility: public` lo fuerza la api** y la query no lo
> acepta (400). Exige **exactamente uno** de `projectId` o `requirementId`. Orden `-updatedAt`, sin
> `include`. Orden de las verificaciones: rol, forma, carga del proyecto o requisito (404
> `project_not_found` / `requirement_not_found`), permiso de proyecto para `external-user` (403
> `access_denied`) y, si filtra por requisito, que sea público (404 `requirement_not_found`).
> jiku-docs aplica además su regla de externos (`public`, proyecto permitido, carpeta sin
> `externalBlocked`).

| Query param | Tipo |
|---|---|
| `projectId` | integer ≥ 1 — excluyente con `requirementId` |
| `requirementId` | integer ≥ 1 — excluyente con `projectId` |
| `limit` | integer 1-200, default 50 — **esta story manda `5`** (UX: "hasta 5 filas y el resto con boton-ver-mas-documentos") |
| `cursor` | string ≤ 500 — `page.cursor` de la respuesta anterior; **su ausencia es el fin** |

Joi del handler (verbatim, `api/lib/routes/opus-docs-documents-get.ts`): `joi.object({ projectId,
requirementId, limit: min(1).max(PAGE_LIMIT_MAX).default(50), cursor: string().max(500).optional()
}).xor('projectId', 'requirementId')`. **Un parámetro no declarado o vacío es 400 `invalid_fields`:
no mandar `cursor: undefined` ni `visibility`.**

Respuesta `200 DocsDocumentPage = { items: DocsDocument[], page: DocsPageInfo }`. Errores: 400
`ModuleBadRequest`, 401, 403 `ModuleForbidden` (`access_denied`), **404 `ModuleNotFound`**
(`module_not_installed` | `project_not_found` | `requirement_not_found`), 500, **503
`ModuleUnavailable`** (`module_unavailable` | `upstream_unavailable` | `attachments_not_configured`),
504 `ModuleGatewayTimeout` (`gateway_timeout` | `query_timeout`).

**`GET /api/opus/docs/documents/{id}`** — `x-roles: [external-user, admin, user]`

> Llama a `documents.get` con `include: ['content', 'attachments']`. Si `visibility` no es `public`
> (o falta), responde 404 `document_not_found`, idéntico al de un id inexistente (DD-3). **No compone
> `folder`**: los externos no ven carpetas. Excepción anotada a ADR-006 (DD-4). `id` con patrón
> `^[0-9A-HJKMNP-TV-Z]{26}$`; un id mal formado responde **404 `document_not_found`** sin llamar al
> bus.

Respuesta `200 DocsDocument` (con `content` **o** `contentUrl`, y `attachments`). Errores: 401, 403,

```ts
const API_URL = () => process.env.API_URL ?? '';

async function forward(method: 'GET' | 'HEAD', id: string) {
  const session = await auth();
  if (!session?.accessToken) {
    return NextResponse.json({ code: 'unauthorized', message: 'Unauthorized' }, { status: 401 });
  }
  const base = API_URL();
  if (!base) {
    return NextResponse.json(
      { code: 'server_misconfigured', message: 'API_URL is not set' },
      { status: 500 }
    );
  }
  const target = new URL(`api/files/${id}/preview`, base.endsWith('/') ? base : `${base}/`);
  // `redirect: 'manual'` no es opcional: el fetch de Node sigue las redirecciones por
  // defecto, y sin esto el handler descargaría el objeto desde S3 y lo devolvería como 200.
  const response = await fetch(target, {
    method,
    headers: { Authorization: `Bearer ${session.accessToken}` },
    redirect: 'manual',
  });
  if (response.status >= 300 && response.status < 400) {
    const location = response.headers.get('Location') ?? '';
    return new NextResponse(null, { status: response.status, headers: { Location: location } });
  }
  // El body se devuelve tal cual para que el `code` sobreviva.
  const body = await response.json().catch(() => null);
  if (body === null) return new NextResponse(null, { status: response.status });
  return NextResponse.json(body, { status: response.status });
}
```

#### User flow relevante — Flujo 4: Leer la documentación de mi proyecto (verbatim)

- **JTBD:** "Cuando el equipo me dice que algo está documentado, quiero leerlo yo mismo en el portal,
  sin pedir que me lo manden." **Audiencia:** cliente. **Trigger:** el cliente entra al tablero de su
  proyecto, o a un requisito, y ve la sección **"Documentación (n)"**. Existe solo con el módulo
  instalado y con al menos un documento público vinculado [REQ-016 RF-24, CA-34, CA-35].
- **Happy path:** (1) tablero-requisitos → la sección "Documentación (n)", arriba de los requisitos,
  lista los documentos públicos del proyecto; (2) abre uno → documento lo muestra renderizado, con
  sus imágenes y adjuntos; (3) vuelve al tablero con "Volver" o el breadcrumb.
- **Alternativos:** desde un requisito — detalle-requisito (o su modal O-01) muestra los documentos
  públicos vinculados a ese requisito, debajo del pie de autoría. Mobile — la sección queda arriba de
  los acordeones y el visor se lee a ancho completo.
- **Errores y recuperación:** módulo caído — la sección aparece con `"Los documentos no están
  disponibles en este momento. Probá de nuevo en unos minutos."`; el visor ofrece "Reintentar".
  Documento interno o de otro proyecto por URL directa — `"Este documento no existe o no está
  compartido con vos."`: el portal no revela que existe.
- **Estado final:** el cliente leyó el documento sin pedirlo a nadie.
- **Criterios de éxito:** solo documentos públicos de sus proyectos (lo garantiza la api); un
  proyecto sin documentos públicos se ve **igual que antes**, sin sección vacía; enterarse de un
  documento nuevo — **no se cumple** (FG-2).

#### Cross-surface — Flujo 4: De la documentación del equipo a la vista del cliente (resumen verbatim)

`web` (origen) → `opus-web` (destino), sincronización **por consulta** (sin tiempo real): el equipo
escribe un documento cuyo frontmatter lo vincula al proyecto o a un requisito y lo marca `public`;
jiku-docs guarda la versión; **la próxima vez que el cliente entra**, lo ve en la sección y lo lee.
Lo que cruza: documento `public` vinculado (✅ la última versión), adjuntos (✅ por el proxy de
opus-web con la sesión del cliente). Lo que no: documento `internal` (❌ nunca), autor, versiones,
reservas de edición (❌).

**Componente `Button` (spec completa, v1.0.0, relevado desde el código):**

- **Propósito:** disparador de acciones del portal.
- **Anatomía:** label de texto, con estado de carga. Variantes con atributos `data-*`:
  `<button data-variant="primary" data-size="md">`.
- **Variants:** `primary` (acción principal, `--color-primary`) · `secondary` (acción alternativa) ·
  `danger` (destructiva, `--color-error`).
- **Sizes:** `sm` · `md` · `lg`.
- **States:** default ✅ · hover ✅ (`--color-primary-hover` en `primary`) · focus ✅ (focus ring
  `--color-primary`) · `loading` ✅ (prop booleana) · disabled ⚠️ no relevado explícitamente.
- **Spacing & sizing:** radios de `--radius-*`.
- **Accesibilidad:** `<button>` nativo. Contraste no medido.
- **API:** `<Button data-variant="primary" | "secondary" | "danger" data-size="sm" | "md" | "lg" loading={boolean} />`
  (en código: props `variant`, `size`, `loading`, `disabled`, `onClick`, `type`, `className`).
- **Uso en esta story:** `boton-volver` → `secondary`; `boton-ver-mas-documentos` → `secondary`
  `size="sm"` con `loading` mientras `isFetchingNextPage`; `boton-reintentar` → `primary`.

**Componente `Spinner` (spec completa, v1.0.0, relevado desde el código):**

- **Propósito:** indicador de carga. **Anatomía:** indicador visual sin label.
- **Variants:** sin variants; **Sizes:** `sm` · `md` · `lg` con `data-size`. **States:** único.
- **Accesibilidad:** la spec marca "sin verificar", pero el código **sí** renderiza `role="status"`,
  `aria-label="Cargando"` y texto oculto "Cargando...". Por eso `indicador-carga` lleva además el
  texto visible `"Cargando documento..."` (patrón de las demás pantallas).
- **API:** `<Spinner data-size="sm" | "md" | "lg" />` (en código: prop `size`).
- **Uso en esta story:** `cargando-documentos` → `sm`; `indicador-carga` → `lg`.

**Patterns:** ninguno documentado (`patterns/README.md` vacío). **Content (placeholder):** botones
verb-first, sentence case; mensajes de error empáticos y accionables. Los textos de esta story vienen
verbatim de los screen.md.

**Accesibilidad (`guidelines/accessibility.md`, verbatim de lo aplicable):** target **WCAG 2.2 AA**.
Texto body contraste ≥ 4.5:1; componentes interactivos ≥ 3:1; **no comunicar estado solo con color**.
Todo interactivo accesible por teclado, foco visible (contraste ≥ 3:1), orden de tab lógico, Enter /
Space activan controles, sin keyboard traps. Cada componente declara su rol ARIA correcto; íconos
decorativos `aria-hidden="true"`; íconos funcionales `aria-label`; **imágenes con contenido: `alt`
real** (en el markdown, el `alt` del autor); live regions para feedback dinámico. Respetar
`prefers-reduced-motion: reduce` (la rotación del chevron usa `--transition-fast`; anularla bajo
`reduce`). Targets táctiles mínimo 44×44 px (el header colapsable de la sección y las filas).
