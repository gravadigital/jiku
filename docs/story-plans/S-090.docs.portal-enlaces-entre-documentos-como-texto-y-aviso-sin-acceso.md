JSDoc vigente (texto a reflejar): *"Todo enlace `/docs/{ULID}` —relativo o con cualquier host, con
`?`/`#` opcional— también se vacía: apunta a la web interna, que el externo no puede abrir (REQ-019
DD-6), y el visor lo muestra como texto (DD-7). Se reconoce por el path, sin comparar el host."*

Orden de evaluación: **adjunto primero** (`/docs/attachments/{ULID}` sigue reescrito al proxy),
después documento (`/docs/{ULID}` → `''`), después `http(s)`/`mailto` (pasan), resto → `''`. Un path
con segmentos extra (`https://ejemplo.com/docs/{ULID}/historial`) **no** es enlace a documento y pasa
como `https`. El vaciado de documento **no** depende de que `documentId` sea ULID.

#### Override `a` de `DocumentMarkdown` (DD-7)

```tsx
a: ({ href, children }: { href?: string; children?: ReactNode }) =>
  href ? (
    <a href={href} target="_blank" rel="noopener noreferrer">
      {children}
    </a>
  ) : (

  ),
```

JSDoc: *"Un enlace sin destino (enlace a otro documento o URL vaciada por el filtro) se renderiza
como texto, sin `<a>` (REQ-019 DD-7)."* Alcanza a `javascript:`, `data:` y `//host` (antes quedaban
como `<a>` sin `href`).

#### `documentation/known-limitations.md` — §"The documentation module has limits of its own" → **Portal** (líneas ~167-177)

```markdown
**Portal**

- **Markdown is rendered without GFM**: tables, strikethrough and task lists appear as plain
  text.
- **Documents over 256 KiB are fetched by the browser**, which needs a CORS `GET` rule on
  jiku-docs' bucket; if it is missing the document shows an error.
- **A document cannot show another document's attachment in the portal.** Attachments are served
  under the document that links them, and only if they belong to it: a `public` document that
  embeds or links an attachment of a different document — even a `public` one — shows it broken
  (404). Its own attachments work as before. The internal web is not affected.
```

Se **agrega** una viñeta al final del bloque Portal (DP-2): los enlaces entre documentos se ven como
texto plano en el portal.

### Flow Context

El único flujo afectado es `documentos-desde-la-web`, Paso 9 (portal). Escenarios de la story,
verbatim:

**Enlace entre documentos en el visor (CA-1 a CA-3)**

1. **[opus-web / `DocumentMarkdown`]** `urlTransform(url)`: `/docs/attachments/{ULID}` (con o sin
   host) → `/api/docs/documents/{documentId}/attachments/{ULID}` (sin cambios); `/docs/{ULID}` (con o
   sin host, con `?`/`#`) → `''` (nuevo); `http(s)`/`mailto` → pasa; resto → `''`.
2. **[opus-web / override `a`]** `href` vacío → `<>{children}</>` (nuevo); si no,
   `<a href target=_blank rel>`.

**Outcome:** los enlaces a documentos internos se ven como texto.

**Un externo sin acceso abre el tablero (CA-4 a CA-6)**

1. **[opus-web / `DocsSection`]** `GET /api/opus/docs/documents` falla → `ApiError` con `status` y `code`.
2. **[opus-web / `DocsSection`]** clasifica según DD-8 → nada, "sin acceso" o "no disponible".

**Manejo de errores:** `module_not_installed` → nada; 403 o `caller_not_authorized` → "No tenés
acceso a la documentación de este proyecto."; otro error → aviso de "no disponible".
