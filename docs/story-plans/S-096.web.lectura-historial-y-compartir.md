- **Summary:** la lectura de un documento (`/docs/[id]`, pantalla 06) deja de mostrar carpetas y rutas:
  breadcrumb "Documentación / {título}", cabecera con visibilidad (Interno / Visible para el cliente /

### Fuera de alcance (declarado, para no improvisarlo)

- **"Restauración de la versión {m}"**: `DocsVersion` no trae la versión de origen de una restauración
  (no hay campo `fromVersion` en el contrato). Se muestra siempre `"Restauración"` (ver Hallazgos).
- **Diff entre versiones**: descartado por la UX.
- **Encabezados *setext*** (`Título\n===`) en el índice: el índice reconoce encabezados ATX (`#`, `##`);
  un setext se renderiza pero no aparece en "En este documento" (ver Hallazgos).
- **Iconos dentro de `Badge`** (eye/eye-off/lock en la visibilidad, lock en "Protegida"): `Badge` no
  tiene slot de icono; el texto siempre acompaña, así que la regla "nunca solo color" se cumple.
- **Tiempo real** (`access.changed`, `docs-notify`): la web no recibe eventos; un documento que pasa a
  restringido con O-12 abierto se entera por `sharing_blocked` al crear.

### Convenciones activas que aplican (extracto)

**`_base` (Next.js):** TypeScript strict, sin `any` salvo bordes; Server Components por defecto (los
componentes con estado llevan `'use client'`); el token nunca en el cliente; imports absolutos `@/…`;
comentarios solo del **porqué**.

**`data-fetching` (custom):**
- Tres capas: componente cliente → hook `useQuery` → Server Action `'use server'` → `apiClient`.
  "Ninguna capa se saltea desde un componente cliente."
- Server Action con tipo de retorno explícito; devuelve `response.data`, nunca la respuesta de axios.
- **`features/docs/` usa `DocsResult`**: las Server Actions no lanzan, devuelven
  `{ ok: true; data } | { ok: false; error }` (`toResult`) y los hooks re-lanzan con `unwrap`.
- Hooks: un objeto `options` con defaults, `enabled` siempre expuesto, el hook no transforma datos.
- Query keys del módulo: el documento sigue en `['docs-document', id]` (lo invalidan `useSaveDocument`,
  `useAssignProject`, etc.); la versión pedida va como tercer elemento `['docs-document', id, { version }]`
  (invalidar `['docs-document', id]` la alcanza por prefijo). Versiones: `['docs', 'versions', id]`.
- Cache global: `staleTime: 30_000`, `retry: 1` (docs: `shouldRetryDocsQuery`); mutations `retry: 0`.

**`mutations` (custom):** invalidar **en el hook** (acá en `onSettled`: tras un 504 la restauración pudo
aplicarse); el hook no navega ni muestra toasts; `retry: 0`; `isPending` alimenta `loading`/`disabled`.
`module_unavailable` invalida `['modules']` (`withModuleInvalidation`).

**`state-management` (custom):** la versión que se lee va en la URL (`?version=N`), no en `useState`. No
copiar datos de query a estado. Estado local solo para lo efímero (panel abierto, versión a confirmar,
aviso del panel).

**`styling` (custom, ADR-010):** Sass + CSS Modules por componente (`@use '@/styles' as *;`), custom
properties del DS (`var(--space-*)`, `var(--space-grid-gap)`, `var(--z-modal)`, `var(--radius-surface)`,
`var(--elevation-raised)`), sin librería de componentes. Viewport único desktop: grilla de 12 columnas
**sin `@media`** (patrón actual de `DocumentView.module.scss`: `.header, .reading { display: grid;
grid-template-columns: repeat(12, minmax(0, 1fr)); gap: var(--space-grid-gap); }`).

**`error-handling` (custom):** avisos inline con `DocsNotice` (gap `alert` aceptado, `role` configurable),
toasts con `react-toastify`, mensaje por `code` en un util del módulo (`utils/versionErrors.ts`).

**`testing-unit` (custom):** tests junto al archivo, partidos por tema (`DocumentView.version.test.tsx`);
mockear **hooks** al testear componentes y **services** al testear hooks; `vi.mock('@/lib/axios')` al
testear Server Actions; mockear `next/navigation` (`useRouter`, `useSearchParams`) y
`@/hooks/use-current-user`; `getByRole` antes que `data-testid`; `userEvent`; `queryBy*` para ausencia;
TZ fijada en UTC. Comandos: `npm test --workspace web`, `npm run lint --workspace web`,
`npm run build --workspace web`.

- **ADR-009: Token confinado al servidor.** El navegador nunca llama a la api: todo pasa por Server

- **ADR-010: Sass + CSS Modules sin librería.** El drawer del historial es un `<dialog>` nativo con CSS
  Module (mismo armazón que `ShareDocumentDialog`), sin librerías de UI.
- **ADR-011: TanStack Query.** Único cache de datos de servidor; invalidación por query key.
- **ADR-015: Módulos opcionales del bus** (DD-2: la api no autoriza el dominio; DD-7: el `code` de

### API Context

Todas las rutas son de la api (`{API_URL}/api`), las llama una Server Action con el Bearer de la sesión.
Cadena: `requireModule('docs') → hasAnyRole(['admin','user']) → Joi`. Id que no es ULID → `404` sin bus.
Errores comunes: `404 module_not_installed`, `503 module_unavailable`, `504 gateway_timeout`,
`400 invalid_fields`, `403 permission_denied`. Cuerpo de error `{ code, message, details? }` →
interceptor → `ApiError { code, message, status, details? }` → `toResult` → `DocsError`.

### Flow Context

**`documentos-desde-la-web`** (modificado por REQ-021), pasos que toca esta story, verbatim:

- **Paso 2: visor de un documento (web)** — `GET /api/docs/documents/{id}` (query opcional `version`).
  "Hace **una sola consulta** (desde S-094 ya no compone `folders.get`): `documents.get { id, version?,
  include: ['content','relations','topics','lock','attachments'] }`." "La web decide editar y compartir
  por la visibilidad del documento y el rol; los nombres vienen en las `*Refs`. Una `version` compactada
  responde 404 `version_pruned` con `details`. **Un documento con `contentUrl` (más de 256 KiB) se muestra
  en solo lectura**."
- **Paso 2c: historial** — "`GET /api/docs/documents/{id}/versions` trae por versión `authorName`, `kind`
  (`create|update|restore`) y `protected` (verbatim). `POST .../restore` de una versión compactada
  responde 404 `version_pruned`. Abrir una versión compactada (`?version=N`) también."
- **Paso 4** — "el aviso de lock usa `details.holderName`."
- **Errores (tabla del flujo):** `2 | Versión pedida compactada (también en restore) | 404 |
  { "code": "version_pruned", "details": { "requestedVersion", "previousAvailable", "nextAvailable" } } |
  La web ofrece las versiones disponibles más cercanas`; `3, 5 | Reserva en poder de otra sesión | 409 |
  { "code": "document_locked", "details": { "holder", "holderName", "via", "expiresAt" } } | La web
  muestra quién tiene la reserva`.
- **Nota a corregir (Task 8):** el flujo todavía dice "**Fuera de la interfaz** aunque la api los expone:
  historial (`GET .../versions`), mover, restaurar y borrar documentos". REQ-021 (Flujos Afectados) fija
  "el historial y restaurar pasan a estar en la interfaz; mover sigue fuera".

**`lectura-por-link-compartido`** — "un documento `restricted` no admite links (`sharing_blocked`);
pasar un documento a `restricted` revoca los links activos (`revokeReason: restricted`)".

**Escenario web de la story (verbatim):**
1. **[web — `VersionHistoryPanel`]** Output: `GET /api/docs/documents/{id}/versions?limit=50`.
2. **[web]** lista con `authorName`, `kind`, `protected`, `message`; pie con `prunedVersionsCount`.
3. **[web → api]** "Ver" en la versión 7 → `GET /api/docs/documents/{id}?version=7`.
4. **[api]** `404 { code: 'version_pruned', details: { requestedVersion: 7, previousAvailable: 5, nextAvailable: 9 } }`.
5. **[web]** aviso y enlaces a las versiones 5 y 9.
- `version_pruned` en `restore` → mismo aviso. `version_conflict` al restaurar → aviso y recarga.

### Decisiones de este plan sobre la story

1. **Permisos de la interfaz (story, "Permisos en la interfaz"):** `canEdit = !doc.contentUrl`;
   `canShare` se parte en dos: **el botón se renderiza** con `useModule('docs').sharing === true` y
   **se deshabilita** con `doc.visibility === 'restricted'` (o módulo caído). Sin `folder`, sin rol.
2. **Versión en lectura (`?version=N`):** `parseVersionParam` acepta solo enteros ≥ 1 (`/^[1-9]\d*$/`);
   cualquier otro valor se ignora. La vista pide **siempre** el documento vigente (`useDocument({ id })`:
   cabecera, permisos, `baseVersion` de restaurar, "Actual" del historial) y, con `?version=N` válido y
   distinto de la versión vigente, **además** `useDocument({ id, version: N })` (contenido, índice,
   `meta-version` y aviso). `?version` igual a la vigente se trata como lectura normal (sin aviso).
3. **Compactada:** si la consulta versionada falla con `version_pruned`, se muestra la cabecera del
   vigente + `aviso-version-compactada` (`role="alert"`) y se ocultan contenido e índice; nunca se
   confunde con "no existe".
4. **Anclas del índice:** `extractHeadings(markdown)` recorre las líneas del contenido **ya sin
   frontmatter**, reconoce encabezados ATX de nivel 1 y 2 fuera de bloques de código cercados (```/~~~)
   y devuelve `{ level, text, id, line }`; `id` = slug (minúsculas, sin acentos, `[^a-z0-9]+` → `-`,
   sin guiones en los bordes, vacío → `seccion`) con sufijo `-2`, `-3` para repetidos. `MarkdownViewer`
   en modo `document` recibe `headingIds: ReadonlyMap<number, string>` (línea → id) y pone el `id` en el
   `h2`/`h3` desplazado leyendo `node.position.start.line` (react-markdown pasa `node` a los
   componentes). Mismo string para los dos → mismas líneas.
5. **Scroll-spy del índice:** `IntersectionObserver` sobre los encabezados con id; el enlace activo
   lleva `aria-current="location"`. Sin `IntersectionObserver` (jsdom) el índice funciona sin marca.
6. **Restaurar:** `baseVersion` = versión del documento **vigente**; éxito → toast
   `"Restauraste la versión {n} como versión {nueva}."` (en el panel, que es el componente), cierra el
   panel y, si se estaba viendo `?version`, `router.replace('/docs/{id}')`. Errores → `aviso-error-historial`
   en el panel (`describeRestoreError`); `version_conflict` además refresca lista y documento (lo hace
   el `onSettled` del hook).
7. **Restaurar bloqueado:** con un lock vigente de otra sesión (`isLockActive(doc.lock, now, null)`),
   todos los "Restaurar" quedan `disabled` con la ayuda `"{nombre} lo está editando."`
   (`nombre` = `holderName` o `"Otra persona"`; agente → `"Un agente lo está editando."`).
8. **Nombres (CA-3):** `meta-version` y el historial usan `editorLabel` (ya existe: `"vos"` si es la
   persona actual, nombre, o `"—"`); en `meta-version` el `"por —"` **se omite**. Lock: `lockedMessage`
   nuevo con `holderName` (`"Otra persona"` solo para lock ajeno sin nombre; propio →
   `"Lo estás editando en otra pestaña o ventana."`). Conflicto del editor: `updatedByName` o `"Otra persona"`.
9. **Título:** `titleOf(doc)` = `doc.title.trim()` o `"Sin título"` (la UX: "ya no se cae al nombre de
   archivo"). `displayTitle` se conserva para `DocsPanel` (S-098).
10. **Adjuntos con cantidad:** título de la card `"Adjuntos ({n})"` con `n ≥ 1`; sin adjuntos,
    `"Adjuntos"` y `"Sin adjuntos."` (la UX pide "título con la cantidad" sin fijar el formato).
11. **Cliente en "Vinculado a" sin enlace:** la UX enlaza proyecto, requisito y tarea a su ficha; el
    cliente va como texto (hoy enlazaba a `/clients/edit/{id}`, que es edición, no ficha).

### Design System Context — `web`

- **Versión fijada:** `4.3.0` (`docs/design-system/web/README.md`).
- **Accent de la superficie:** verde agua `#61CCB9` (`color.brand.primary`) — acento, foco e ítem activo
  (el enlace activo del índice puede usarlo como marca lateral), nunca fondo. Texto/enlace verde sobre
  claro: `color.brand.primary-deep` `#12897A`.
- **Grid:** `desktop` 1440 px, único, 12 columnas; `display: grid` de 12 columnas con
  `gap: var(--space-grid-gap)`, sin `@media`.
- **Elevación:** `elevation.card` en cards; lo que flota (drawer) usa la sombra del armazón de dialogs
  existente (`var(--elevation-raised)`) y `z-index: var(--z-modal)`.
- **Mono:** el DS no tiene token de familia monoespaciada (gap previo): versión y fechas usan el mismo
  stack que ya usan los SCSS de `features/docs` (`--fontStack-monospace, ui-monospace, …, monospace`).

**Componentes usados (extractos normativos verbatim):**
- **ViewHeader** (`detail`, con `parent`) — "El título **DEBE** ser el `<h1>` de la vista." "El breadcrumb
  **DEBE** ser un `<nav aria-label="Ruta">` con una lista, y el nivel actual **DEBE** llevar
  `aria-current="page"`." "**NO SE DEBEN** poner dos botones primarios en la cabecera." "**NO SE DEBE**
  ponerle `border-bottom`." API real: `variant`, `title`, `parent: { label, href }`, `badges`, `action`.
  Con `parent={{ label: 'Documentación', href: '/docs' }}` produce exactamente `"Documentación / {título}"`.
- **Button** — `primary` (Editar), `secondary-nav` (Historial, Compartir, Ver), `secondary-dismiss`
  (Restaurar, Ver versiones anteriores, Cerrar). "Foco: anillo `focus.ring` visible." "**NO SE DEBEN**
  apilar dos botones primarios en una misma vista." "**NO SE DEBE** usar el botón para navegar entre
  pantallas" (la API trae `href` como extensión local para "Volver"; "Ver" navega con `router.push` desde
  `onClick` porque además cierra el panel). API: `variant`, `disabled`, `loading` (spinner + `aria-busy`),
  `icon`, `onClick`, `href`, `ariaDescribedBy`. **Sin `aria-label` fuera del FAB** (ver DS Gaps).
- **ConfirmDialog** (O-02) — "**DEBE** llevar `role="dialog"` con `aria-modal="true"` y `aria-labelledby`."
  "El foco DEBE atraparse dentro del diálogo… y volver al elemento que lo abrió." "`Esc` DEBE cerrar el
  diálogo cancelando la acción." "El cuerpo **DEBE** nombrar qué se afecta." "El fondo DEBE quedar inerte."
  "**NO SE DEBE** usar rojo en el botón de confirmar." API: `open`, `title`, `body`, `confirmLabel`,
  `cancelLabel`, `onConfirm`, `onCancel`, `pending`.
- **Badge** (`outline`, familia `neutral`; `state` en la tabla de links) — "**NO SE DEBE** comunicar el
  estado sólo con color." "**NO SE DEBE** usar un badge como botón: si dispara una acción, es un Button"
  (los pills de tema enlazan: el `<a>` envuelve al badge; ver DS Gaps).
- **Card** (`panel`, `headingLevel="h2"`) — "**NO SE DEBEN** anidar tarjetas" (las cuatro cards de la
  columna derecha son hermanas dentro del `<aside>`).
- **Loader** (`block` / `inline`) — `role="status"`. **EmptyState** (`list`) — vacío de links.
- **Table** (`light`) — tabla de links (sin cambios de estructura).

**Accesibilidad (guideline `web`, extracto aplicable):** WCAG 2.2 AA. "NO comunicar estado solo con
color." "Todo elemento interactivo es accesible vía teclado. Foco visible. ESC cierra modales /
popovers. Enter / Space activan controles. Sin keyboard traps." "Cada componente declara su rol ARIA
correcto. Iconos puramente decorativos: `aria-hidden="true"`. Live regions para feedback dinámico
(`aria-live="polite"`)."

**DS Gaps — `web`:**
- *Aceptados* (REQ-021 → "Dejar anotado"):
  - `lista-indice`, `lista-vinculos`, `lista-propiedades`, `lista-versiones` (`list`) — `web` no tiene
    componente de lista (gap previo). Se implementan como `<ol>`/`<ul>`/`<dl>` semánticos con CSS Module.
  - `boton-historial` (`button` solo icono), `boton-cerrar-historial` — `Button` no tiene variant de solo
    icono fuera del FAB. Se usa `Button` `secondary-nav` / `secondary-dismiss` con `icon` y, como
    `children`, un `<span>` visualmente oculto con el nombre accesible (`"Historial de versiones"`,
    `"Cerrar historial"`); el CSS Module de la feature lo hace cuadrado.
  - `aviso-version-anterior`, `aviso-version-compactada`, `aviso-bloqueado`, `aviso-error-historial`,
    `aviso-bloqueado` de O-12 (`alert`) — gap previo: `DocsNotice` de la feature.
  - `toast-resultado` de restaurar (`toast`) — gap previo: `react-toastify` sin spec.
  - `panel-historial` (`modal` drawer) — gap previo: `<dialog>` nativo con el armazón de foco de
    `ConfirmDialog`/`ShareDocumentDialog`, anclado a la derecha (480 px, alto completo).
  - `breadcrumbs` → **cubierto** por `ViewHeader` con `parent`.
- *Nuevos* (aparecieron al planificar; **no bloquean**, se resuelven inline y quedan reportados):
  - **`Badge` sin slot de icono**: los iconos de visibilidad (eye/eye-off/lock) y de "Protegida" (lock)
    no se dibujan dentro del badge; el texto lleva el significado.
  - **`Badge` enlazado** (pills de `temas-documento` que navegan): se envuelve el `Badge` en un `<a>` (el
    destino es el enlace, el badge es su contenido visual). Si el DS quiere un "chip enlace", es una
    variante nueva vía `/product-design-system-update`.
