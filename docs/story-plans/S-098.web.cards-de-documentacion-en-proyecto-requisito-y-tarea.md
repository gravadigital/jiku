### Fuera de alcance (declarado, para no improvisarlo)

- **Marca "En edición" en la card**: se quita a propósito (decisión UX de REQ-021: "sigue en Documentación
  y en el documento"). No se reemplaza por nada.
- **Paginado dentro de la card**: no hay "Ver más" ni "Anterior/Siguiente"; el resto vive en "Ver todos".
- **Requisitos y tareas por campos en el alta**: llegan precargados vía `initial.requirement`/`initial.task`
  y se muestran como "También se vincula a: …" (comportamiento de S-097).
- **Arreglar el loader infinito / error no manejado de las fichas** (registrado en los screen.md como
  as-is): fuera de esta story.

### Convenciones activas que aplican (extracto)

**`_base` (Next.js):** TypeScript strict, sin `any` salvo bordes; componentes con estado llevan
`'use client'`; el token nunca en el cliente; imports absolutos `@/…`; comentarios solo del **porqué**.
Un Server Component (la página de tarea) puede pasar props serializables a un Client Component (`DocsPanel`).

**`data-fetching` (custom):**
- Tres capas: componente cliente → hook `useQuery` → Server Action `'use server'` → `apiClient`.
  "Ninguna capa se saltea desde un componente cliente."
- **`features/docs/` usa `DocsResult`**: las Server Actions no lanzan; los hooks re-lanzan con `unwrap`.
- Hooks: un objeto `options` con defaults, `enabled` siempre expuesto, el hook no transforma datos.
- Toda consulta de docs va envuelta en `withModuleInvalidation` y usa `retry: shouldRetryDocsQuery`.
- Query keys del módulo con prefijo `['docs', …]`: listados `['docs', 'documents', …]` (la card pasa a
  `['docs', 'documents', 'card', filters]`).

**`mutations` (custom):** invalidar **en el hook** (`onSuccess`); el hook no navega ni muestra toasts.

**`state-management` (custom):** el `open` del diálogo es estado de interfaz (`useState`) del panel; los
datos de la card son de TanStack Query; no se copian a estado.

**`styling` (custom, ADR-010):** Sass + CSS Modules por componente (`@use '@/styles' as *;`), custom
properties del DS (`var(--space-*)`, `var(--text-secondary)`, `var(--text-link)`), sin librería. Viewport
único desktop, sin `@media` nuevos.

**`error-handling` (custom):** avisos inline con `DocsNotice` (`intent="warning"`, rol `alert`), texto
`DOCS_UNAVAILABLE_MESSAGE` de `utils/docsErrors.ts`.

**`testing-unit` (custom):** tests junto al archivo, partidos por tema (`DocsPanel.actions.test.tsx`);
mockear **hooks** al testear componentes y **services** al testear hooks; mockear `next/navigation`;
`getByRole` antes que `data-testid`; `userEvent`; `queryBy*` para ausencia; TZ fijada en UTC.
Comandos: `npm test --workspace web`, `npm run lint --workspace web`, `npm run build --workspace web`.

### Relevant ADRs

- **ADR-009: Token confinado al servidor.** La card consulta vía la Server Action existente `listDocuments`
  (`'use server'`, `apiClient`); ningún hook ni componente nuevo importa `apiClient`.
- **ADR-010: Sass + CSS Modules sin librería.** `DocumentRowCompact` es un componente de la feature con su
  CSS Module; la lista es `<ul>`/`<li>` (el DS de `web` no tiene `List`: gap aceptado).
- **ADR-011: TanStack Query.** Único cache; invalidación por prefijo de query key.
- **ADR-015: Módulos opcionales del bus.** La card existe solo si `useModule('docs')` no es
  `not_installed`; con `unavailable` muestra el aviso. La api no autoriza el dominio: la card lista lo que
  jiku-docs deja ver.

### API Context

Todas las rutas son de la api (`{API_URL}/api`), las llama una Server Action con el Bearer de la sesión.
Cadena: `requireModule('docs') → hasAnyRole(['admin','user']) → Joi`. Errores comunes: `404
module_not_installed`, `503 module_unavailable`, `504 gateway_timeout`, `400 invalid_fields`, `403
permission_denied`. Cuerpo de error `{ code, message, details? }` → `ApiError` → `toResult` → `DocsError`.

**`GET /docs/documents`** (`docs/apis/api.yaml:2127`, sin cambios) — "Llama a `documents.list` de
jiku-docs. Responde el `data` de jiku-docs sin transformar." "**Requiere jiku-docs >= 1.3.0** … `count=true`
manda `count: true` y la respuesta trae `page.total`." "Cada ítem gana `clientRefs` y `projectRefs` … Los
campos de jiku-docs (`clients`, `projects`, `projectMatch`, `topics`, `lock`, ...) pasan intactos."
Parámetros que usa la card (verbatim):
- `projectId` — "Proyecto; repetido = lista (O), hasta 20. Excluyente con `myActiveProjects`" (`array` de
  `integer ≥ 1`, `style: form, explode: true`).
- `requirementId` — "Filtro por requisito" (`integer ≥ 1`).
- `taskId` — "Filtro por tarea" (`integer ≥ 1`).
- `count` — "`true` = devuelve `page.total`" (`boolean`).
- `sort` — enum `[updatedAt, -updatedAt, createdAt, -createdAt, title, -title, path, -path]`, default `-updatedAt`.
- `limit` — "Tamaño de página" (`1..200`, default 50).

Response `200 DocsDocumentPage { items: DocsDocument[]; page: DocsPageInfo }`:
- `DocsPageInfo { limit: integer; returned: integer; cursor?: string /* su ausencia es la única señal de fin */;
  total?: integer /* Solo con count */ }`.
- `DocsDocument` (campos que usa la card): `id: string (ULID)`, `title: string`, `updatedAt: string (ISO)`,
  `topics?: string[]`, `projectMatch?: 'direct' | 'indirect'` — "Solo con `projectId` en el filtro"
  (`api.yaml:4059`).

Request exacto de cada card (con `definedOnly` + `paramsSerializer: { indexes: null }`):
- Proyecto 12: `GET /api/docs/documents?projectId=12&count=true&sort=-updatedAt&limit=5`
- Requisito 45: `GET /api/docs/documents?requirementId=45&count=true&sort=-updatedAt&limit=5`
- Tarea 7: `GET /api/docs/documents?taskId=7&count=true&sort=-updatedAt&limit=5`

### Decisiones de este plan sobre la story

1. **Prop nueva `context` en `DocsPanel`** (la story solo fija `scope`): `context?: { clientId?: number;
   projectId?: number; title?: string | null }` lleva lo que el "+" necesita y la card no puede deducir del
   `scope`. Montajes:
   - Proyecto: `scope={{ projectId: Number(id) }}` + `context={{ clientId: project.client?.id }}`.
   - Requisito: `scope={{ requirementId: requirement.id }}` + `context={{ projectId: requirement.projectId,
     title: requirement.title }}`.
   - Tarea: `scope={{ taskId: Number(id) }}` + `context={{ projectId: objective.projectId, title:
     objective.title }}`.
   El cliente de requisito y tarea **no** se pasa: `NewDocumentDialog` lo completa desde el proyecto
   (`clientPending`, S-097 TS-27). Así no dependemos de que `GET /requirements/{id}` u `/objectives/{id}`
   traigan el cliente.
2. **`cardInitial(scope, context)`** (`utils/docsCard.ts`), sin claves `undefined`:
   - `{ projectId }` → `{ projectId, clientId? }`.
   - `{ requirementId }` → `{ projectId?, clientId?, requirement: { id: requirementId, title: context?.title ?? null } }`.
   - `{ taskId }` → `{ projectId?, clientId?, task: { id: taskId, title: context?.title ?? null } }`.
   Se memoiza en el panel (`useMemo`) para no cambiar la referencia del `initial` del diálogo en cada render.
3. **Una consulta, sin paginar:** `useDocsCard({ filters, enabled })` → `useQuery` con key `['docs',
   'documents', 'card', filters]` y `listDocuments(filters)`. `cardFilters(scope)`:
   `{ projectId: [id] }` · `{ requirementId: id }` · `{ taskId: id }` + `{ count: true, sort: '-updatedAt',
   limit: 5 }` (`CARD_LIMIT = 5`). El prefijo `['docs', 'documents']` hace que las invalidaciones que ya
   existen (alta, guardado, asignar, restaurar) refresquen la card; por eso se quita `['docs-documents']`.
4. **Cantidad (`countLabel(page)`):** `page.total` definido → `String(total)`; si no, `page.cursor` presente
   → `` `${page.returned}+` ``; si no, `String(page.returned)` (sin cursor, `returned` es exacto). La
   cantidad va dentro del `h2`, en un `<span>` aparte: `"Documentación"` + `"12"` → nombre accesible
   `"Documentación 12"`. Mientras carga, con el módulo caído o con error: solo `"Documentación"`.
5. **"Ver todos ›" es un enlace (`next/link`), no un `Button`:** el DS de `web` dice "**NO SE DEBE** usar el
   botón para navegar entre pantallas"; el screen.md pide el aspecto `secondary-nav`. Se implementa como
   `<Link href>` con los tokens de `Button` `secondary-nav` en el CSS Module del panel (gap aceptado de REQ-021
   "Button no tiene variant de texto/enlace"). Texto visible `"Ver todos"` + `<span aria-hidden="true">›</span>`;
   nombre accesible `"Ver todos"`. `href = '/docs?' + serializeDocsSearch({ tokens: [token], publico: false,
   orden: 'recientes', pagina: 1, origen })` → `/docs?proyecto=12&origen=proyecto`,
   `/docs?requisito=45&origen=requisito`, `/docs?tarea=7&origen=tarea`. Se oculta con 0 documentos,
   mientras carga, con el módulo caído y con error.
6. **"+" solo icono:** `Button` `secondary-dismiss` con `<span aria-hidden="true">+</span>` y `<span
   className={styles.srOnly}>{nombre}</span>` (mismo patrón que el "+" de "Tareas" en `RequirementDetail`).
   Nombres: `"Nuevo documento en este proyecto"` · `"Nuevo documento en este requisito"` · `"Nuevo documento
   en esta tarea"`. `disabled` con el módulo `unavailable` o con error de la consulta; habilitado mientras
   carga y con 0 documentos. Abre `NewDocumentDialog open initial={cardInitial(...)} onClose`.
   El diálogo se monta solo con el módulo `available`.
7. **Filas (`DocumentRowCompact`)**: `<li>` con icono file, título como `<Link href="/docs/{id}">` con
   `::after` que cubre la fila (fila entera clickeable, un solo foco), fecha `formatDay(updatedAt)` en mono a
   la derecha (`"—"` si falta), y debajo la línea de meta: `TopicPills topics emptyLabel="Sin tema"` (máx. 3
   + `+N`, como hoy) y, si `showIndirect && projectMatch === 'indirect'`, `" · vinculado, sin proyecto
   propio"`. **Sin ruta, sin visibilidad, sin "En edición".** La lista es `<ul aria-label="Documentos
   vinculados">`. El título usa `doc.title` tal cual (en 1.3.0 el servicio siempre lo deriva); se borra
   `displayTitle`.
8. **La marca indirecta solo en la card de proyecto** (`showIndirect = 'projectId' in scope`): CA-5 lo pide
   explícito aunque jiku-docs solo mande `projectMatch` al filtrar por proyecto.
9. **Desborde a 1440 px (bug con test, CA-5):** sin `Table`; la fila es `display: grid;
   grid-template-columns: minmax(0, 1fr) auto;` y la columna de texto lleva `min-width: 0`; el título
   `overflow-wrap: anywhere`. jsdom no mide layout: el test verifica (a) que no hay `table` ni ruta en el DOM
   y (b) esas reglas en `DocumentRowCompact.module.scss` leyendo el archivo (mismo patrón que
   `RequirementDetail.test.tsx`, `scssContent` + extracción de bloque por llaves balanceadas).
10. **Estados** (sin regresión, CA-6): `not_installed` → `null` y la consulta con `enabled: false`;
    `unavailable` o `isError` → card con `DocsNotice intent="warning"` y `DOCS_UNAVAILABLE_MESSAGE`, "+"
    deshabilitado, sin lista ni "Ver todos"; cargando → `Loader variant="inline"` (sin label propio: el DS
    prohíbe "pasar un label distinto por consumidor"; nombre accesible `"Cargando"`); vacío → `EmptyState
    variant="list"` con el mensaje por entidad (los mismos de hoy).
11. **Bajas:** `useDocuments` (+ `PANEL_PAGE_SIZE`), `utils/paths.ts`, `utils/persons.ts` y sus tests quedan
    sin uso y se borran; `usePersons` (`features/auth`) no se toca. Los tipos `path`/`folderId`/`fileName`
    de `DocsDocument` se conservan (contrato verbatim).

### Design System Context — `web`

- **Versión fijada:** `4.3.0` (verificada por la revisión UX de REQ-021, 20 specs).
- **Accent de la superficie:** verde agua `#61CCB9` (`color.brand.primary`) — acento, foco e ítem activo;
  "**`#61CCB9` sobre blanco da 1.9:1: nunca se usa para texto.**" Texto/enlace verde sobre claro:
  `color.brand.primary-deep` `#12897A`.
- **Grid:** `desktop` 1440 px, único, 12 columnas, sin `@media` nuevos. La card vive en una columna de 420 px
  (proyecto, requisito) o a ancho completo (tarea).
- **Mono:** sin token de familia monoespaciada (gap previo): la fecha usa
  `var(--fontStack-monospace, ui-monospace, SFMono-Regular, Menlo, Consolas, monospace)` como `DocumentRow`.

**Componentes usados (extractos normativos verbatim):**
- **Card** (`panel`) — "**NO SE DEBEN** anidar tarjetas." "**NO SE DEBE** usar color de fondo de sistema en
  la superficie de la tarjeta." "Una tarjeta clickeable en su totalidad **DEBE** exponer un solo destino
  accesible" (aplica a la fila: un solo `<a>` con `::after`). API usada: `variant="panel"`,
  `headingLevel="h2"`, `header` (slot con el `h2` propio + acciones), `children`.
- **Button** (`secondary-dismiss`, "+") — "Foco: anillo `focus.ring` visible. **NO SE DEBE** suprimir con
  `outline: none` sin reemplazo." "**NO SE DEBE** usar el botón para navegar entre pantallas." API:
  `variant`, `disabled`, `onClick`, `children`.
- **Badge** (`outline`, `neutral`, vía `TopicPills`) — "**NO SE DEBE** usar un badge como botón." "**NO SE
  DEBE** comunicar el estado sólo con color."
- **EmptyState** (`list`) — "**NO DEBE** usar `role="alert"`: la ausencia de datos no es un error." "El
  mensaje **DEBE** ser texto real." "**NO SE DEBE** dejar el área en blanco sin mensaje." API: `variant`,
  `message`.
- **Loader** (`inline`) — "El contenedor **DEBE** llevar `role="status"` con `aria-live="polite"`." "En
  `inline` sin label visible, el indicador **DEBE** llevar `aria-label="Cargando"`." "**NO SE DEBE** pasar un
  label distinto por consumidor." "**NO SE DEBE** usar un loader para decir 'no hay datos'."

**Accesibilidad (guideline `web`, extracto aplicable):** WCAG 2.2 AA. "NO comunicar estado solo con color."
"Todo elemento interactivo es accesible vía teclado. Foco visible. ESC cierra modales / popovers. Enter /
Space activan controles." "Cada componente declara su rol ARIA correcto. Iconos puramente decorativos:
`aria-hidden="true"`." Aplicado a la card: `h2` con la cantidad; "+" con nombre accesible; "›" e icono file
`aria-hidden`; lista con `aria-label`; foco de la fila en el enlace del título.

**DS Gaps — `web`:**
- *Aceptados* (REQ-021 → "Dejar anotado"):
  - **lista-documentos-card** (`list`) — "`web` no tiene componente de lista; gap **previo** … Las filas
    compactas se usan en tres cards: candidato claro a componente (`DocumentRowCompact`); en modo auto no se
    crea". Se implementa como componente de la feature.
  - **boton-nuevo-documento-card** (`button` solo icono) — "`Button` no tiene variant de texto/enlace ni de
    solo icono (fuera del FAB). Se implementan con los tokens de `Button` y nombre accesible obligatorio".
  - **aviso-documentacion-no-disponible** (`alert`) — gap previo: `DocsNotice`.
  - **marca-sin-proyecto-propio** (`label`), **temas-documento-card** (`chips`) — cubiertos por texto
    secundario y `Badge` `outline`.
- *Nuevos* (aparecieron al planificar; **no bloquean**):
  - **boton-ver-todos-documentos** declarado `Button` `secondary-nav` pero es navegación: choca con la regla
    del DS "no usar el botón para navegar". Se implementa como `Link` con los tokens visuales de
    `secondary-nav` (Decisión 5). Candidato a una variant enlace vía `/product-design-system-update`.
