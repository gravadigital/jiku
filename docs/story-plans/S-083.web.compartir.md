## Story Reference

- **Story:** [S-083](../stories/S-083.web-compartir.md)
- **Service:** `web`
- **Summary:** Agrega a `/docs/[id]` el botón **"Compartir"** (solo con `features.sharing` de
  `GET /modules` y `folder.effectivePermission === 'manage'`) y el overlay **O-12 Compartir
  documento**: crear un link público de solo lectura (vencimiento 7/15/30/90/180 días, nota, con o sin
  adjuntos), mostrar la URL **una sola vez** con "Copiar", confirmar el posible secreto con un botón
  distinto ("Compartir igual"), listar los links sin URL ni token y revocarlos con O-02.

**Fuera de esta story (no implementar acá):** la ruta pública `/p/docs/{token}` que sirve el link →
**S-080** (api). La documentación del flujo `lectura-por-link-compartido` y el ADR-015 → **S-085**.
Links con versión fija (`mode: pinned`) → descartado por la UX ("sigue al documento").

**Ya existe (S-081 y S-082, Completed) y se extiende:** `features/docs/` completo — tipos
(`docs.types.ts`, `module.types.ts` con `features.sharing`), `useModule('docs')` → `{ status, sharing,
isKnown }`, `useDocument`, `DocumentView` (encabezado con "Volver" y "Editar"), `DocsNotice`
(`warning`/`error`/`info`, `role` `alert`/`none`), `NewDocumentDialog` (armazón de modal),
utils `docsResult` (`toResult`/`unwrap`), `docsErrors`, `moduleInvalidation`, `dates`
(`formatDateTime`), `paths` (`displayTitle`). **No hay que tocar la api**: las tres rutas de shares
existen desde S-079 y `features.sharing` desde S-077.

### Service Architecture

`web` es `type: frontend`, `language: nextjs`. Todas sus convenciones son **custom**
(`docs/architectures/web/conventions/`): `data-fetching`, `mutations`, `api-routes`, `auth`,
`state-management`, `forms`, `styling`, `error-handling`, `testing-unit`.

**Estructura relevante (nuevo marcado):**

```
│                                       CreateShareInput, ShareExpiryDays

├── hooks/                            + useDocumentShares, useCreateShare, useRevokeShare

│   └── DocumentView/                 + boton-compartir y montaje de O-12
└── index.ts / hooks/index.ts         + exports
```

**Datos en tres capas:** componente cliente → hook (`useQuery` / `useMutation`) → Server Action
(`'use server'`, `apiClient`) → api. Sin route handler nuevo: ninguna llamada de esta story necesita una
capacidad que el Server Action no tenga.

**Manejo de errores:** el interceptor de axios normaliza todo fallo a
`ApiError { code, message, status, details? }`. Las Server Actions de docs **no lanzan**: devuelven
`DocsResult<T>` (`toResult`) y el hook re-lanza con `unwrap` del lado del cliente (P-2 de S-082, ya
vigente para todas las Server Actions de `features/docs`). Estados de datos de un componente, en orden:
**loading → error → empty → happy path**.

**Logging:** ESLint permite solo `console.warn` / `console.error`. **Nunca loguear el `token` ni la
`url` de un link compartido**, ni ponerlos en la URL del navegador, en `localStorage`/`sessionStorage`
ni en el caché de TanStack Query más allá del diálogo (story §Seguridad; REQ-016 §Seguridad).

**Testing:** Vitest + Testing Library; se mockea `apiClient` al testear Server Actions (patrón de
`docsApi.test.ts`), la capa de **services** al testear un hook (patrón de `useDocsHooks.test.tsx`) y la
de **hooks** al testear un componente. Nombres de test en español; consultas por rol y nombre
accesible; timers falsos para el `"Copiado"` de 2 s y para fijar `Date.now()`. `tests/setup.ts` trae un
polyfill de `HTMLDialogElement.showModal` (no simula el evento `cancel` nativo: `Escape` se testea por
`keydown`).

### Relevant ADRs

- **ADR-009: Token confinado al servidor**
  - Decision: el access token de Zitadel vive solo en el servidor de Next; el navegador nunca lo ve.
  - Implementation Rules:
    - El access token **NO DEBE** llegar al navegador por ningún camino: ni en el bundle, ni en una
      respuesta, ni en una cookie legible por JS.
    - La URL de la api **DEBE** leerse de `API_URL` **en el servidor, en runtime**. **NO SE DEBE**
      usar `NEXT_PUBLIC_API_URL` ni ninguna variable horneada en build.
    - En `web`, toda llamada de dominio **DEBE** ir por un Server Action (`'use server'`) con
      `apiClient`. Un route handler en `app/api/` **DEBE** justificarse por una capacidad que el Server
      Action no tenga (streaming, headers de respuesta, llamada desde componente cliente).
    - En `opus-web`, toda llamada **DEBE** ir por el proxy `/api/opus/[...path]`. **NO SE DEBE**
      agregar un cliente axios que apunte directo a `API_URL` desde el navegador.
    - Todo route handler que reenvíe a la api **DEBE** exigir sesión y responder
      `401 {"error":"Unauthorized"}` si no hay `accessToken`. La única excepción vigente es
      `GET /attachments/[id]/[fileName]` de `opus-web`, cuya autorización la decide la api.
    - Al reenviar respuestas binarias, **DEBEN** propagarse `Content-Type`, `Content-Disposition` y
      `Content-Length`.
    - Al reenviar uploads **DEBE** usarse streaming con `duplex: 'half'`, no bufferizar el archivo
      entero en memoria.
    - Un 401 de la api **DEBE** redirigir el navegador a `/login`.
    - **NO SE DEBE** agregar `NEXT_PUBLIC_*` funcional: rompería la premisa de una imagen por todos los
      entornos.
  - Aplicación en esta story: las tres llamadas (`GET`/`POST …/shares`, `DELETE /docs/shares/{id}`)
    van por Server Actions; **no se agrega ningún route handler**. Que la función de compartir esté
    configurada se lee de `GET /modules` (`features.sharing`), **nunca** de una variable
    `NEXT_PUBLIC_*` ni de `JIKU_PUBLIC_URL` en la web.

- **ADR-011: TanStack Query**
  - Implementation Rules:
    - Todo dato que venga de la api **DEBE** manejarse con TanStack Query. **NO SE DEBE** copiar una
      respuesta a `useState` ni a un store global.
    - Las query keys **DEBEN** seguir el patrón por dominio: `['<dominio>', <identificador o filtros>]`.
    - Tras una mutación exitosa **DEBE** invalidarse la key afectada. Al invalidar por prefijo, hay que
      verificar que el prefijo cubra lo que se pretende.
    - Las mutations **DEBEN** mantener `retry: 0`. Reintentar una escritura sin idempotencia
      garantizada duplicaría datos ([ADR-002](ADR-002-comandos-nats-sin-jetstream.md)).
    - El update optimista **DEBE** usarse solo donde el rollback sea trivial y la latencia se note. **NO
      SE DEBE** aplicar por default.
    - El estado propio de la interfaz **DEBE** usar `useState` local. Un Context nuevo **DEBE**
      justificarse por tener consumidores reales.
    - En listados paginados por categoría, **DEBE** evaluarse el costo de montar N queries en paralelo:
      el tablero del portal monta 7 y su `isLoading` es un `some`, así que la pantalla espera a la más
      lenta.
  - Aplicación: la lista es `useQuery(['docs-shares', documentId])`. **Excepción deliberada a "no
    copiar una respuesta a `useState`" (P-3):** la `url` del `201` se guarda en `useState` local del
    diálogo **y en ningún otro lado** —es estado de interfaz efímero que la UX exige descartar al
    cerrar— y la mutación de alta usa `gcTime: 0` + `reset()` al cerrar para que el caché de mutaciones
    no la retenga. Sin update optimista: la revocación actualiza la fila **después** del `200`.

- **ADR-010: Sass + CSS Modules sin librería**
  - Implementation Rules:
    - Los estilos de un componente **DEBEN** vivir en su `*.module.scss` adyacente. **NO SE DEBE**
      usar CSS global salvo en `globals.scss` y en la capa de tokens.
    - Los valores de color, espaciado y tipografía **DEBEN** referenciar custom properties de
      `_variables.scss`. **NO SE DEBEN** hardcodear valores hexadecimales ni píxeles sueltos.
    - Los patrones visuales repetidos (tipografía, botones, inputs, tags, focus rings) **DEBEN** usar
      los mixins de `_mixins.scss`.
    - Los breakpoints **DEBEN** declararse con los mixins de `_mixins.scss`. **NO SE DEBEN** escribir
      `@media` crudas con valores literales — hoy hay 14 en `web` con 8 valores distintos, y es deuda
      reconocida (NFR-U03).
    - **NO SE DEBE** agregar una librería de componentes ni un framework CSS utilitario sin un ADR que
      lo reemplace.
    - En `opus-web`, las variantes de componente **DEBEN** expresarse con atributos `data-*`, no con
      nombres de clase compuestos.
    - Un valor de token **DEBE** declararse en un solo lugar.
  - **Precisión vigente (convención `styling`, REQ-013):** los tokens se consumen del **tier
    semántico o de componente** (`_semantic.scss` / `_component.scss`), **nunca** primitivos ni hex.
    El guardia `features/design-system-migration.guard.test.ts` falla si aparecen tokens viejos de
    `_variables.scss`, hex literales, radios fuera de 8/10/14/999, `<button>` o `<table>` crudos,
    `font-size` en px, `font-weight` numérico o `font-family` con `system-ui`/`Roboto` en cualquier
    `.tsx` / `.module.scss` de `web/src`.

- **ADR-002: Comandos NATS sin JetStream** (citado por ADR-011) — sin acuse ni idempotencia: un
  `504` en una escritura significa "pudo haberse aplicado". Por eso **ninguna escritura se reintenta
  sola**; tras cualquier respuesta del alta se refresca la lista para que un link que sí se creó
  aparezca y pueda revocarse (P-4).

- **ADR-015 "Módulos opcionales del bus"** (DD-17 de REQ-016) todavía no existe: lo escribe S-085.
  Las decisiones que aplican se copian abajo desde REQ-016.

### API Context

Todas las llamadas salen de Server Actions con `apiClient` (Bearer inyectado por el interceptor). El
`baseURL` ya incluye `/api`: se llama `apiClient.get('/docs/documents/{id}/shares')`, no
`/api/docs/...`.

**Reglas comunes a todas las rutas `/docs/*`** (verbatim de `api.yaml`): `x-roles: [admin, user]`,
`x-jiku-module: docs`. "La api no autoriza el dominio de documentación (REQ-016, DD-2): jiku-docs
resuelve el ACL con el `actor` (el `sub` del token) y responde `permission_denied`. `requireModule` va
antes que el rol. Las reglas de dominio las valida jiku-docs y su `code` llega sin traducir (DD-7). Un
`id` mal formado responde 404 sin llamar al bus." Un parámetro o campo no declarado es **400
`invalid_fields`**.

#### `GET /docs/documents/{id}/shares` — Lista los links compartidos de un documento

Verbatim: "Consulta `shares.list` con `filter: { documentId, status? }` y `sort: ['-createdAt']`
(REQ-016, ruta 18). Nunca incluye el token (CA-31). Funciona sin `JIKU_PUBLIC_URL`."

| Parámetro | En | Tipo |
|---|---|---|
| `id` | path | string ULID `^[0-9A-HJKMNP-TV-Z]{26}$` (id del documento) |
| `status` | query | enum `active, revoked, expired` — **no se usa** (P-7) |
| `limit` | query | integer 1-200, default 50 — **se manda `200`** (P-7) |
| `cursor` | query | string ≤ 500 — no se usa |

→ `200 DocsSharePage`. Errores: 400 (`ModuleBadRequest`), 401, 403 (`ModuleForbidden`), 404
(`ModuleNotFound`), 500, 503 (`ModuleUnavailable`), 504 (`ModuleGatewayTimeout`).

#### `POST /docs/documents/{id}/shares` — Crea un link compartido

Verbatim: "Publica `shares.new` (REQ-016, ruta 19, CA-S9). Responde 404 `sharing_not_configured` si
la api no tiene `JIKU_PUBLIC_URL` (DD-14); el chequeo va después de validar el `id`. El `token` y la
`url` se devuelven **solo acá** y no se loguean. `secret_warning_not_acknowledged` (400): reenviar con
`acknowledgeSecretWarning: true`."

```yaml
requestBody:
  required: true
  content:
    application/json:
      schema:
        type: object
        additionalProperties: false
        required: [mode, expiresAt]
        properties:
          id: { type: string, pattern: '^[0-9A-HJKMNP-TV-Z]{26}$' }
          mode: { type: string, enum: [latest, pinned] }
          version: { type: integer, minimum: 1, description: "Obligatoria con `pinned` (la valida jiku-docs)" }
          expiresAt: { type: string, format: date-time, description: "Futuro y como máximo 180 días (`share_expiry_invalid`)" }
          includeAttachments: { type: boolean }
          note: { type: string, minLength: 1 }
          acknowledgeSecretWarning: { type: boolean }
```

→ `201 DocsShareCreated`. Errores: 400 (`ModuleBadRequest`: `invalid_fields`,
`secret_warning_not_acknowledged`, `share_expiry_invalid`), 401, 403 (`ModuleForbidden`:
`permission_denied`, `sharing_blocked`), 404 (`ModuleNotFound`: `document_not_found`,
`sharing_not_configured`, `module_not_installed`), 409 (`ModuleConflict`), 500, 503, 504.

#### `DELETE /docs/shares/{id}` — Revoca un link compartido

Verbatim: "Publica `shares.{id}.revoke` (REQ-016, ruta 20). Funciona sin `JIKU_PUBLIC_URL`. Un `id` mal
formado responde 404 `share_not_found` sin llamar al bus. La api no autoriza: jiku-docs exige `manage` o
ser el creador del link."

- **boton-copiar** — `"Copiar"` → tras copiar, `"Copiado"` durante 2 s; ícono check (solo en
  `"Copiado"`).
- **aviso-secreto** — `"Este documento parece contener una clave o un token. Si lo compartís,
  cualquiera con el link lo va a poder leer."`; ícono warning. Aparece cuando el módulo rechaza el alta
  con `secret_warning_not_acknowledged`. La salida segura es cerrar y corregir el documento.
- **boton-compartir-igual** — `"Compartir igual"`. Reenvía el alta reconociendo el aviso. El `"Crear
  link"` queda oculto en este estado para que la confirmación sea una acción distinta y no el mismo
  click repetido.
- **aviso-bloqueado** — `"La carpeta de este documento no permite compartirlo fuera de Jiku."`; ícono
  lock. `sharing_blocked`. La lista de links existentes se sigue mostrando y se puede revocar.
- **titulo-links** — `"Links de este documento"`.
- **tabla-links** — columnas `"Estado"` · `"Vence"` · `"Nota"` · `"Accesos"` · `"Último acceso"` ·
  (acción). Estado con `Badge`: `"Activo"` · `"Vencido"` · `"Revocado"`. Sin nota: `"—"`. Sin accesos:
  `"Nunca"` en "Último acceso". **La URL y el token no aparecen nunca en la lista** [REQ-016 CA-31].
  Orden: más nuevo primero.
- **boton-revocar** — `"Revocar"`. Abre O-02 con `"Revocar link"` · `"Quien tenga este link va a dejar
  de poder abrir el documento. No se puede deshacer."` · `"Revocar"` / `"Cancelar"`.
- **vacio-links** — `"Este documento todavía no tiene links."`; ícono link. `EmptyState` `list`.
- **boton-cerrar-compartir** — `"Cerrar"`. Con un link recién creado, cerrar es lo que lo hace
  desaparecer para siempre; el aviso ya lo dijo, no se pide confirmación.

**Estados (verbatim):**

- **default** — formulario y lista visibles.
- **empty** (sin links) — `"Este documento todavía no tiene links."`; vacio-links visible; tabla-links
  oculta.
- **loading** — tabla-links: `Loader` `inline` en el cuerpo; boton-crear-link: disabled con `Loader`
  `inline` mientras crea.
- **error de validación** — `"El vencimiento no es válido. Elegí entre 7 y 180 días."`
  (`share_expiry_invalid`); selector-vencimiento: state=error.
- **error de sistema / sin conexión** — `"No se pudo crear el link. Intentá de nuevo."` · lista: `"No
  se pudieron cargar los links."` · función no configurada: `"Compartir no está habilitado en esta
  instalación."` (`sharing_not_configured`); mensaje `role="alert"` sobre el formulario.
- **success** — ver *link creado*.
- **not found** — no aplica: el documento ya está abierto; si dejó de existir, el error se muestra como
  error de sistema.
- **estado terminal / readonly** — ver *compartir bloqueado*.
- **link creado** (parent: success) [REQ-016 CA-31] — `"Copiá el link ahora: por seguridad, no lo vas a
  poder volver a ver."`; aviso-link-creado, campo-link, boton-copiar: visibles;
  explicacion-compartir, selector-vencimiento, campo-nota, selector-adjuntos, boton-crear-link:
  ocultos; tabla-links: suma la fila nueva, **sin la URL**.
- **confirmar posible secreto** (parent: default) — `"Este documento parece contener una clave o un
  token. Si lo compartís, cualquiera con el link lo va a poder leer."`; aviso-secreto y
  boton-compartir-igual: visibles; boton-crear-link: oculto.
- **compartir bloqueado** (parent: default) — `"La carpeta de este documento no permite compartirlo
  fuera de Jiku."`; aviso-bloqueado: visible; formulario: oculto; la lista sigue visible con
  boton-revocar operable.
- **sin links** (parent: default) — `"Este documento todavía no tiene links."`; vacio-links: visible.

**Interacciones (verbatim):**

- boton-crear-link · on click → `POST /docs/documents/{id}/shares` con vencimiento, nota y adjuntos →
  *link creado*; `secret_warning_not_acknowledged` → *confirmar posible secreto*; `sharing_blocked` →
  *compartir bloqueado*.
- boton-compartir-igual · on click → reenvía reconociendo el aviso → *link creado*.
- boton-copiar · on click → copia al portapapeles; el label pasa a `"Copiado"` 2 s.
- boton-revocar · on click → O-02; al confirmar, `DELETE /docs/shares/{id}` y la fila pasa a
  `"Revocado"`.
- boton-cerrar-compartir / `Escape` · → cierra; la URL creada se descarta de memoria.
- **Validaciones:** ninguna en el cliente: el vencimiento sale de una lista cerrada.
- **Feedback:** revocar: el badge de la fila cambia a `"Revocado"`; sin toast (el resultado se ve).

**Accesibilidad (verbatim):**

- **Orden de foco:** selector-vencimiento → campo-nota → selector-adjuntos → boton-crear-link → filas
  de tabla-links (boton-revocar) → boton-cerrar-compartir. Con link creado, el foco va a campo-link.
- **Landmarks y jerarquía:** `role="dialog"` con `aria-modal`, `aria-labelledby` hacia
  titulo-compartir (h2) y h3 para la lista.
- **Foco y teclado:** atrapa el foco; `Escape` cierra; al cerrar vuelve a `boton-compartir`. O-02 se
  apila encima y devuelve el foco a la fila revocada (P-10).
- **Propio de esta composición:** el cambio a *link creado* se anuncia (`role="status"`) porque
  reemplaza el formulario sin navegar; `"Copiado"` también se anuncia.
- Foco inicial al abrir: **selector-vencimiento** (primer control del orden de foco); en *compartir
  bloqueado*, el primer `"Revocar"` o, sin filas activas, `boton-cerrar-compartir`.

**Decisiones (verbatim):**

- **Crear y listar en el mismo diálogo.** Quien comparte casi siempre quiere ver qué links ya existen
  antes de crear otro; separarlos haría crear duplicados.
- **El link se muestra una sola vez, y el diálogo lo dice antes de que se pierda.** El módulo no lo
  vuelve a entregar; la nota es la que permite reconocer cada link después [REQ-016 Supuestos].
- **Vencimiento elegido de una lista, no con un calendario.** Cinco plazos cubren los casos y no hay
  fecha inválida posible; 15 días está porque es el caso del criterio de aceptación [REQ-016 CA-31].
- **La confirmación de posible secreto es un botón distinto.** Si fuera el mismo "Crear link", el
  segundo click sería un reflejo y no una decisión.
- **Adjuntos con `ToggleGroup` y no con checkbox.** El DS de `web` no tiene checkbox; el segmentado es
  el control existente para una elección entre dos opciones.
- **Descartadas:** mostrar la URL en la lista (el contrato no la devuelve y no debe guardarse en el
  navegador); elegir una versión fija para el link (el pedido no lo pide y "sigue al documento" es lo
  que se espera de un link a documentación viva).

#### Flujo de usuario relevante (web `user-flows.md`, Flujo 6, verbatim)

**Flujo 6: Compartir un documento con alguien de afuera.** JTBD: *"Cuando alguien sin cuenta en Jiku
necesita leer un documento, quiero mandarle un link que se corte solo, en vez de copiar el texto a un
mail o abrir un acceso."* Audiencia: equipo-interno — quien administra la carpeta del documento
(`manage`). Trigger: en **documento**, botón **"Compartir"**. **Existe solo si la instalación tiene
configurada la función de compartir** (`JIKU_PUBLIC_URL`); si no, el botón no aparece [REQ-016 CA-32].

Happy path:
1. **documento** → **"Compartir"** abre O-12, con los links que ya existen
2. Elige vencimiento (default 30 días, máximo 180), una nota para reconocer el link y si incluye
   adjuntos
3. **"Crear link"** → el link aparece **una sola vez**, con **"Copiar"** y el aviso de que no se podrá
   volver a ver [CA-31]
4. Cierra; la lista muestra el link nuevo con estado, vencimiento, nota y accesos, **sin la URL**
5. Lo manda por el canal que quiera; quien lo recibe lo abre sin cuenta

Alternativos: **Revocar** — desde la misma lista, con confirmación (O-02); el link deja de funcionar al
instante. **Perdió el link** — no se puede recuperar: se revoca y se crea otro.

Errores: **Posible secreto** — O-12 lo avisa y pide **"Compartir igual"** como acción distinta.
**Carpeta que no permite compartir** — aviso; la lista se sigue viendo y se puede revocar.

Estado final: existe un link activo, que vence solo y que el equipo puede cortar antes.
Criterios de éxito: el link **nunca** debería poder recuperarse desde la interfaz después de cerrado el
diálogo; quien comparte debería saber **qué ve el otro**: la última versión, sin sesión, hasta que
venza.

#### Flujo cross-surface (`cross-surface-flows.md`, Flujo 5, filtrado)

**Un documento leído por alguien sin cuenta** — `web` (origen) → página pública de la api (destino, no
es una superficie). Existe solo con el módulo instalado y la función de compartir configurada.

| # | Superficie | Quién | Acción |
|---|---|---|---|
| 1 | web | equipo-interno (`manage`) | Crea un link en O-12 y lo copia (se muestra una sola vez) — ver `web` Flujo 6 |
| 2 | — | equipo-interno | Lo manda por fuera del producto (mail, chat) |
| 3 | página pública | tercero | Abre `{JIKU_PUBLIC_URL}/p/docs/{token}` sin iniciar sesión y lee el documento |
| 4 | web | equipo-interno | Ve en la lista de O-12 cuántas veces se abrió y cuándo; lo revoca si hace falta |

Sincronización: **no hay tiempo real**. "Los accesos se cuentan, pero solo se ven abriendo O-12" (la
lista se pide al abrir el diálogo). Criterio: un link vencido o revocado debería **dejar de funcionar
al instante** y sin revelar por qué (lo garantiza S-080).

### Design System Context — `web`

- **Versión fijada:** `web` **v4.2.0** (normativo, implementado).
- **Accent color de la superficie:** `color.brand.primary` = verde agua. Se consume vía tokens
  semánticos, nunca el hex.
- **Componentes usados:** `Select` (`single`), `Input` (`text`, `locked`), `ToggleGroup`
  (`segmented`), `Button` (`primary`, `secondary-nav`, `secondary-dismiss`), `Table` (`light`), `Badge`
  (`state`), `EmptyState` (`list`), `Loader` (`inline`), `ConfirmDialog` (O-02 y armazón de O-12).
  APIs en "Reusable Code".
- **Reglas de spec que aplican (extracto normativo):**
  - **ToggleGroup:** **DEBE** implementarse como grupo de radios (`role="radiogroup"` con
    `role="radio"`); el grupo **DEBE** tener nombre accesible; labels cortos (una o dos palabras —
    "Incluir adjuntos" / "Solo el texto" son de dos/tres, aceptados por la UX); contenedor `segmented`
    con radio 10 (`radius.field`), se ajusta a su contenido (`width: fit-content`), segmentos sin gap;
    **NO SE DEBE** usar para más de cuatro o cinco opciones ni para selección múltiple.
  - **Select:** label `text.field-label` (13/400), sustantivo ("Vence en"); el menú **DEBE** ser
    operable sin puntero; **NO SE DEBE** abrir el menú al recibir foco por teclado sin acción
    explícita; **NO SE DEBE** poner `searchable` en una lista fija y corta.
  - **Input:** label visible asociado siempre (el placeholder nunca lo reemplaza); alto 44 px y radio
    10 px; foco con anillo verde agua; `locked` es de solo lectura y seleccionable.
  - **ConfirmDialog:** **DEBE** llevar `role="dialog"` con `aria-modal="true"` y `aria-labelledby`;
    **el foco DEBE atraparse** y volver al disparador; **`Esc` DEBE cerrar**; el cuerpo **DEBE**
    nombrar qué se afecta; el fondo **DEBE** quedar inerte; **NO SE DEBE** usar rojo ni el primario
    verde agua en el confirmar de una acción destructiva (ambas acciones `secondary-dismiss`).
  - **Button:** un solo `primary` visible por vista (en O-12 lo garantizan los estados: "Crear link" o
    "Compartir igual" o "Copiar"); `secondary-nav` navega/abre (por eso "Compartir" es `secondary-nav`),
    `secondary-dismiss` descarta ("Cerrar", "Revocar"); `loading` → spinner + `aria-busy`.
  - **Table:** todo listado usa `light`; **DEBE** usarse `<table>` real con `<th scope="col">`; una
    celda recortada **DEBE** conservar su texto completo en el DOM; **NO SE DEBE** teñir la fila con un
    color de sistema.
  - **Badge:** `state` = pill con punto de color; no interactivo; mapeo de familias en P-8.
  - **EmptyState:** `list` admite acción (acá no lleva); nunca `role="alert"`.
- **Feedback de estado (tokens semánticos, `tokens/semantic.md`):**

| Token | Pleno | Tinte | Borde | Texto |
|---|---|---|---|---|
| `state.resolved` | `color.system.resolved` | `color.tint.green` | `color.tint-border.green` | `color.deep.green` |
| `state.in-progress` | `color.system.resolved` | `color.tint.aqua` | `color.tint-border.aqua` | `color.deep.green` |
| `state.review` | `color.system.medium` | `color.tint.amber` | `color.tint-border.amber` | `color.deep.amber` |
| `state.urgent` | `color.system.urgent` | `color.tint.red` | `color.tint-border.red` | `color.deep.red` |
| `state.analysis` | `color.system.analysis` | `color.tint.violet` | `color.tint-border.violet` | `color.deep.violet` |
| `state.neutral` | `color.graphite` | `color.tint.graphite` | `color.tint-border.graphite` | `text.secondary` |

  En CSS: `--state-{resolved,in-progress,review,urgent,analysis,neutral}-{full,tint,border,text}`. El
  modo oscuro los redeclara en `_semantic.scss`: un componente nuevo **no** escribe
  `[data-theme='dark'] &`. `DocsNotice`: `warning` → `review` (aviso-secreto), `error` → `urgent`
  (errores del alta, de la lista y de la revocación), `info` → `neutral` (aviso-bloqueado), **`success`
  → `resolved`** (aviso-link-creado, P-13).
- **Grid:** viewport `desktop` 1440 px, 12 columnas, único. Dentro del modal de 640 px las fracciones
  se aplican sobre una grilla de 12 columnas con gap `--space-grid-gap`.
- **Accesibilidad (`guidelines/accessibility.md`):** WCAG 2.2 AA. NO comunicar estado solo con color
  (el `Badge` lleva texto). Todo interactivo accesible por teclado, foco visible (contraste ≥ 3:1),
  orden de tab lógico. Iconos decorativos `aria-hidden="true"`; funcionales con `aria-label`. Live
  regions para feedback dinámico (`role="status"` del link creado y del "Copiado"). Respetar
  `prefers-reduced-motion`.
- **Contenido (`guidelines/content.md`):** sin toast cuando el resultado ya está en pantalla (por eso
  crear y revocar no tienen toast); preferir el error junto al campo antes que el toast (por eso
  `share_expiry_invalid` va en el `error` del `Select`).

**DS Gaps para `web`:**

- **Aceptados** (Revisión UX de REQ-016, resolución "Dejar anotado"):
  - **`alert`** (aviso-link-creado, aviso-secreto, aviso-bloqueado, errores del alta/lista/revocación)
    — *"`web` no tiene componente de aviso inline. Se usa en 5 pantallas y 2 overlays de este REQ, así
    que es candidato claro a componente; en modo auto no se crea. Mientras tanto: `role="alert"` y los
    tokens de estado del DS."* Se reutiliza el `DocsNotice` local, extendido con `success` y
    `role="status"` (P-13).
  - **`modal`** (modal-compartir) — *"`ConfirmDialog` especifica superficie, overlay, z-index y a11y de
    un diálogo; los dos overlays reutilizan ese armazón con un cuerpo de formulario. Un `Dialog`
    genérico sería el componente correcto."* `ShareDocumentDialog` replica el armazón de
    `NewDocumentDialog`/`ConfirmDialog` con ancho 640 px, en `features/docs/`, sin crear un componente
    en `shared/components/ui/`.
- **Resueltos en el REQ como "Reemplazar"** (no son gaps): selector-adjuntos (`checkbox`) →
  `ToggleGroup` segmentado. **Cubiertos** sin gap: campo-link → `Input` `locked`; selector-vencimiento
  → `Select`; tablas, badges, vacíos, cargas → `Table`, `Badge`, `EmptyState`, `Loader`.
- **Nuevos** (aparecieron al planificar):
  - **Label visible del `ToggleGroup`** — el componente solo expone `aria-label`; el screen.md pide
    label `"Adjuntos"` visible. Se pinta un texto con `aria-hidden="true"` encima del grupo (P-14).
    Candidato a prop `showLabel` / `<legend>` en `ToggleGroup`.
  - **Ícono en `Select`** — el screen.md declara ícono calendar para selector-vencimiento y `Select` no
    acepta ícono. Se omite el ícono (es decorativo). Candidato a prop `icon` en `Select`.
  - **Seleccionar al enfocar en `Input` `locked`** — "seleccionado entero al recibir foco" no lo da el
    componente (sin `onFocus` ni `ref`). Se resuelve con un wrapper `onFocusCapture` que llama
    `select()` sobre el `<input>`. Candidato a comportamiento por defecto de `locked`.
