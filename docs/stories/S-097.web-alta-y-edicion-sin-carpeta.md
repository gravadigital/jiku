# S-097: web: alta y edición sin carpeta

**Status:** Ready
**Created:** 2026-10-26
**Source:** REQ-021

## Historia de Usuario

**Como** persona interna que crea y edita documentos,
**quiero** crear un documento eligiendo cliente, proyecto, temas y visibilidad (sin carpeta ni plantilla) y editarlo con un mensaje opcional de versión,
**para** documentar rápido, dejarlo vinculado y proteger las versiones importantes.

## Criterios de Aceptación

### CA-1: Visibilidad según rol

**DADO** una persona con rol `user`
**CUANDO** abre "Nuevo documento"
**ENTONCES** el selector ofrece Interno (por defecto) y Visible para el cliente, sin Restringido; para un `admin` ofrece además Restringido

### CA-2: Alta sin carpeta

**DADO** el alta con título, cliente, proyecto y temas
**CUANDO** elige "Crear y editar"
**ENTONCES** la api llama a `documents.new` sin `folderId` ni `fileName`, y sin recargar la página el documento queda abierto en edición con el lock tomado

### CA-3: Sin ruta ni plantilla

**DADO** el diálogo "Nuevo documento"
**CUANDO** se abre
**ENTONCES** no muestra carpeta, nombre de archivo, ruta, aviso de ruta ni plantilla; el proyecto se limita al cliente elegido y elegir un proyecto completa el cliente

### CA-4: Temas libres

**DADO** el campo de temas del alta o la edición
**CUANDO** escribe un prefijo
**ENTONCES** ve los temas existentes de `topics.list` y puede agregar uno nuevo con Enter; no hay "Proponer tema nuevo"

### CA-5: Relaciones precargadas

**DADO** el "+" de una card de Documentación
**CUANDO** abre "Nuevo documento"
**ENTONCES** el proyecto (y su cliente; en requisito y tarea también el requisito o la tarea) ya están elegidos

### CA-6: Edición por campos

**DADO** un documento en edición
**CUANDO** la persona cambia título, visibilidad, temas, cliente o proyecto
**ENTONCES** se edita con campos, el editor de markdown muestra solo el cuerpo y un solo `PUT` guarda todo (sin perder claves desconocidas, comentarios ni estilo del frontmatter); requisitos y tareas vinculados se conservan

### CA-7: Propiedades ilegibles

**DADO** un frontmatter que no se puede parsear
**CUANDO** se abre la edición
**ENTONCES** la edición por campos se deshabilita, se avisa y se edita el contenido completo

### CA-8: Mensaje de versión

**DADO** el editor
**CUANDO** guarda con un mensaje
**ENTONCES** la versión se guarda con ese `message` y en el historial aparece protegida (con la aclaración de que queda protegida de la compactación)

### CA-9: Error de visibilidad

**DADO** un `user` que logra mandar `restricted`
**CUANDO** el servicio responde `permission_denied`
**ENTONCES** se muestra el error junto al selector

## Technical Design

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|
| web | Alto | `NewDocumentDialog`, `TopicsInput`, `ProjectPicker`, `DocumentEditor` con propiedades por campos, `utils/frontmatter.ts` (reescritura con la librería `yaml`, dependencia nueva), fix de la carrera "Crear y editar"; baja de `utils/slug` (nombre de archivo) | Pending |

### Cambios de API

Consume (definidas en S-094): `POST /docs/documents` (sin `folderId`/`fileName`), `PUT /docs/documents/{id}` con `message`, `POST .../lock`, `GET /docs/topics`, `GET /docs/suggestions` (proyectos y clientes para el selector). No agrega rutas.

### Cambios de Base de Datos

Ninguno.

### Diseño de la pantalla

**Alta.** La web arma `content` con frontmatter (`title`, `visibility`, `topics`, `jiku: { clients, projects, requirements, tasks }`) más `# {título}`.

**Edición (08).** Mismas cabecera y propiedades que la 06 (Cliente · Proyecto en lugar de ruta), aviso de bloqueo, fila de propiedades editables, editor y vista previa (sin frontmatter), campo "Mensaje de la versión (opcional)" junto a Guardar. Al guardar reescribe el frontmatter con `yaml` (API `Document`) y manda un solo `PUT` con `baseVersion`, `sessionId` y `message`. No se agrega "Origen HedgeDoc".

**Carrera de "Crear y editar".** `DocumentView` toma la intención de `?editar=1` una vez, primero toma el lock y recién después limpia la URL con `window.history.replaceState`. `NewDocumentDialog` navega con `router.push` y cierra el diálogo después de la navegación.

### Flujo de Interacción

#### Escenario: alta con "Crear y editar"

**Trigger:** la persona completa el diálogo y elige "Crear y editar".

1. **[web — `NewDocumentDialog`]**
   - Acción: arma el frontmatter y el título.
   - Output: `POST /api/docs/documents { content }` (sin `folderId`/`fileName`).
2. **[api]**
   - Acción: `documents.new` con `via: 'human'` y `actor`.
   - Output: `201 { id, version: 1, path, folderId, fileName }`.
3. **[web]**
   - Acción: `router.push('/docs/{id}?editar=1')`; `DocumentView` carga, `session.start()` → `POST .../lock { sessionId }` → fase `editing`; luego `history.replaceState`.

**Outcome:** documento abierto en edición con el lock tomado, sin recarga completa.

**Manejo de errores:**
- 403 `permission_denied` → error junto al selector.
- 400 `frontmatter_invalid` / `invalid_relation` → error en el diálogo.
- Falla el lock → toast actual y queda en lectura.

### Flujos Afectados

- **documentos-desde-la-web** (ref: docs/flows/documentos-desde-la-web.md) — alta sin carpeta; `message` que protege la versión; frontmatter reescrito por campos.

### Consideraciones Técnicas

**Seguridad:**
- "Restringido" solo elegible por `admin` según `session.user.roles`; la autoridad es jiku-docs.

**Performance:**
- Un solo `PUT` por guardado; sugerencias de temas con debounce.

**Dependencias:**
- S-094. Comparte componentes chicos con S-095 y S-096.
- Bug con test: la carrera "Crear y editar" (test que reproduce cierre del diálogo + navegación + efecto de la vista sin recarga y verifica `POST .../lock` y fase `editing`).
- Riesgo: reescribir el frontmatter puede perder formato. Mitigación: tests con claves desconocidas, comentarios y estilo flujo.
