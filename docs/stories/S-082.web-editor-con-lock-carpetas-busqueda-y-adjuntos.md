# S-082: web: editor con lock, carpetas, búsqueda y adjuntos

**Status:** Completed
**Created:** 2026-10-24
**Source:** REQ-016

## Historia de Usuario

**Como** persona del equipo con permiso de escritura,
**quiero** editar documentos con reserva y versión base, navegar carpetas, buscar y adjuntar archivos,
**para** mantener la documentación sin pisar los cambios de otra persona.

## Criterios de Aceptación

### CA-29: Edición con lock

**DADO** un documento sin lock
**CUANDO** la persona entra en edición
**ENTONCES** la web toma el lock, lo renueva mientras el editor está abierto, guarda con `baseVersion` y lo libera al guardar o cancelar

### CA-30: Conflicto de versión

**DADO** que al guardar llega `version_conflict`
**CUANDO** se muestra el resultado
**ENTONCES** la persona ve que alguien guardó otra versión, puede recargarla y no pierde su texto

### CA-S12: Documento bloqueado por otra persona

**DADO** un documento con lock de otra sesión
**CUANDO** la persona pulsa "Editar"
**ENTONCES** el documento queda en solo lectura con "{persona} lo está editando hasta {hora}" (el `holder` se resuelve contra `GET /persons`, con fallback "otra persona")

### CA-S13: Navegación y búsqueda (RF-21)

**DADO** el módulo `available`
**CUANDO** la persona abre `/docs`, navega carpetas por niveles o busca por texto
**ENTONCES** ve subcarpetas y documentos que puede leer, resultados de búsqueda o "sin resultados", y "Nuevo documento" solo en carpetas con `write`/`manage` (nunca en la raíz)

### CA-S14: Adjuntos

**DADO** un documento en edición
**CUANDO** la persona suelta un archivo en la zona de adjuntos
**ENTONCES** la web calcula el SHA-256 en el navegador, pide `POST /api/docs/attachments`, sube con `putFileToStorage`, confirma e inserta `![nombre]({link})`

### CA-S15: Documento grande en solo lectura

**DADO** un documento con `contentUrl` (> 256 KiB)
**CUANDO** se abre
**ENTONCES** se muestra en solo lectura con aviso y sin botón "Editar"

### Flujo de Interacción

#### Escenario: edición con lock y versión base (CA-17, CA-18, CA-29, CA-30)

**Trigger:** la persona pulsa "Editar" en `/docs/{id}` (con `folder.effectivePermission` `write` o `manage`).

1. **[web]** genera `sessionId` (ULID) y llama `POST /api/docs/documents/{id}/lock { sessionId }`. `409 document_locked` → solo lectura con "{holder} lo está editando hasta {expiresAt}".
2. **[web]** renueva cada 60 s con el mismo `sessionId` (TTL 120 s) mientras el editor está abierto.
3. **[web → api]** guardar: `PUT /api/docs/documents/{id} { baseVersion: 6, content, sessionId }`.
4. **[api]** éxito → `200 { id, version: 7 }`; la web libera con `unlock { sessionId }` y vuelve al visor.
   - `version_conflict` → `409 { code, message, details: { currentVersion: 7 } }`. La web conserva el texto propio en el editor, avisa y ofrece recargar la versión ajena al lado para copiar. Nunca reintenta en silencio.
   - `document_locked` → `409 { …, details: { holder, via, expiresAt } }`.
5. **[web]** cancelar o salir: `unlock`. Cierre de pestaña: `pagehide` → `fetch('/api/docs/documents/{id}/unlock', { method: 'POST', keepalive: true })`. Si nada llega, el lock vence a los 120 s.

**Outcome:** una versión nueva sin pisar cambios ajenos.

**Manejo de errores:**
- Reserva perdida (renovación falla) → sub-estado *reserva perdida* con el texto propio conservado.
- `permission_denied` → aviso y editor de solo lectura.

#### Escenario: subida de adjunto (CA-S14)

1. **[web]** `crypto.subtle` calcula el SHA-256 del archivo; `POST /api/docs/attachments { documentId, fileName, mimeType, fileSize, checksum }` → `201 { id, uploadUrl, expiresIn, link }`.
2. **[web]** `PUT` a `uploadUrl` con `putFileToStorage`; luego `POST …/confirm`.
3. **[web]** inserta `![nombre]({link})` en el markdown.

**Outcome:** adjunto subido directo a S3; jiku-docs delega en el servicio de archivos de core y el archivo nunca se vincula a una entidad de Jiku.

**Manejo de errores:**
- `attachment_type_not_allowed` / `attachment_too_large` → mensaje sobre la zona de adjuntos.

### Consideraciones Técnicas

**Seguridad:**
- `force` del unlock no se expone; el texto propio nunca se pisa en silencio.

**Performance:**
- Renovación cada 60 s con TTL de 120 s: un fallo aislado no pierde la reserva.

**Dependencias:**
- **R-7:** locks huérfanos al cerrar el navegador: `keepalive` + vencimiento, nunca peor que la espera del TTL.
- El editor edita hasta 256 KiB; la subida por URL de contenido grande queda fuera.
