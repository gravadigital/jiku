# S-075: Registro de módulos y política del bus para docs

**Status:** Ready
**Created:** 2026-10-24
**Source:** REQ-016

## Historia de Usuario

**Como** operador de una instalación de Jiku,
**quiero** que el despliegue base cree el registro de módulos y que el bus conozca los permisos del módulo de documentación,
**para** que jiku-docs pueda conectarse, registrarse y ser llamado sin ampliar más de lo necesario los permisos de nadie.

## Criterios de Aceptación

### CA-1: KV de módulos idempotente (RF-1)

**DADO** el stack local sin módulos instalados
**CUANDO** se levanta con `deploy/local.sh up` dos veces seguidas
**ENTONCES** el KV `JIKU_MODULES` existe una sola vez, con historial 1, sin TTL y `allow_direct`, y la segunda ejecución no falla

### CA-9: Plantilla de servidor para el machine user de docs (RF-6)

**DADO** el machine user de jiku-docs con roles `[internal-app, docs]`
**CUANDO** se autentica en el bus
**ENTONCES** recibe la plantilla `docs` y puede suscribirse con queue group a `{instance}.*.jiku-docs-commands.v1.>` y `.jiku-docs-queries.v1.>`, publicar en `{instance}.docs-events.v1.>` y `{instance}.*.docs-notify.v1.>`, administrar `JIKU_DOCS_EVENTS`, escribir `$KV.JIKU_MODULES.docs` y llamar a `jiku-queries` / `jiku-commands` de core

### CA-10: Solo su propia clave del registro

**DADO** el mismo machine user
**CUANDO** intenta escribir `$KV.JIKU_MODULES.otro`
**ENTONCES** el bus lo rechaza por permisos

### CA-11: Conectores (RF-7)

**DADO** un usuario con solo `internal-app`
**CUANDO** se autentica
**ENTONCES** recibe la plantilla de conector, que ahora permite publicar comandos y consultas de docs bajo su id, leer/observar el KV y hacer ping, pero no suscribirse a los subjects de servicio de docs ni publicar eventos de docs

### CA-12: Personas internas (RF-8)

**DADO** un usuario `user` (persona interna)
**CUANDO** publica `{instance}.{suId}.jiku-docs-commands.v1.documents.new`
**ENTONCES** el bus lo permite; y cuando publica bajo el id de otra persona, lo rechaza

### CA-13: Personas externas (RF-8)

**DADO** un usuario `external-user`
**CUANDO** publica en `jiku-docs-commands` bajo su id, o se suscribe a `docs-notify`
**ENTONCES** el bus lo rechaza; y cuando publica en `jiku-docs-queries` bajo su id, lo permite

### CA-S1: Ningún otro rol cambia (RF-9)

**DADO** las plantillas de los demás roles
**CUANDO** se comparan con las anteriores a esta story
**ENTONCES** no ganan ningún permiso fuera de los listados, y ninguna plantilla de persona tiene `$JS.API.STREAM.` distinto de `INFO` ni `$KV.`

### Cambios en el bus

**`rules.yaml`:** regla `match: docs` → `templates/docs.yaml`, **arriba** de `internal-app` (gana la primera que coincide).

**`templates/docs.yaml` (nueva)** = permisos de `connector.yaml` más los de servidor:

- pub: `{{instance}}.{{user_id}}.jiku-commands.v1.>`, `{{instance}}.{{user_id}}.jiku-queries.v1.>`, `{{instance}}.docs-events.v1.>`, `{{instance}}.*.docs-notify.v1.>`, `$JS.API.INFO`, `$JS.API.STREAM.*.JIKU_DOCS_EVENTS`, `$KV.JIKU_MODULES.docs`, `$JS.API.STREAM.INFO.KV_JIKU_MODULES`, `$JS.API.DIRECT.GET.KV_JIKU_MODULES.$KV.JIKU_MODULES.docs`
- sub: `{{instance}}.*.jiku-docs-commands.v1.>`, `{{instance}}.*.jiku-docs-queries.v1.>`, `$SRV.>`, `_INBOX.{{user_id_hash}}.>`
- response: `max: 1`, `ttl: 45s`

**`connector.yaml`:** suma pub a `jiku-docs-commands.v1.>` y `jiku-docs-queries.v1.>` bajo su id, `$SRV.PING.>`, las cinco formas de JetStream para consumir `JIKU_DOCS_EVENTS` con durable propio y el bloque `KV_READ_WATCH`.

**`person-internal.yaml`:** pub a comandos y consultas de docs bajo su id + `KV_READ_WATCH`; sub a `{{instance}}.{{user_id}}.docs-notify.v1.>`.

**`person-external.yaml`:** pub solo a `jiku-docs-queries.v1.>` bajo su id + `KV_READ_WATCH`. Sin notificaciones ni comandos.

**`KV_READ_WATCH`** (idéntico en las tres): `$JS.API.INFO`, `$JS.API.STREAM.INFO.KV_JIKU_MODULES`, `$JS.API.DIRECT.GET.KV_JIKU_MODULES.>`, `$JS.API.CONSUMER.CREATE.KV_JIKU_MODULES.>`, `$JS.FC.KV_JIKU_MODULES.>`.

> **La lista exacta del watch se fija en esta story contra los dos clientes reales** (nats.js 2.29 de la api y el cliente Go de jiku-docs/jiku-go), con el método que S-067 usó para `JIKU_EVENTS`: un consumidor que arranca y observa una escritura, mirando el log del servidor NATS. Un `allow` incompleto no falla en la llamada: sale como violación en el log (README del callout, "Los modos de fallo").

**`deploy/nats/create-modules-kv.sh` (nuevo):** copia el patrón de `create-events-stream.sh` (usuario administrativo descartable, comparación contra el contrato, `--force`). Bucket `JIKU_MODULES` con `history: 1`, sin TTL, `allow_direct: true`, `storage: file`, `replicas: 1`. Si existe con esos parámetros no hace nada; si difiere falla salvo `--force`. `local.sh up` lo invoca después de que NATS responde (a diferencia del stream de eventos, que solo se avisa).

### Flujo de Interacción

#### Escenario: arranque del stack local (CA-1)

**Trigger:** `deploy/local.sh up`

1. **[local.sh]** espera a NATS y ejecuta `create-modules-kv.sh`.
2. **[create-modules-kv.sh]** inspecciona `JIKU_MODULES`; lo crea si no existe, no hace nada si coincide, falla si difiere (sin `--force`).

**Outcome:** el bucket existe una sola vez con los parámetros del contrato.

**Manejo de errores:**
- Bucket existente con otros parámetros → falla con el diff, salvo `--force`.
- NATS no responde → `local.sh` no continúa.

### Consideraciones Técnicas

**Seguridad:**
- **R-1:** si `docs` queda debajo de `internal-app`, el machine user cae en la plantilla de conector y reinicia en loop al suscribirse a sus subjects de servicio. Test estructural que parsea `rules.yaml` y exige `docs` antes de `internal-app` (patrón de `core/tests/bus/events-structure.test.ts`).
- **R-3:** ampliar `connector.yaml` amplía a **todos** los `internal-app` (jiku-docs los trata como clase `service`). Aceptado en D-2; se documenta en el README del callout ("Mirá el tamaño de lo que concede").
- **R-4:** las personas reciben por primera vez permisos de JetStream, acotados al stream del KV y sin mutación; test estructural que lo verifica.
- Las plantillas siguen siendo **literales** (`jiku-docs-*`): registrar un módulo con otro `serviceName` es un cambio de seguridad deliberado (H-2). No se generaliza a `{{instance}}.{{user_id}}.*.v1.>`.
- Lo que ninguna plantilla gana: `$JS.API.>` entero, `$KV.JIKU_MODULES.>`, consumir `JIKU_DOCS_EVENTS` para personas.

**Performance:**
- Sin impacto.
