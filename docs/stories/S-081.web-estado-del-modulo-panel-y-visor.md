# S-081: web: estado del módulo, panel y visor

**Status:** Completed
**Created:** 2026-10-24
**Source:** REQ-016

## Historia de Usuario

**Como** persona del equipo que usa la web de Jiku,
**quiero** ver los documentos vinculados en las fichas de proyecto, requisito y tarea y leerlos en un visor seguro,
**para** consultar la documentación sin salir de Jiku, y no ver nada de esto si la instalación no tiene el módulo.

## Criterios de Aceptación

### CA-25: Sin módulo, sin documentación

**DADO** el módulo `not_installed`
**CUANDO** una persona interna abre la ficha de un proyecto
**ENTONCES** no hay panel ni menú de documentación

### CA-26: Panel con documentos

**DADO** el módulo `available` y documentos vinculados al proyecto 12
**CUANDO** abre la ficha del proyecto 12
**ENTONCES** ve el panel con título, ruta y fecha de actualización de cada documento, y puede abrirlo en el visor

### CA-27: Módulo caído

**DADO** el módulo `unavailable`
**CUANDO** abre la ficha
**ENTONCES** ve el panel con un aviso de "documentación no disponible" y sin acciones habilitadas

### CA-28: Markdown seguro

**DADO** un documento con `<script>` o `javascript:` en su markdown
**CUANDO** se muestra en el visor
**ENTONCES** no se ejecuta ningún script ni queda ningún enlace `javascript:`

### CA-33: Imágenes adjuntas

**DADO** un documento cuyo markdown contiene `/docs/attachments/01J…` o `{JIKU_WEB_URL}/docs/attachments/01J…`
**CUANDO** se abre en el navegador
**ENTONCES** la imagen carga a través de la web (sesión → api → 302)

### CA-S11: Consulta periódica del estado (RF-17)

**DADO** la web abierta
**CUANDO** inicia, pasan 60 s o una llamada devuelve `module_unavailable`
**ENTONCES** consulta `GET /modules` y actualiza lo que muestra sin recargar

## Diseño Técnico

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|
| web | Alto | Módulo `features/docs/` (servicios, tipos verbatim de `jiku-docs-queries.yaml`, `useModule('docs')` con `refetchInterval: 60_000`); card "Documentación" en `detalle-proyecto`, `detalle-requisito` y `detalle-tarea`; página `/docs/[id]` en modo lectura; visor markdown con reescritura de adjuntos; route handler `src/app/docs/attachments/[id]/route.ts`; ítem "Documentación" en la sidebar, condicional | Done |

### Cambios de API

#### Endpoints Existentes a Modificar

Ninguno.

#### Nuevos Endpoints

Ninguno propio: consume `GET /modules`, `GET /docs/documents`, `GET /docs/documents/{id}` y `GET /docs/attachments/{id}` (S-077, S-078).

**Route handler de la web** `GET /docs/attachments/{id}` (fuera de `(loggedin)`): `decodedToken()`; sin sesión → 401; `fetch(API_URL + 'api/docs/attachments/{id}', { redirect: 'manual', Bearer })` y propaga el 302 sin cuerpo (patrón de `web/src/app/api/attachments/[id]/download/route.ts`).

### Cambios de Base de Datos

Ninguno.

### Diseño de UI (de la Revisión UX del REQ)

Pantallas (viewport desktop, único en `web`):

- **Modificar `detalle-proyecto`:** card **"Documentación"** en la columna derecha, entre Propiedades y Archivos Adjuntos: tabla Documento · Ruta · Actualizado, marca "En edición", vacío, carga propia, aviso de módulo caído, "Ver más". Lista, no crea.
- **Modificar `detalle-requisito`:** la misma card, cuarta en la columna derecha (entre Etiquetas y Resolución), filtrada por `requirementId`.
- **Modificar `detalle-tarea`:** la misma card, entre la tarjeta de detalle y el historial, filtrada por `taskId`.
- **Agregar `documento` (`/docs/[id]`), parte de lectura:** visor markdown, badge de visibilidad, adjuntos; sub-estado *módulo no disponible*. (El editor y sus sub-estados son de S-082; "Compartir" es de S-083.)
- **Shell:** ítem **"Documentación"** en la sidebar, condicional al módulo.

Regla transversal: con `not_installed` no aparece nada (ni ítem, ni card; las rutas nuevas responden 404); con `unavailable` todo aparece con el aviso `"La documentación no está disponible en este momento. Probá de nuevo en unos minutos."` y las acciones deshabilitadas. Las cards con módulo `available` y sin documentos se muestran vacías con su mensaje.

Design System (`web` v4.2.0): `Card` `panel`, `Table` `light`, `Badge`, `EmptyState`, `Loader`, `Button` "Ver más" (paginación por cursor). El markdown se renderiza con el `MarkdownViewer` existente. **El aviso inline no tiene componente (gap `alert` anotado):** se implementa con `role="alert"` y los tokens de estado del DS; si antes de planificar esta story se crea el componente con `/product-design-system-update`, se usa directamente.

### Flujo de Interacción

#### Escenario: panel en la ficha de proyecto (CA-25 a CA-27)

**Trigger:** una persona interna abre `/projects/12`.

1. **[web — `useModule('docs')`]** `GET /modules` (Server Action + TanStack Query, `refetchInterval: 60_000`, invalidado ante `module_unavailable`). `not_installed` → no se monta panel ni ítem.
2. **[web — `DocsPanel`]** `available` → Server Action `listDocuments({ projectId: 12 })` → `GET /api/docs/documents?projectId=12`.
3. **[web]** panel con título, ruta y fecha; cada fila abre `/docs/{id}`.

**Outcome:** documentos vinculados que la persona puede leer.

**Manejo de errores:**
- `unavailable` → panel visible con aviso y acciones deshabilitadas; `upstream_unavailable` → 503 con el mensaje de jiku-docs.

#### Escenario: imagen adjunta en el markdown (CA-33)

1. **[web — visor]** `urlTransform` reescribe todo `src`/`href` cuyo path sea `/docs/attachments/{ULID}` (relativo o absoluto, **sin mirar el host**, DD-15) al `/docs/attachments/{id}` del propio origen; deja pasar solo `http(s)`, `mailto` y esos paths (CA-28).
2. **[web — route handler]** pide a la api con la sesión y propaga el 302.
3. **[navegador]** descarga de S3.

**Outcome:** la imagen carga con la identidad de quien mira.

### Consideraciones Técnicas

**Seguridad:**
- `react-markdown` sin `rehype-raw`; `urlTransform` bloquea `javascript:`.
- `/docs/attachments/[id]` vive fuera de `(loggedin)/` y no tiene guard: valida la sesión por sí mismo (corolario del overview de `web`).

**Performance:**
- El panel carga por separado y no demora la ficha.

**Dependencias:**
- **R-6:** `app/docs/attachments/[id]/route.ts` convive con `app/(loggedin)/docs/[id]/page.tsx`; `/docs/attachments` sin id caería en la página. Test de ruteo en esta story.
- **R-8:** los tipos de docs se escriben a mano verbatim de `jiku-docs-queries.yaml` y se citan en el archivo de tipos.
