# S-094: api: rutas de documentación para jiku-docs 1.3.0

**Status:** Completed
**Created:** 2026-10-26
**Source:** REQ-021

## Historia de Usuario

**Como** web interna (y, por extensión, la persona que usa Documentación),
**quiero** que la api exponga los filtros, las relaciones, las sugerencias y los nombres que trae el contrato 1.3.0 de jiku-docs, sin carpetas,
**para** construir la Documentación sin carpetas (propuesta B) sin que la web hable con jiku-docs ni con core.

## Criterios de Aceptación

### CA-1: Filtros nuevos y listas en el listado

**DADO** una persona interna que pide `GET /docs/documents` con `projectId` repetido, `clientId`, `topic`, `hasProject`, `hasClient`, `hasTopic`, `person`, `visibility` o `count=true`
**CUANDO** la api arma la consulta `documents.list`
**ENTONCES** traduce cada parámetro a su `filter` del contrato (listas = O dentro de un tipo, tipos distintos = Y; `person` = `filter.or` de `createdBy`/`updatedBy`), pide `include: ['lock','topics']` y devuelve `page.total` cuando hay `count`

### CA-2: "Mis proyectos activos"

**DADO** `myActiveProjects=true`
**CUANDO** la persona participa en proyectos con `status = 'activo'`
**ENTONCES** la api los resuelve desde la base (hasta 200) y los manda como `filter.projectId`; sin proyectos responde `{ items: [], page: { limit, returned: 0 } }` sin llamar al bus; combinado con `projectId` responde 400 `invalid_fields`

### CA-3: Búsqueda con los mismos filtros

**DADO** `GET /docs/search` con `q` y los filtros nuevos
**CUANDO** se ejecuta
**ENTONCES** se traducen igual que en el listado, el hit trae `createdBy`, `createdByName`, `updatedByName`, `visibility`, `clients`, `projects`, `projectMatch`, `clientRefs` y `projectRefs`

### CA-4: Nombres de relaciones desde la base

**DADO** un listado, una búsqueda o un detalle de documento
**CUANDO** la respuesta trae ids de clientes, proyectos, requisitos o tareas
**ENTONCES** la api agrega `clientRefs`, `projectRefs` (y en el detalle `requirementRefs`, `taskRefs`) resueltos con una consulta `IN` por tipo y por respuesta; un id desconocido va con `name`/`title` en `null`; los campos de jiku-docs no se modifican

### CA-5: Detalle sin carpeta

**DADO** `GET /docs/documents/{id}`
**CUANDO** se responde
**ENTONCES** ya no se consulta `folders.get` ni se devuelve `folder`; pasan sin transformar `prunedVersionsCount`, `createdByName`, `updatedByName` y `lock.holderName`; con una versión compactada responde 404 `version_pruned` conservando `details`

### CA-6: Alta sin carpeta

**DADO** `POST /docs/documents` sin `folderId` ni `fileName`
**CUANDO** se crea el documento
**ENTONCES** la api llama a `documents.new` sin esos campos y la respuesta incluye `folderId` y `fileName`; un `user` que manda `visibility: restricted` recibe el `permission_denied` del servicio

### CA-7: Asignar relaciones

**DADO** `POST /docs/documents/{id}/relations` con `baseVersion` y `add`/`remove`
**CUANDO** se ejecuta
**ENTONCES** llama a `documents.{id}.relations.update` y devuelve `DocsRelationsResult`; `version_conflict` y `document_locked` salen como 409, `invalid_relation`/`invalid_fields`/`frontmatter_invalid` como 400, `permission_denied` 403, `document_not_found` 404 (un `id` mal formado responde 404 sin bus)

### CA-8: Relaciones sugeridas

**DADO** `GET /docs/documents/{id}/suggested-relations`
**CUANDO** se ejecuta
**ENTONCES** llama a `documents.suggest-relations` y devuelve `items` con `projectId`, `clientId`, `score`, `reason`, `projectName`, `projectCode` y `clientName` resueltos de la base

### CA-9: Sugerencias del buscador

**DADO** `GET /docs/suggestions?q=vid&clientId=4`
**CUANDO** se ejecuta
**ENTONCES** devuelve `projects` (los activos de la persona primero con `mine: true`, limitados al cliente), `clients`, `persons` (de `people` habilitadas con `user_id`) y `topics` (de `topics.list` por prefijo, con conteo), con tope por grupo (1..10, por defecto 5)

### CA-10: Portal sin ruta

**DADO** `GET /opus/docs/documents` y su detalle
**CUANDO** la api pide los campos a jiku-docs
**ENTONCES** `fields` no incluye `path`, `folderId` ni `fileName`

### CA-11: Actor completo y autenticación intacta

**DADO** cualquier ruta nueva o modificada hacia jiku-docs
**CUANDO** se llama
**ENTONCES** el payload lleva el `actor` completo de `buildActor` (D-11), y `validateToken`, `config/public.ts` y `getRolesFromToken` no cambian

### CA-12: Contratos y documentación al día

**DADO** el cierre de la story
**CUANDO** se revisa `docs/apis/api.yaml`, el ADR-015 y los flujos
**ENTONCES** reflejan las rutas, esquemas y errores nuevos, la revisión de la composición `folder` por las referencias con nombre, y el flujo `buscador-de-documentacion`

## Technical Design

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|
| api | Alto | Filtros y listas en listado y búsqueda, `count`, `myActiveProjects`, alta sin carpeta, rutas `relations`, `suggested-relations` y `suggestions`, helper `lib/modules/docs/relation-refs.ts`, detalle sin `folder`, mapa de errores, portal sin ruta | Done |
| jiku-docs | Ninguno | Ya desplegado en 1.3.0 (requisito de instalación: ≥ 1.3.0) | - |
| core | Ninguno | Se lee su modelo desde la base, como siempre | - |

### Cambios de API

Todas las rutas siguen la cadena `requireModule('docs') → hasAnyRole(['admin','user']) → Joi → handler`, con `moduleQuery`/`moduleCommand` y el `actor` completo. La api sigue sin autorizar el dominio (DD-2).

#### Composición de nombres (reemplaza la composición `folder`)

| Campo agregado | Dónde | Origen | Forma |
|---|---|---|---|
| `clientRefs` | ítems de `GET /docs/documents`, `GET /docs/search` y `GET /docs/documents/{id}` | tabla `clients` | `[{ id, name \| null }]` |
| `projectRefs` | ídem | tabla `projects` | `[{ id, name \| null, code \| null, clientId \| null }]` |
| `requirementRefs` | solo detalle | `requirements` | `[{ id, title \| null, projectId \| null }]` |
| `taskRefs` | solo detalle | `objectives` | `[{ id, title \| null, projectId \| null }]` |

Se resuelven en lote (una consulta `IN` por tipo por respuesta), respetando el orden de jiku-docs.

#### Endpoints Existentes a Modificar

**`GET /docs/documents`** (ref: `docs/apis/api.yaml`:2127)
- `projectId`, `clientId`, `topic`: entero/valor o lista (hasta 20). Mismo tipo repetido = O; tipos distintos = Y.
- Nuevos: `hasProject`, `hasClient`, `hasTopic`, `person` (repetible hasta 10, `sub`), `visibility` (`internal|public|restricted`), `myActiveProjects` (excluyente con `projectId`), `count`.
- `include: ['lock','topics']`. `folderId` y `pathPrefix` se conservan sin uso en la web.
- Response: ítems con `clientRefs`, `projectRefs` y los campos 1.3.0 sin transformar.
- **Justificación:** RF 2, 5, 6, 7, 8, 16, 17.

**`GET /docs/search`** (ref: `docs/apis/api.yaml`:2322)
- Nuevos: `clientId`, `hasProject`, `hasClient`, `hasTopic`, `person`, `visibility`; `projectId`, `clientId`, `topic` admiten listas. `limit` hasta 50, sin cursor.
- **Justificación:** RF 2, 6.

**`GET /docs/documents/{id}`** (ref: `docs/apis/api.yaml`:2202)
- Eliminado: `folders.get` y el campo `folder`. **Cambio incompatible del contrato HTTP** (único consumidor: web, se publica junto; va al CHANGELOG).
- Nuevos: `clientRefs`, `projectRefs`, `requirementRefs`, `taskRefs`.
- **Justificación:** RF 11, 14, 15.

**`POST /docs/documents`** (ref: `docs/apis/api.yaml`:2162)
- `folderId` y `fileName` pasan a opcionales; `DocsWriteResult` suma `folderId` y `fileName`. Visibilidad, título, temas y relaciones viajan en el frontmatter de `content`.
- **Justificación:** RF 9, 10.

**`GET /docs/documents/{id}/versions`** (ref: `docs/apis/api.yaml`:2296)
- `DocsVersion` suma `authorName`, `kind` (`create|update|restore`) y `protected`, sin transformar.

**`PUT /docs/documents/{id}`, `POST .../lock`, `POST .../restore`, `GET /docs/topics`**
- Sin cambios de forma. El 409 `document_locked` trae `details.holderName` (pasa verbatim). `restore` puede responder `version_pruned`.

**`GET /opus/docs/documents` y `GET /opus/docs/documents/{id}`** (ref: `docs/apis/api.yaml`:3245, 3279)
- `fields` explícitos sin `path`, `folderId` ni `fileName`; la descripción deja de mencionar `externalBlocked`.
- **Justificación:** RF 19.

**Mapa de errores** (`api/lib/modules/docs/errors.ts`): `version_pruned: 404` (conserva `details`).

**Esquemas** (`docs/apis/api.yaml`:3850-4078): `DocsDocument` (+ `restricted`, `createdByName`, `updatedByName`, `clients`, `projects`, `projectMatch`, `prunedVersionsCount`, `lock.holderName`, `clientRefs`, `projectRefs`); `DocsDocumentDetail` (− `folder`, + `requirementRefs`, `taskRefs`); `DocsVersion`; `DocsSearchHit`; `DocsShare.revokeReason` (+ `restricted`); `DocsWriteResult`; nuevos `DocsRelationsResult`, `DocsRelationSuggestions`, `DocsSearchSuggestions`.

#### Nuevos Endpoints

**`POST /docs/documents/{id}/relations`**
- **Servicio:** api → comando `documents.{id}.relations.update`
- **Descripción:** agrega o quita relaciones sin tocar el contenido fuera del bloque `jiku:`.
- **Request** (Joi `strict`, al menos uno de `add`/`remove`):
  ```json
  {
    "baseVersion": "integer >= 1, requerido",
    "add": { "clients": [1], "projects": [12], "requirements": [], "tasks": [] },
    "remove": { "projects": [31] },
    "sessionId": "ULID, opcional"
  }
  ```
- **Response 200:** `{ id, version, relations: { clients, projects, requirements, tasks }, warnings? }`
- **Errores:** 409 `version_conflict` / `document_locked`; 400 `invalid_relation` / `invalid_fields` / `frontmatter_invalid`; 403 `permission_denied`; 404 `document_not_found`.

**`GET /docs/documents/{id}/suggested-relations`**
- **Servicio:** api → consulta `documents.suggest-relations { id }`
- **Response 200:**
  ```json
  {
    "items": [
      { "projectId": "integer | null", "clientId": "integer | null", "score": "number 0..1",
        "reason": "string", "projectName": "string | null", "projectCode": "string | null", "clientName": "string | null" }
    ]
  }
  ```

**`GET /docs/suggestions`**
- **Servicio:** api (base + consulta `topics.list`)
- **Query:** `q` (1..100, requerido), `clientId` (opcional), `limit` (1..10, default 5).
- **Response 200:**
  ```json
  {
    "projects": [{ "id": 12, "name": "Videoconferencia", "code": "VID", "clientId": 4, "clientName": "EXO", "mine": true }],
    "clients": [{ "id": 4, "name": "EXO" }],
    "persons": [{ "userId": "sub", "name": "Ana Pérez" }],
    "topics": [{ "topic": "video", "documents": 7 }]
  }
  ```
- **Reglas:** proyectos por `name`/`code` `ILIKE`, primero los activos de la persona, luego activos, luego el resto; clientes por nombre; personas habilitadas por nombre y apellido; temas por `topics.list` con `filter.prefix` (solo prefijo). "Buscar «q»" y "Sin proyecto/cliente/tema" los arma la web.

### Cambios de Base de Datos

Ninguno. La api solo **lee** `projects`, `clients`, `people`, `projects_persons`, `requirements` y `objectives` (ref: `docs/db-schemas/jiku.md`) con su rol de solo lectura.

### Flujo de Interacción

#### Escenario: sugerencias del buscador con filtro de cliente

**Trigger:** la web pide `GET /docs/suggestions?q=vid&clientId=4`.

1. **[api — `docs-suggestions-get.ts`]**
   - Cadena `requireModule → hasAnyRole → Joi`.
   - DB: proyectos del cliente 4 que coinciden (los de la persona primero), clientes y personas.
   - Bus: `topics.list { filter: { prefix: 'vid' }, page: { limit: 5 }, actor }`.
   - Output: `200 { projects, clients, persons, topics }`.

**Outcome:** grupos de sugerencias con tope por grupo.

**Manejo de errores:** módulo no instalado → 404 `module_not_installed`; módulo caído → 503.

#### Escenario: asignar proyecto

**Trigger:** la web llama a `POST /docs/documents/{id}/relations { baseVersion, add: { projects: [12] } }`.

1. **[api]** comando `documents.{id}.relations.update { baseVersion, add, actor }`; jiku-docs reescribe solo `jiku:`, agrega el cliente del proyecto y crea la versión.
2. **[api]** responde `200 { id, version, relations }`.

**Manejo de errores:** `version_conflict` → 409; `document_locked` → 409 con `details.holderName`; `invalid_relation` → 400.

### Flujos Afectados

- **documentos-desde-la-web** (ref: docs/flows/documentos-desde-la-web.md) — composición `folder` reemplazada por referencias con nombre; filtros nuevos; alta sin carpeta; `message`; historial; portal con `fields` sin ruta; errores `version_pruned` y `sharing_blocked` por `restricted`.
- **lectura-por-link-compartido** (ref: docs/flows/lectura-por-link-compartido.md) — un `restricted` no admite links; `revokeReason: restricted`; `shares.resolve` responde `share_not_found`.
- **buscador-de-documentacion** (ref: docs/flows/buscador-de-documentacion.md) — flujo nuevo: sugerencias, resultados filtrados, "Sin proyecto" con asignar/sugerido.

### Consideraciones Técnicas

**Seguridad:**
- Sin cambios de autenticación; tests que verifican el `actor` completo en cada payload.
- `/docs/suggestions` solo para `admin`/`user`; expone nombres que una persona interna ya ve en el resto de la web.
- "Restringido" lo decide jiku-docs (`permission_denied`); la api no valida.

**Performance:**
- Hasta 4 consultas `IN` por respuesta, por PK; nunca una por ítem.
- `myActiveProjects`: un `JOIN` `people`–`projects_persons`–`projects` por pedido.
- `count: true` solo cuando se pide.

**Dependencias:**
- jiku-docs ≥ 1.3.0 (una versión anterior responde `invalid_fields` a los filtros y exige `folderId`). Se anota en "Notes for existing installations" del CHANGELOG; sin chequeo en runtime.
- Revisión de ADR-015 (sección "Revisión") por la composición nueva.
