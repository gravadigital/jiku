# S-087: El adjunto del portal solo de documentos públicos

**Status:** Ready
**Created:** 2026-10-24
**Source:** REQ-017

## Historia de Usuario

**Como** responsable de la seguridad de la documentación que se muestra al cliente,
**quiero** que el portal opus-web solo entregue adjuntos que pertenezcan a un documento `public`, sin importar el rol de quien pida,
**para** que un usuario interno que conoce el id de un adjunto de un documento `internal` no pueda descargarlo por el portal.

## Criterios de Aceptación

### CA-1: Adjunto de documento interno

**DADO** un usuario interno (`admin` o `user`) en el portal opus-web
**CUANDO** pide un adjunto de un documento `internal` por la ruta de adjuntos del portal, conociendo su id
**ENTONCES** recibe 404 y no se genera ninguna URL de descarga

### CA-2: Adjunto de documento público

**DADO** un usuario externo con permiso sobre el proyecto
**CUANDO** pide un adjunto de un documento `public` vinculado a su proyecto por el portal
**ENTONCES** recibe la redirección 302 a la descarga, como hoy

### CA-3: Listado y ficha para usuarios internos

**DADO** un usuario interno en el portal
**CUANDO** lista documentos o abre un documento `internal` por `/opus/docs/*`
**ENTONCES** no lo ve en la lista y la ficha responde 404

### CA-4: Visor con adjuntos embebidos

**DADO** el visor del portal con un documento `public` que embebe adjuntos
**CUANDO** se renderiza
**ENTONCES** los adjuntos se ven (las URLs reescritas apuntan a la ruta del portal vigente)

### CA-5: Adjunto de otro documento

**DADO** un documento `public` que enlaza el adjunto de otro documento (aunque ese otro sea `public`)
**CUANDO** se pide por el portal bajo el documento que lo enlaza
**ENTONCES** responde 404 `attachment_not_found` (comportamiento aceptado, sin tratamiento visible)

### Cambios de API

#### Endpoints Existentes a Modificar

**`GET /opus/docs/attachments/{id}`** (ref: `docs/apis/api.yaml`:línea 3298) — **ELIMINADO**
- Reemplazado por la ruta nueva. Se borra `api/lib/routes/opus-docs-attachments-id-get.ts` y su línea del barrel; la petición vieja responde el 404 genérico de Express. La ruta no está en ningún tag (`v1.6.0` es el último), reemplazarla no rompe un contrato publicado.

**`GET /opus/docs/documents`** y **`GET /opus/docs/documents/{id}`** (ref: `docs/apis/api.yaml`:líneas 3237 y 3271)
- **Cambio:** ninguno de comportamiento (ya fuerzan `public` para todo rol). Se agregan tests con token `admin` y `user`: el primero verifica que el payload a `documents.list` lleva `visibility: 'public'`; el segundo, que un documento `internal` responde 404 `document_not_found`.

#### Nuevos Endpoints

**`GET /opus/docs/documents/{documentId}/attachments/{id}`**
- **Servicio:** api (`api/lib/routes/opus-docs-documents-id-attachments-id-get.ts`)
- **Cadena:** `requireModule('docs')` -> `hasAnyRole(['external-user', 'admin', 'user'])` -> handler (igual que la ruta que reemplaza; mantiene la excepción DD-4 a ADR-006)
- **Descripción:**
  1. `documentId` o `id` sin forma ULID -> 404 (`document_not_found` / `attachment_not_found`) sin bus.
  2. `documents.get { id: documentId, include: ['attachments'] }` como `actor`. Error del módulo -> el mapa de siempre (`docsHttpStatusFor`).
  3. `visibility !== 'public'` (o ausente) -> 404 `document_not_found`, para todo rol.
  4. `attachments` sin un elemento con `id === id` -> 404 `attachment_not_found`.
  5. `attachments.{id}.request-download` -> `redirectToModuleDownload` (302, `Location`, `X-Content-Type-Options: nosniff`; la URL nunca se loguea).
- **Request:** sin cuerpo. Path: `documentId` (ULID), `id` (ULID).
- **Response:** `302`; `401, 403, 404, 500, 503, 504` con las mismas `$ref` (`Unauthorized`, `ModuleForbidden`, `ModuleNotFound`, `InternalError`, `ModuleUnavailable`, `ModuleGatewayTimeout`).
- **Errores:** nunca 403 por visibilidad: el portal no revela que existe un documento interno.

#### opus-web (route handler, no es API pública)

- `opus-web/src/app/api/docs/attachments/[id]/route.ts` **ELIMINADO** -> `opus-web/src/app/api/docs/documents/[documentId]/attachments/[id]/route.ts` **NUEVO**: mismo comportamiento (sesión, `ULID_PATTERN` sobre los dos ids, `redirect: 'manual'`, 302 propagado, 401 `{code, message}`), apuntando a `api/opus/docs/documents/{documentId}/attachments/{id}`.
- `docsUrlTransform(url)` -> `docsUrlTransform(documentId)(url)` (o `createDocsUrlTransform`): el enlace `/docs/attachments/{ULID}` se reescribe a `/api/docs/documents/{documentId}/attachments/{ULID}`. `DocumentMarkdown` recibe `documentId` y `DocumentView` se lo pasa (`doc.id`).
- `DocumentAttachments`: `href` = `/api/docs/documents/${attachment.documentId}/attachments/${attachment.id}`; si faltara `documentId`, usa el id del documento abierto (prop).

### Flujo de Interacción

#### Escenario: adjunto desde el portal (CA-1, CA-2, CA-4)

**Trigger:** el visor del portal renderiza un documento `public` con un enlace `/docs/attachments/{attId}`, o el usuario hace click en la lista de adjuntos.

**Flujo:**

1. **[opus-web — visor]**
   - Acción: `docsUrlTransform(doc.id)` reescribe el enlace
   - Output: `/api/docs/documents/{docId}/attachments/{attId}`

2. **[opus-web — route handler]**
   - Acción: valida sesión y los dos ULID
   - Output: `GET {API_URL}/api/opus/docs/documents/{docId}/attachments/{attId}` con `Authorization: Bearer <token>` y `redirect: 'manual'`

3. **[api]**
   - Acción: `requireModule('docs')` -> `hasAnyRole` -> `documents.get { id: docId, include: ['attachments'] }`
   - Output: `visibility !== 'public'` -> 404 `document_not_found`; `attId` ausente en `attachments[].id` -> 404 `attachment_not_found`; OK -> `request-download` -> 302 `Location`

4. **[opus-web — route handler]**
   - Acción: propaga el 302; el navegador baja del storage

**Outcome:** solo se descargan adjuntos de documentos `public` que pertenecen al documento pedido.

**Manejo de errores:**
- Módulo no instalado -> 404 `module_not_installed`; no disponible -> 503; timeout -> 504
- `external-user` sin acceso en jiku-docs -> `document_not_found` / `permission_denied` traducido por el mapa (sin cambio)

### Consideraciones Técnicas

**Seguridad:**
- Cierra F-13: ningún rol obtiene por el portal un adjunto que no pertenezca a un documento `public`. El 404 no distingue "documento interno" de "inexistente".
- R-3: un documento `public` que enlaza el adjunto de otro deja de mostrarlo; se registra en `documentation/known-limitations.md`.

**Performance:**
- Suma un round-trip a jiku-docs (`documents.get`) antes del `request-download`; es la misma consulta que ya hace el visor, despreciable frente a la descarga.

**Dependencias:**
- Independiente de S-086. S-088 depende de esta: el conteo final y las filas de `api-reference.md` dependen de la ruta que quede.
