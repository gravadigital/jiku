# S-083: web: compartir

**Status:** Ready
**Created:** 2026-10-24
**Source:** REQ-016

## Historia de Usuario

**Como** persona con permiso de administración sobre un documento,
**quiero** crear, listar y revocar links públicos de solo lectura,
**para** compartir documentación con alguien de afuera sin darle una cuenta.

## Criterios de Aceptación

### CA-31: Crear un link y verlo una sola vez

**DADO** que la persona tiene `manage` y la función de compartir está configurada
**CUANDO** crea un link de 15 días
**ENTONCES** ve la URL una sola vez con "Copiar"; al cerrar el diálogo el link aparece en la lista sin URL, y puede revocarlo

### CA-32: Compartir oculto si no está configurado

**DADO** que la api no tiene `JIKU_PUBLIC_URL`
**CUANDO** se abre un documento
**ENTONCES** el botón "Compartir" no aparece

### CA-S16: Solo con `manage`

**DADO** que la persona solo tiene `write` sobre la carpeta del documento
**CUANDO** abre el documento
**ENTONCES** el botón "Compartir" no se habilita

### CA-S17: Posible secreto

**DADO** un documento con alerta de posible secreto
**CUANDO** la persona intenta crear un link y jiku-docs responde `secret_warning_not_acknowledged`
**ENTONCES** la web pide confirmación explícita con un botón distinto ("Compartir igual") y reenvía con `acknowledgeSecretWarning: true`

### CA-S18: Lista de links

**DADO** links existentes de un documento
**CUANDO** se abre la lista
**ENTONCES** se ve estado, vencimiento, nota, accesos y último acceso, nunca el token

## Diseño Técnico

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|
| web | Medio | Botón "Compartir" en `documento`, condicionado a `features.sharing` (de `GET /modules`) y `folder.effectivePermission === 'manage'`; overlay O-12 Compartir documento; Server Actions de crear, listar y revocar | Pending |

### Cambios de API

#### Endpoints Existentes a Modificar

Ninguno.

#### Nuevos Endpoints

Consume `GET /docs/documents/{id}/shares`, `POST /docs/documents/{id}/shares` y `DELETE /docs/shares/{id}` (S-079), y `features.sharing` de `GET /modules` (S-077). El `POST` responde `201 { id, token, url, expiresAt }` y 404 `sharing_not_configured` sin `JIKU_PUBLIC_URL`.

### Cambios de Base de Datos

Ninguno.

### Diseño de UI (de la Revisión UX del REQ)

- **Overlay O-12 Compartir documento** (modal, abierto desde `boton-compartir` de `documento`): vencimiento (7/15/30/90/180 días, default 30, máximo 180), nota, adjuntos sí/no (`ToggleGroup` segmentado "Incluir adjuntos" / "Solo el texto"); link mostrado **una sola vez** con "Copiar" y la advertencia de que no se podrá volver a ver; lista sin URL; revocar; confirmación de posible secreto como botón distinto ("Compartir igual"). Mensaje de error con `role="alert"`.
- **Overlay O-02 Confirmación de borrado:** nuevo trigger "revocar un link" en O-12.
- Design System: `Select` (vencimiento), `Input`, `ToggleGroup`, `Table`/`Badge` (lista), `Button`. El modal reutiliza el armazón de `ConfirmDialog` (gap `modal` anotado).

### Flujo de Interacción

#### Escenario: crear y revocar un link (CA-31, CA-32)

**Trigger:** la persona pulsa "Compartir" en `/docs/{id}`.

1. **[web]** el botón solo está visible si `features.sharing` y `effectivePermission === 'manage'`.
2. **[web → api]** `POST /api/docs/documents/{id}/shares { mode: "latest", expiresAt, includeAttachments, note }`.
   - `secret_warning_not_acknowledged` → confirmación explícita y reenvío con `acknowledgeSecretWarning: true`.
3. **[web]** muestra `url` una sola vez con "Copiar"; al cerrar, la lista (`GET …/shares`) lo muestra sin token.
4. **[web]** "Revocar" → confirmación → `DELETE /api/docs/shares/{id}`.

**Outcome:** el link funciona hasta que vence o se revoca (se sirve con S-080).

**Manejo de errores:**
- `sharing_blocked` / `permission_denied` → aviso en el diálogo.
- `sharing_not_configured` → no debería ocurrir con el botón oculto; se muestra error genérico.

### Flujos Afectados

- **lectura-por-link-compartido** (ref: docs/flows/lectura-por-link-compartido.md) — Flujo nuevo, tramo de creación (S-085).

### Consideraciones Técnicas

**Seguridad:**
- El token y la URL no se guardan en el cliente más allá del diálogo, ni se loguean.
- La lista nunca recibe ni muestra el token.

**Performance:**
- Sin consideraciones especiales.

**Dependencias:**
- Depende de que la api tenga `JIKU_PUBLIC_URL` (DD-13, DD-14).
