# S-090: Portal: enlaces entre documentos como texto y aviso sin acceso

**Status:** Ready
**Created:** 2026-10-25
**Source:** REQ-019

## Historia de Usuario

**Como** usuario externo que lee la documentación de su proyecto en el portal opus-web,
**quiero** que los enlaces a otros documentos se vean como texto (sin apuntar a la web interna) y que, si no tengo acceso, se me diga eso y no que el módulo está caído,
**para** no ver links a una web que no puedo usar y entender si debo pedir acceso o esperar a que el servicio vuelva.

## Criterios de Aceptación

### CA-1: Enlace absoluto a otro documento

**DADO** un documento abierto en opus-web con un enlace `http://localhost:3000/docs/{ULID}`
**CUANDO** se renderiza
**ENTONCES** se ve el texto del enlace y no hay ningún `<a>` navegable hacia esa URL

### CA-2: Enlace relativo a otro documento

**DADO** un documento con un enlace relativo `/docs/{ULID}` o `/docs/{ULID}#seccion`
**CUANDO** se renderiza en opus-web
**ENTONCES** se muestra como texto

### CA-3: Adjuntos y enlaces externos sin cambios

**DADO** un documento con un adjunto `/docs/attachments/{ULID}`, un enlace `https://ejemplo.com` y un `mailto:`
**CUANDO** se renderiza en opus-web
**ENTONCES** el adjunto sigue reescrito al proxy propio y los otros dos siguen siendo enlaces

### CA-4: Sin acceso a la documentación

**DADO** un externo sin acceso a la documentación del proyecto
**CUANDO** `DocsSection` recibe un 403 o `caller_not_authorized`
**ENTONCES** muestra el mensaje propio "No tenés acceso a la documentación de este proyecto." y no el de "no disponible"

### CA-5: Módulo caído o error de red

**DADO** el módulo caído o un error 5xx o de red
**CUANDO** `DocsSection` carga
**ENTONCES** sigue mostrando el aviso de "no disponible"

### CA-6: Módulo no instalado

**DADO** `module_not_installed`
**CUANDO** `DocsSection` carga
**ENTONCES** no renderiza nada (sin cambios)

## Technical Design

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|
| opus-web | Bajo | `docsUrlTransform` vacía los enlaces `/docs/{ULID}`; `DocumentMarkdown` renderiza texto cuando el `href` queda vacío; `DocsSection` distingue "sin acceso"; constante `MSG_DOCS_FORBIDDEN`; tests (CA-1 a CA-6) | Pending |
| docs | Bajo | `architectures/opus-web/overview.md` e `index.md` (describen `docsUrlTransform` y `DocsSection`); flujo `documentos-desde-la-web` (portal) | Pending |
| web | Ninguno | La web interna sigue enlazando entre documentos | - |

### Cambios de API

Ninguno. El contrato HTTP de la api no cambia; opus-web consume los status y `code` que ya devuelve.

### Cambios de Base de Datos

Ninguno.

### Decisiones de diseño

- **DD-6 — Enlace entre documentos = path `/docs/{ULID}`.** Nueva regex en `docsUrlTransform`, evaluada después de la de adjuntos: `/^(?:https?:\/\/[^/?#\s]+)?\/docs\/([0-9A-HJKMNP-TV-Z]{26})(?:[?#].*)?$/` → devuelve `''`. No se compara con `JIKU_WEB_URL`. Hoy la variante relativa ya se vacía (falla `new URL`), pero `DocumentMarkdown` sigue renderizando un `<a target="_blank">` sin `href`.
- **DD-7 — "Como texto" = sin `<a>`.** El override `a` de `DocumentMarkdown` renderiza un fragmento con los `children` cuando `href` es vacío. Alcanza también a los demás enlaces vaciados (`javascript:`, `data:`, `//host`). El test existente "mal" (`not.toHaveAttribute('href')`) se ajusta a "no hay `<a>`".
- **DD-8 — "Sin acceso" en `DocsSection`.** Con `query.isError`: (1) `code === 'module_not_installed'` → nada; (2) `status === 403` o `code === 'caller_not_authorized'` → `DocsAlert` con `MSG_DOCS_FORBIDDEN`; (3) cualquier otro → `MSG_DOCS_UNAVAILABLE`. `ApiError` ya trae `code` y `status` (`opus-web/src/lib/axios.ts`).
- **DD-9 — El visor del documento no cambia.** `classifyDocumentError` ya trata 403 como `not_found` a propósito (DD-3 de REQ-016).

### Flujo de Interacción

#### Escenario: enlace entre documentos en el visor (CA-1 a CA-3)

**Trigger:** el externo abre un documento del portal que contiene enlaces.

**Flujo:**

1. **[opus-web / `DocumentMarkdown`]**
   - Acción: `urlTransform(url)`: `/docs/attachments/{ULID}` (con o sin host) → `/api/docs/documents/{documentId}/attachments/{ULID}` (sin cambios); `/docs/{ULID}` (con o sin host, con `?`/`#`) → `''` (nuevo); `http(s)`/`mailto` → pasa; resto → `''`
   - Output: URL transformada

2. **[opus-web / override `a`]**
   - Acción: `href` vacío → `<>{children}</>` (nuevo); si no, `<a href target=_blank rel>`
   - Output: texto o enlace

**Outcome:** los enlaces a documentos internos se ven como texto.

#### Escenario: un externo sin acceso abre el tablero (CA-4 a CA-6)

**Trigger:** `DocsSection` carga en el tablero o en el detalle de requisito.

**Flujo:**

1. **[opus-web / `DocsSection`]**
   - Acción: `GET /api/opus/docs/documents` falla
   - Output: `ApiError` con `status` y `code`

2. **[opus-web / `DocsSection`]**
   - Acción: clasifica según DD-8
   - Output: nada, "sin acceso" o "no disponible"

**Manejo de errores:**
- `module_not_installed` → nada
- 403 o `caller_not_authorized` → "No tenés acceso a la documentación de este proyecto."
- Otro error → aviso de "no disponible"

### Flujos Afectados

- **documentos-desde-la-web** (ref: docs/flows/documentos-desde-la-web.md) — portal: `DocsSection` ante 403 o `caller_not_authorized` muestra "sin acceso"; enlaces `/docs/{ULID}` como texto en el visor
