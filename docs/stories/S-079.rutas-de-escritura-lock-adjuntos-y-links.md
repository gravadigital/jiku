# S-079: Rutas de escritura, lock, adjuntos y links

**Status:** Ready
**Created:** 2026-10-24
**Source:** REQ-016

## Historia de Usuario

**Como** frontend de Jiku,
**quiero** rutas HTTP para crear y editar documentos con lock y versión base, subir adjuntos y gestionar links compartidos,
**para** que las personas del equipo mantengan la documentación sin pisar cambios ajenos.

## Criterios de Aceptación

### CA-17: Conflicto de versión

**DADO** un documento en versión 7
**CUANDO** la persona llama `PUT /docs/documents/{id}` con `baseVersion: 6`
**ENTONCES** responde 409 con `code: version_conflict` y `details.currentVersion: 7`

### CA-18: Documento bloqueado

**DADO** un documento con lock de otra sesión
**CUANDO** la persona intenta guardar
**ENTONCES** responde 409 `document_locked` con `details.holder`, `details.via` y `details.expiresAt`

### CA-S6: `PUT` bajo la autenticación global (H-3)

**DADO** un `PUT /docs/documents/{id}` sin token
**CUANDO** llega a la api
**ENTONCES** responde 401 por el `validateToken` global, y `week-assigned-times-put.ts` sigue autenticado sin su `validateToken` propio

### CA-S7: Alta con checksum y ULID generados por la api (DD-8, DD-9)

**DADO** una persona con permiso de escritura
**CUANDO** llama `POST /docs/documents` sin `id`
**ENTONCES** la api genera el ULID, calcula `checksum = "sha256:" + hex(sha256(utf8(content)))`, publica `documents.new` con `via: "human"` y responde `201 { id, version, path, warnings? }`

### CA-S8: Lock idempotente

**DADO** una sesión con lock vigente
**CUANDO** repite `POST /docs/documents/{id}/lock` con el mismo `sessionId`
**ENTONCES** el lock se renueva y responde `200 { id, sessionId, expiresAt }`

### CA-S9: Link compartido, token una sola vez (DD-14)

**DADO** una persona con `manage` y `JIKU_PUBLIC_URL` configurada
**CUANDO** llama `POST /docs/documents/{id}/shares`
**ENTONCES** responde `201 { id, token, url, expiresAt }` (único lugar donde `token`/`url` aparecen, sin loguearlos); y sin `JIKU_PUBLIC_URL` responde 404 `sharing_not_configured`

### Cambios de API

#### Endpoints Existentes a Modificar

**Autenticación global de `PUT`** (ref: `api/config/public.ts:1-6,41-46`, `api/app.ts:32-35`)
- **Cambio:** agregar `put: []` y `app.put(publicPaths('put'), validateToken)`; eliminar el `validateToken` de la cadena de `week-assigned-times-put.ts`.
- **Justificación:** H-3. `config/public.ts` no declara `put`; ADR-008 prohíbe autenticar ruta por ruta.

#### Nuevos Endpoints

Todos: `hasAnyRole(['admin','user'])`, `requireModule('docs')`, `actor: { id: req.user.id }`, `via: "human"` (DD-9).

| # | Ruta | Llama a | Payload |
|---|---|---|---|
| 8 | `POST /docs/documents` | `documents.new` | `{ id, folderId, fileName, content, checksum, via, message? }` |
| 9 | `PUT /docs/documents/{id}` | `documents.{id}.update` | `{ baseVersion, content, checksum, sessionId?, via, message? }` |
| 10 | `POST /docs/documents/{id}/move` | `documents.{id}.move` | `{ baseVersion, folderId?, fileName?, sessionId? }` |
| 11 | `DELETE /docs/documents/{id}?baseVersion=N` | `documents.{id}.delete` | `{ baseVersion }` |
| 12 | `POST /docs/documents/{id}/restore` | `documents.{id}.restore` | `{ fromVersion, baseVersion }` |
| 13 | `POST /docs/documents/{id}/lock` | `documents.{id}.lock` | `{ sessionId, via, ttlSeconds? }` |
| 14 | `POST /docs/documents/{id}/unlock` | `documents.{id}.unlock` | `{ sessionId }` (`force` no se expone) |
| 15 | `POST /docs/attachments` | `attachments.request-upload` | `{ id, documentId, fileName, mimeType, fileSize, checksum }` |
| 16 | `POST /docs/attachments/{id}/confirm` | `attachments.{id}.confirm` | `{}` |
| 18 | `GET /docs/documents/{id}/shares` | `shares.list` | `{ filter: { documentId, status? }, sort: ["-createdAt"], page }` |
| 19 | `POST /docs/documents/{id}/shares` | `shares.new` | `{ id, documentId, mode, version?, expiresAt, includeAttachments?, note?, acknowledgeSecretWarning? }` |
| 20 | `DELETE /docs/shares/{id}` | `shares.{id}.revoke` | `{}` |

Formas de respuesta:
- Ruta 8: body `{ id?, folderId, fileName, content, message? }` → `201 { id, version, path, warnings? }` (`warnings` incluye `possible_secret_detected`, no bloquea).
- Ruta 9: body `{ baseVersion, content, sessionId?, message? }` → `200 { id, version, path?, warnings? }`; errores `409 { code: "version_conflict", message, details: { currentVersion } }` y `409 { code: "document_locked", message, details: { holder, via, expiresAt } }`.
- Ruta 13: `200 { id, sessionId, expiresAt }`.
- Ruta 15: `201 { id, uploadUrl, expiresIn, link }` con `link = {JIKU_WEB_URL}/docs/attachments/{id}` (D-5).
- Ruta 19: `201 { id, token, url, expiresAt }`; 404 `sharing_not_configured` sin `JIKU_PUBLIC_URL`.

El `id` de alta (`documents.new`, `attachments.request-upload`, `shares.new`) lo genera la api con `generateUlid` si el cliente no lo manda. El `checksum` del binario del adjunto lo calcula quien tiene el archivo (el navegador); el `sessionId` lo genera la web (DD-8).

### Cambios de Base de Datos

Ninguno.

### Flujo de Interacción

#### Escenario: guardar un documento (CA-17, CA-18)

**Trigger:** `PUT /api/docs/documents/{id}` con `{ baseVersion: 6, content, sessionId }`.

1. **[api]** `requireModule` → `hasAnyRole` → Joi.
2. **[api]** calcula `checksum` y publica `documents.{id}.update { actor, baseVersion: 6, content, checksum, sessionId, via: "human" }`.
3. **[jiku-docs]** aplica o responde error.
4. **[api]** éxito → `200 { id, version: 7 }`; `version_conflict` → 409 con `details.currentVersion`; `document_locked` → 409 con `details`.

**Outcome:** una versión nueva sin pisar cambios ajenos.

**Manejo de errores:**
- Todos los códigos de S-077 mantienen su `code` y `details`.
- `no responders` → 503 `module_unavailable` + re-ping.

### Consideraciones Técnicas

**Seguridad:**
- La api no decide permisos de documentación (DD-2).
- `token`, `url` de shares y URLs prefirmadas no se loguean.
- `PUT` queda bajo la autenticación global.

**Performance:**
- Timeouts de comandos existentes (`NATS_REQUEST_TIMEOUT_MS` 5 s).

**Dependencias:**
- Depende de S-077.
