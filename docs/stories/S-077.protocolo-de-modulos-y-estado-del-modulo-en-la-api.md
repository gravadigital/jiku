# S-077: Protocolo de módulos y estado del módulo en la api

**Status:** Ready
**Created:** 2026-10-24
**Source:** REQ-016

## Historia de Usuario

**Como** persona que usa Jiku (y como cliente de la api),
**quiero** que la api sepa en todo momento si el módulo de documentación está instalado y disponible,
**para** que las rutas respondan 404 o 503 según corresponda y la interfaz muestre u oculte la documentación sin reiniciar nada.

## Criterios de Aceptación

### CA-2: Sin clave, `not_installed`

**DADO** que no existe la clave `docs` en `JIKU_MODULES`
**CUANDO** una persona autenticada llama `GET /modules`
**ENTONCES** recibe `[{ "module": "docs", "status": "not_installed" }]`

### CA-3: Rutas de docs sin módulo

**DADO** que no existe la clave `docs`
**CUANDO** una persona llama `GET /docs/documents?projectId=12`
**ENTONCES** recibe 404 con `code: module_not_installed`

### CA-4: Protocolo incompatible

**DADO** que la clave `docs` existe con `protocol: v2`
**CUANDO** la api la lee
**ENTONCES** el estado es `not_installed` hacia afuera, se registra un log de error y las rutas responden 404 `module_not_installed`

### CA-5: Módulo caído

**DADO** que la clave `docs` existe con `serviceName: jiku-docs`, `protocol: v1` y nadie responde a `$SRV.PING.jiku-docs-queries`
**CUANDO** una persona llama `GET /docs/documents`
**ENTONCES** recibe 503 `module_unavailable` y `GET /modules` informa `unavailable`

### CA-6: Borrado de la clave en caliente

**DADO** el módulo `available`
**CUANDO** se borra la clave `docs`
**ENTONCES** sin reiniciar la api, `GET /modules` pasa a `not_installed`

### CA-7: Recuperación

**DADO** el módulo `unavailable`
**CUANDO** el servicio vuelve a responder el ping
**ENTONCES** a más tardar en 30 s el estado pasa a `available`

### CA-8: El nombre del servicio sale del registro

**DADO** el módulo registrado con `serviceName: otro-docs`
**CUANDO** la api llama a una consulta de documentación
**ENTONCES** publica en `{instance}.{apiUserId}.otro-docs-queries.v1.{método}` (verificado con el doble del bus; el bus real exige además un cambio deliberado de política, H-2)

### CA-S2: `GET /opus/modules` y `features` (RF-4, DD-13)

**DADO** una persona externa o interna autenticada
**CUANDO** llama `GET /modules` o `GET /opus/modules` con el módulo `available`
**ENTONCES** recibe `[{ module: "docs", status: "available", features: { sharing: <bool> } }]`, donde `sharing` es verdadero solo si la api tiene `JIKU_PUBLIC_URL`

## Diseño Técnico

### Servicios Afectados

| Servicio | Impacto | Cambios Necesarios | Estado |
|----------|---------|-------------------|--------|

### Cambios de API

#### Endpoints Existentes a Modificar

Ninguno.

#### Nuevos Endpoints

**`GET /modules`** y **`GET /opus/modules`**
- **Servicio:** api
- **Descripción:** estado de los módulos opcionales (`opus/modules` existe porque el catch-all de opus-web solo reenvía `/api/opus/*`).
- **Roles:** cualquiera autenticado.
- **Response 200:**
  ```json
  [{ "module": "docs", "status": "not_installed | unavailable | available", "features": { "sharing": true } }]
  ```
  `incompatible` se informa como `not_installed`; `features` se omite con `not_installed`.
- Marcados `x-jiku-module: docs` en `api.yaml`.

**Middleware `requireModule('docs')`:** `not_installed`/`incompatible` → 404 `module_not_installed`; `unavailable` → 503 `module_unavailable`.

### Paquete `@jiku/nats-protocol`

```ts
export const MODULES_BUCKET = 'JIKU_MODULES';   // stream subyacente KV_JIKU_MODULES
export interface ModuleRecord { module: string; serviceName: string; protocol: string; registeredAt: string; }
export function moduleCommandSubject(serviceName: string, protocol: string, method: string, userId: string): string;
export function moduleQuerySubject(serviceName: string, protocol: string, method: string, userId: string): string;
export function modulePingSubject(serviceName: string): string;   // `$SRV.PING.${serviceName}-queries`
export function generateUlid(): string;                            // movido desde core/src/ulid.ts
```

- `{version}` es el `protocol` del módulo, no `PROTOCOL_VERSION` de core.
- `serviceName` se valida contra `^[a-z][a-z0-9-]{1,40}$` antes de armar el subject (sin inyección de tokens por `.`, `*`, `>`).
- `generateUlid` se mueve sin cambiar la implementación; core re-apunta su import.

### Mapa de errores de docs

`lib/modules/docs/errors.ts`, propio del módulo (no se mezcla con `STATUS_BY_ERROR_CODE` de core):

| Status | Códigos |
|---|---|
| 400 | `invalid_fields`, `invalid_cursor`, `file_name_invalid`, `frontmatter_invalid`, `invalid_relation`, `content_too_large`, `checksum_mismatch`, `upload_not_found`, `attachment_type_not_allowed`, `attachment_too_large`, `share_expiry_invalid`, `secret_warning_not_acknowledged`, `semantic_search_not_configured` |
| 403 | `permission_denied`, `sharing_blocked`, `unknown_caller`, `caller_not_authorized` |
| 404 | `document_not_found`, `folder_not_found`, `attachment_not_found`, `share_not_found` |
| 409 | `version_conflict`, `document_locked`, `lock_not_held`, `already_exists`, `folder_not_empty` |
| 503 | `upstream_unavailable`, `attachments_not_configured` |
| 504 | `query_timeout` |
| 500 | `internal_error` y cualquier código desconocido |

Cuerpo de error: `{ code, message, details? }` donde `code` es el `errorCode` de jiku-docs sin traducir y `details` su `errorDetails` verbatim (DD-7; `errorBody` de `protocol.ts` hoy descarta `errorDetails`). Sin reply: timeout → `504 gateway_timeout`; `no responders` → `503 module_unavailable` y re-ping inmediato. `upstream_unavailable` no marca al módulo como `unavailable`.

### Cambios de Base de Datos

Ninguno.

### Flujo de Interacción

#### Escenario: descubrimiento y estado (CA-2 a CA-8)

**Trigger:** arranque de la api; cambio de la clave `docs`; temporizador de 30 s.

1. **[api — registry, al arrancar]** `kv = js.views.kv('JIKU_MODULES', { bindOnly: true })`; `kv.get('docs')`. Sin entrada → `not_installed`. Bucket inexistente o bus caído → `not_installed` + log de error + reintento a los 30 s (DD-6: no tumba la api).
2. **[api]** Con entrada: valida contra `ModuleRecord`; `protocol !== 'v1'` → `incompatible` + `logger.error('[modules] docs: protocolo v2 no soportado (soportado: v1)')`. JSON inválido → `incompatible` + log, el watch sigue.
3. **[api → NATS]** `request('$SRV.PING.jiku-docs-queries', '', { timeout: 2000 })`: respuesta → `available`; `no responders`/timeout → `unavailable`.
4. **[api]** `kv.watch({ key: 'docs' })`: `PUT` vuelve al paso 2; `DEL`/`PURGE` → `not_installed`.
5. **[api, cada 30 s]** repite el ping con registro `v1`.
6. **[cualquier ruta de docs]** `no responders` → `unavailable` inmediato + re-ping.

**Outcome:** `GET /modules` refleja el estado sin reinicios.

**Manejo de errores:** ver arriba; el estado vive en memoria por réplica (DD-5), dos réplicas pueden discrepar hasta 30 s.

### Consideraciones Técnicas

**Seguridad:**
- `serviceName` del registro se valida antes de entrar a un subject.
- La api llama a jiku-docs con `actor: { id }` solamente (DD-1); `sendCommand`/`withActor` de core no se reusan para docs.

**Performance:**
- Un ping cada 30 s por réplica y un consumidor efímero de watch por réplica: despreciable.

**Dependencias:**
- Concentra el riesgo técnico nuevo (KV y watch en nats.js 2.29). Se prueba con el doble del bus (`api/tests/mocks/bus.ts`, extendido con respuestas de módulo y KV simulado) y, contra el bus real, con los permisos de S-075.
