# S-093: opus-web: requisito no disponible o sin acceso

**Status:** Ready
**Created:** 2026-10-26
**Source:** REQ-020

## Historia de Usuario

**Como** usuario externo del portal opus-web que abre un requisito interno o sin permiso,
**quiero** ver un aviso claro de que no está disponible o no tengo acceso, con salida al tablero,
**para** no quedarme ante un error genérico con un "Reintentar" que nunca va a funcionar.

## Criterios de Aceptación

### CA-1: Requisito no disponible o sin acceso

**DADO** un externo en opus-web que abre un requisito interno (la api responde 403 o 404)
**CUANDO** carga la página o el modal de detalle
**ENTONCES** ve un estado de "no disponible o sin acceso" con explicación, un botón para volver al tablero del proyecto y ningún botón "Reintentar"

### CA-2: Error de sistema

**DADO** un error de red o 5xx al cargar el requisito en opus-web
**CUANDO** se muestra el error
**ENTONCES** sigue ofreciendo "Reintentar" (también en el modal)

### CA-3: Sin reintento automático en 403/404

**DADO** una respuesta 403 o 404 al cargar el requisito
**CUANDO** `useRequirement` falla
**ENTONCES** no se hace un reintento automático antes de mostrar el estado

## Technical Design

|----------|---------|-------------------|--------|

### Cambios de API

Ninguno. Se consume igual `GET /opus/requirements/{reqid}`: `404 requirement_not_found` (requisito `internal`, para todo rol) o `403 access_denied`.

### Cambios de Base de Datos

Ninguno.

### Decisiones de diseño

- **DD-7 — Clasificación.** Helper `classifyRequirementError(error): 'not_found' | 'system'` en `features/requirements/utils/`: `status` 403 o 404, o `code` `requirement_not_found` / `access_denied` → `not_found`; cualquier otro (5xx, red: el interceptor de `lib/axios.ts` deja `status: 500`, `code: 'unknown_error'`) → `system`. Mismo criterio que `classifyDocumentError` (DD-3 de REQ-016): no se distingue "no existe" de "sin permiso".
- **DD-8 — Estado "no disponible o sin acceso".** Componente compartido `RequirementUnavailable` con título/explicación *"El requisito no está disponible o no tenés acceso"* y botón **"Volver al tablero"**.
  - **Página** (`requirements/[requirementId]/page.tsx`): `not_found` muestra cabecera mínima (`{proyecto} › Requisitos`, salida a `/projects/{projectId}/requirements`) + `RequirementUnavailable`, sin "Reintentar". El caso "query resuelta sin datos" (`page.tsx:49-61`) cae en el mismo estado. `system` conserva "Error al cargar el requisito" + "Volver al listado" + "Reintentar".
  - **Modal** (`RequirementDetailModal.tsx:48-60`): `not_found` → `RequirementUnavailable` donde "Volver al tablero" es `onClose()`. `system` → texto actual + "Reintentar" (`refetch`) + cerrar (hoy el modal no ofrece reintentar).
  - Composición visual según `detalle-requisito.md` (revisión UX aplicada): cabecera mínima, `aviso-no-disponible`, `boton-volver-tablero` primary; desktop centrado con sidebar, mobile arriba a ancho completo.
- **DD-9 — `useRequirement` no reintenta 403/404.** `retry: (count, error) => classifyRequirementError(error) === 'system' && count < 1` (el global `queryClient.ts:7` tiene `retry: 1`).
- Un 401 sigue redirigiendo a `/login` desde el interceptor de `lib/axios.ts`.

### Flujo de Interacción

#### Escenario: externo abre un requisito interno (CA-1 a CA-3)

**Trigger:** el externo abre página o modal de detalle de un requisito.

**Flujo:**

1. **[opus-web / `useRequirement`]**
   - Acción: `GET /api/opus/requirements/{id}` (route handler same-origin que agrega el token)
   - Output: 404 `requirement_not_found` o 403 `access_denied`

2. **[opus-web]**
   - Acción: `classifyRequirementError` → `not_found`; sin reintento de TanStack
   - Output: `RequirementUnavailable` con "Volver al tablero", sin "Reintentar"

**Outcome:** el externo entiende que no está disponible y vuelve al tablero.

**Manejo de errores:**
- Red o 5xx → `system` → un reintento automático → "Error al cargar el requisito" + "Reintentar"
