# S-078: Rutas de lectura de documentación

**Status:** Ready
**Created:** 2026-10-24
**Source:** REQ-016

## Historia de Usuario

**Como** frontend de Jiku (web u opus-web),
**quiero** rutas HTTP de lectura de documentación que llamen a jiku-docs en nombre de la persona,
**para** mostrar documentos, carpetas, versiones, búsqueda y adjuntos respetando lo que jiku-docs le permite ver a cada persona.

## Criterios de Aceptación

### CA-16: Listado en nombre de la persona

**DADO** el módulo `available` y una persona interna autenticada
**CUANDO** llama `GET /docs/documents?projectId=12`
**ENTONCES** la api llama `documents.list` con `filter.projectId: 12` y `actor.id` igual al de la sesión, y responde 200 con la página que devolvió jiku-docs

### CA-19: Adjunto con redirección

**DADO** un adjunto de un documento que la persona puede leer
**CUANDO** llama `GET /docs/attachments/{id}`
**ENTONCES** responde 302 a la `downloadUrl` de jiku-docs; si no puede leerlo, 404 `attachment_not_found`

### CA-S3: Composición del detalle (ruta 2)

**DADO** un documento legible
**CUANDO** se llama `GET /docs/documents/{id}`
**ENTONCES** la respuesta es el documento con `folder: { id, path, effectivePermission, sharingBlocked }`, resuelto con `documents.get` y luego `folders.get`

### CA-S4: Superficie del portal solo con documentos públicos (DD-3, DD-4)

**DADO** una persona externa
**CUANDO** llama `GET /opus/docs/documents?projectId=12`, o pide un documento por id
**ENTONCES** el listado fuerza `filter.visibility: public`, exige permiso sobre el proyecto (y requisito público si filtra por requisito), y un documento no `public` responde 404 `document_not_found`

### CA-S5: Estado del módulo en las rutas

**DADO** el módulo `not_installed` o `unavailable`
**CUANDO** se llama cualquier ruta de esta story
**ENTONCES** responde 404 `module_not_installed` o 503 `module_unavailable` respectivamente

### Cambios de API

#### Endpoints Existentes a Modificar

Ninguno.

#### Nuevos Endpoints

Superficie interna: `hasAnyRole(['admin','user'])`, `actor: { id: req.user.id }`, antes `requireModule('docs')`. Las respuestas son el `data` de jiku-docs sin transformar; los listados responden `{ items, page }`.

| # | Ruta | Llama a | Payload |
|---|---|---|---|
| 1 | `GET /docs/documents` | `documents.list` | `filter`: `projectId`, `requirementId`, `taskId`, `clientId`, `folderId`, `pathPrefix`, `topic`; `sort` default `["-updatedAt"]`; `page: { limit, cursor }`; `include: ["lock"]` |
| 2 | `GET /docs/documents/{id}` | `documents.get` + `folders.get` | `{ id, version?, include: ["content","relations","topics","lock","attachments"] }`; luego `folders.get { id: folderId, include: ["effectivePermission"] }` |
| 3 | `GET /docs/documents/{id}/versions` | `documents.versions.list` | `{ filter: { documentId }, sort: ["-version"], page }` |
| 4 | `GET /docs/search` | `documents.search` | `{ query: q, mode: "text", filter, limit }` |
| 5 | `GET /docs/topics` | `topics.list` | `{ filter: { prefix? }, page }` |
| 6 | `GET /docs/folders` | `folders.list` | `{ filter: { parentId?, pathPrefix? }, sort: ["name"], page, include: ["effectivePermission"] }` |
| 7 | `GET /docs/folders/{id}` | `folders.get` | `{ id, include: ["effectivePermission"] }` |
| 17 | `GET /docs/attachments/{id}` | `attachments.{id}.request-download` | `{}` → **302** a `downloadUrl` |

- La ruta 17 responde `302 Location`, `X-Content-Type-Options: nosniff`, sin cuerpo y sin `res.redirect()` (mismo criterio que `redirectToPresigned`).
- Documento con `contentUrl` (> 256 KiB): se devuelve tal cual.

Superficie del portal: `hasAnyRole(['external-user','admin','user'])`, solo lectura.

| # | Ruta | Middlewares | Llama a |
|---|---|---|---|
| 21 | `GET /opus/docs/documents?projectId=` o `?requirementId=` (uno obligatorio) | `requireModule`, `validateProjectPermissions`, `validateRequirementIsPublic` si filtra por requisito | `documents.list` con `filter: { projectId | requirementId, visibility: "public" }` |
| 22 | `GET /opus/docs/documents/{id}` | `requireModule` | `documents.get` (`include: ["content","attachments"]`); 404 `document_not_found` si `visibility !== "public"` |
| 23 | `GET /opus/docs/attachments/{id}` | `requireModule` | `attachments.{id}.request-download` → 302 |

### Flujo de Interacción

#### Escenario: listado de documentos de un proyecto (CA-16)

**Trigger:** `GET /api/docs/documents?projectId=12` con Bearer.

1. **[api — docs-documents-get.ts]** `requireModule('docs')` → `hasAnyRole` → Joi → `moduleQuery('docs', 'documents.list', { actor: { id }, filter: { projectId: 12 }, sort: ['-updatedAt'], page: { limit: 50 }, include: ['lock'] })`.
2. **[NATS → jiku-docs]** `dev.{apiUserId}.jiku-docs-queries.v1.documents.list`; jiku-docs filtra por ACL.
3. **[api]** responde 200 con el `data` tal cual.

**Outcome:** documentos que la persona puede leer.

**Manejo de errores:**
- `permission_denied` → 403; `document_not_found` → 404; `upstream_unavailable` → 503 con el mensaje de jiku-docs; `query_timeout` → 504.

### Flujos Afectados

- **documentos-desde-la-web** (ref: docs/flows/documentos-desde-la-web.md) — Flujo nuevo (S-085).

### Consideraciones Técnicas

**Seguridad:**
- La api no autoriza el dominio de documentación (DD-2): autentica, rutea por superficie y traduce errores; jiku-docs es la autoridad. El portal agrega defensa en profundidad (DD-3, DD-4).
- No se loguean contenidos de documentos ni URLs prefirmadas.

**Performance:**
- La ruta 2 hace dos consultas en serie (~2x latencia de bus); aceptado.
- Timeouts existentes: `NATS_QUERY_TIMEOUT_MS` 10 s.

**Dependencias:**
- Depende de S-077 (cliente de módulo, `requireModule`, mapa de errores).
