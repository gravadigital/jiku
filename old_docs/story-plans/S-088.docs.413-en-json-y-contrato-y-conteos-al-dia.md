### Lo implementado: el código que hay que documentar

#### api — `api/app.ts` (commit `4cbbad2`)

```ts
/**
 * DD-3 de REQ-017: el 413 de body-parser (`entity.too.large`, de cualquiera de los parsers: el de
 * /api/docs con 768 KiB o el global con 100 kb) sale con la forma de error de toda la api en lugar del
 * HTML del finalhandler. Cuatro argumentos, y todo lo que no reconoce sigue su camino con next(err): el
 * 404 del fallback de arriba y cualquier otro error no cambian. No loguea: es un error del cliente, y en
 * /p/docs/* la URL lleva el token del link.
 */
function payloadTooLargeHandler(err: any, _req: Request, res: Response, next: NextFunction) {
  if (err?.type === 'entity.too.large' && !res.headersSent) {
    return res.status(413).json({
      code: 'payload_too_large',
      message: 'El cuerpo de la solicitud supera el límite permitido',
    });
  }
  return next(err);
}
// ...al final de initialize(), después del fallback 404:
// DD-3: AL FINAL de la cadena, para recibir el error de cualquier parser sin interceptar nada más.
app.use(payloadTooLargeHandler);
```

Notas de origen (para el texto de las secciones):

- `/api/docs/*` y `/api/opus/docs/*`: `requireModule('docs')` → 404 `module_not_installed` si jiku-docs
  no está instalado, 503 `module_unavailable` si no responde al registro, 504 `gateway_timeout` si la
  consulta o el comando no vuelven a tiempo (`api.yaml`, `ModuleNotInstalled`, `ModuleUnavailable`,
  `ModuleGatewayTimeout`). La api **no autoriza el dominio**: el rol solo deja pasar, los permisos por
  carpeta los aplica jiku-docs (`permission_denied`) (ADR-015, DD-2).
- `/api/opus/docs/*`: sirve solo documentos `public`, para todo rol (DD-3 de REQ-016); la ficha y el
  adjunto de uno que no lo es responden 404 `document_not_found`; un adjunto que no pertenece al
  documento pedido, 404 `attachment_not_found` (S-087).
- `/api/modules`, `/api/opus/modules`: estado de los módulos opcionales en memoria (`listModules()`), no
  hablan con el bus por request. Sin `validateProjectPermissions` (excepción anotada a ADR-008).
- `/p/docs/*`: montadas en la raíz, no bajo `/api`; la **única** exención de `validateToken`
  (`api/config/public.ts`: `get: ['p/docs/']`). Control propio: host público exclusivo
  (`JIKU_PUBLIC_URL`, 404 en cualquier otro host), rate limit de 60/min/IP, token de 256 bits que valida
  jiku-docs contra su hash, 404 indistinguible para cualquier link inválido y cabeceras de solo
  lectura (CSP, `noindex`, `no-store`). Responden HTML, no JSON. Hablan con jiku-docs por
  `shares.resolve` / `shares.attachment` (`api/lib/modules/docs/public-share.ts`).
- "Bus" en estas filas significa que la request **consulta o manda un comando a jiku-docs** por el bus
  (`moduleQuery` / `moduleCommand` / `queryShare`), no a `core` (DP-3).

### Flow Context

El único flujo afectado es `documentos-desde-la-web`. Escenario de la story (CA-2), verbatim:

1. **[web]** envía `PUT /api/docs/documents/{id}` con un cuerpo mayor a 768 KiB.
2. **[api]** `docsWriteJson` (body-parser, `limit: '768kb'`) lanza `PayloadTooLargeError`
   (`type: 'entity.too.large'`); el manejador nuevo, al final de la cadena de `app.ts`, lo atiende →
   `413 { "code": "payload_too_large", "message": "El cuerpo de la solicitud supera el límite permitido" }`.

**Outcome:** el cliente recibe un 413 JSON con la forma del resto de la api, en lugar del HTML de
`finalhandler`. **Manejo de errores:** cualquier otro error → `next(err)` (sin cambio).
