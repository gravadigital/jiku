## Story Reference

- **Story:** [S-081](../stories/S-081.web-estado-del-modulo-panel-y-visor.md)
- **Service:** `web`
- **Summary:** Abre el módulo `features/docs/` de la web: consulta el estado del módulo opcional
  de documentación (`GET /modules`, al iniciar, cada 60 s y ante `module_unavailable`), muestra la
  card **"Documentación"** en las fichas de proyecto, requisito y tarea, agrega el ítem
  condicional de la sidebar, y publica la página `/docs/[id]` **en modo lectura** con un visor
  markdown seguro que reescribe los enlaces a adjuntos hacia el route handler
  `/docs/attachments/[id]` (sesión → api → 302). Sin módulo instalado no aparece nada.

**Fuera de esta story (no implementar acá):** editor, reserva de edición, conflicto de versión,
subida de adjuntos, página `/docs` (carpetas + búsqueda) y overlay O-11 → **S-082**. Botón
"Compartir" y overlay O-12 → **S-083**. Por eso en `/docs/[id]` **no** se renderizan
`boton-editar`, `boton-compartir`, `aviso-bloqueado`, `aviso-documento-grande` ni ningún bloque de
edición.

> **Brecha transitoria conocida:** el ítem "Documentación" de la sidebar, el breadcrumb y
> "Volver" de `/docs/[id]` apuntan a `/docs`, que crea **S-082**. Entre S-081 y S-082 `/docs`
> responde 404. Las dos stories son del mismo REQ (REQ-016) y el corte de release cae sobre un REQ
> cerrado, así que la brecha no llega a una versión publicada. No crear una página provisoria.

### Service Architecture

`web` es `type: frontend`, `language: nextjs`. Todas sus convenciones son **custom**
(`docs/architectures/web/conventions/`).

**Estructura relevante:**

```
web/src/
├── app/
│   ├── providers.tsx              QueryClient + Session + Theme + Project + Sidebar
│   ├── (loggedin)/                grupo protegido: guard en layout.tsx (auth() + redirect)
│   │   ├── layout.tsx             shell: <ShellSidebar> + <main> + toasts; force-dynamic
│   │   ├── ShellSidebar.tsx       'use client' — NAV_ITEMS, getVisibleNavItems, resolveActiveKey
│   │   ├── projects/[id]/page.tsx          ficha de proyecto ('use client')
│   │   ├── requirements/[reqid]/page.tsx   ficha de requisito → RequirementDetailContainer
│   │   ├── objectives/[id]/page.tsx        ficha de tarea (server) → ObjectiveDetails + historial
│   │   └── docs/[id]/page.tsx              NUEVO (esta story)
│   ├── docs/attachments/[id]/route.ts      NUEVO — FUERA de (loggedin): no hay guard, valida sesión solo
│   └── api/attachments/[id]/download/route.ts   patrón a copiar (302 propagado)
├── features/
│   ├── attachments/components/MarkdownViewer/   visor existente (se extiende)
│   ├── auth/hooks/usePersons.ts                 personas (resolver `sub` → nombre)
│   ├── projects/ requirements/ objectives/ clients/   hooks de detalle por id
│   └── docs/                                    NUEVO módulo (esta story)
├── shared/components/ui/          Card, Table, Badge, EmptyState, Loader, Button, ViewHeader...
├── shared/utils/                  decodedToken, cn, labelFromDate, formatDate
└── lib/axios.ts                   apiClient (baseURL `${API_URL}/api`) + ApiError
```

**Módulos de dominio:** cada uno en `src/features/{m}/` con `components/`, `hooks/`, `services/`,
`types/` y `utils/`; el barrel `index.ts` es la superficie pública.

**Decisión estructural vigente:** *"una ruta nueva fuera de `(loggedin)/` no tiene ningún guard"*.
`src/app/docs/attachments/[id]/route.ts` vive afuera a propósito (D-5: el link estable de adjuntos
es `{JIKU_WEB_URL}/docs/attachments/{id}`) y por eso **valida la sesión por sí mismo**.

**Datos en tres capas:** componente cliente → hook (`useQuery`) → Server Action (`'use server'`,
`apiClient`) → api. Una página de servidor puede llamar a la Server Action directamente.

**Manejo de errores:** el interceptor de axios normaliza todo fallo a
`ApiError { code, message, status }` (`src/lib/axios.ts`) y redirige a `/login` ante un 401 en el
navegador. Estados de datos de un componente, en orden: **loading → error → empty → happy path**.

**Logging:** ESLint permite solo `console.warn` / `console.error`. Nunca loguear token, sesión ni
datos personales; **nunca loguear contenido de documentos ni URLs prefirmadas** (REQ-016 §Seguridad).

**Testing:** Vitest + Testing Library; se mockea la capa de **services** (al testear un hook) o de
**hooks** (al testear un componente). **No** se mockea `apiClient` ni `fetch` global **salvo** en
route handlers (patrón de `api/attachments/[id]/download/route.test.ts`) y en la Server Action que
descarga `contentUrl`. Nombres de test en español; consultas por rol y nombre accesible.

### Relevant ADRs

- **ADR-009: Token confinado al servidor**
  - Decision: el access token de Zitadel vive solo en el servidor de Next; el navegador nunca lo ve.
  - Implementation Rules:
    - El access token **NO DEBE** llegar al navegador por ningún camino: ni en el bundle, ni en una
      respuesta, ni en una cookie legible por JS.
    - La URL de la api **DEBE** leerse de `API_URL` **en el servidor, en runtime**. **NO SE DEBE**
      usar `NEXT_PUBLIC_API_URL` ni ninguna variable horneada en build.
    - En `web`, toda llamada de dominio **DEBE** ir por un Server Action (`'use server'`) con
      `apiClient`. Un route handler en `app/api/` **DEBE** justificarse por una capacidad que el Server
      Action no tenga (streaming, headers de respuesta, llamada desde componente cliente).
    - En `opus-web`, toda llamada **DEBE** ir por el proxy `/api/opus/[...path]`. **NO SE DEBE**
      agregar un cliente axios que apunte directo a `API_URL` desde el navegador.
    - Todo route handler que reenvíe a la api **DEBE** exigir sesión y responder
      `401 {"error":"Unauthorized"}` si no hay `accessToken`. La única excepción vigente es
      `GET /attachments/[id]/[fileName]` de `opus-web`, cuya autorización la decide la api.
    - Al reenviar respuestas binarias, **DEBEN** propagarse `Content-Type`, `Content-Disposition` y
      `Content-Length`.
    - Al reenviar uploads **DEBE** usarse streaming con `duplex: 'half'`, no bufferizar el archivo
      entero en memoria.
    - Un 401 de la api **DEBE** redirigir el navegador a `/login`.
    - **NO SE DEBE** agregar `NEXT_PUBLIC_*` funcional: rompería la premisa de una imagen por todos los
      entornos.
  - Nota para esta story: el route handler de adjuntos **no reenvía binario**: propaga el 302 (como
    `api/attachments/[id]/download`), así que la regla de cabeceras binarias no aplica.

- **ADR-011: TanStack Query**
  - Implementation Rules:
    - Todo dato que venga de la api **DEBE** manejarse con TanStack Query. **NO SE DEBE** copiar una
      respuesta a `useState` ni a un store global.
    - Las query keys **DEBEN** seguir el patrón por dominio: `['<dominio>', <identificador o filtros>]`.
    - Tras una mutación exitosa **DEBE** invalidarse la key afectada. Al invalidar por prefijo, hay que
      verificar que el prefijo cubra lo que se pretende.
    - Las mutations **DEBEN** mantener `retry: 0`. Reintentar una escritura sin idempotencia
      garantizada duplicaría datos ([ADR-002](ADR-002-comandos-nats-sin-jetstream.md)).
    - El update optimista **DEBE** usarse solo donde el rollback sea trivial y la latencia se note. **NO
      SE DEBE** aplicar por default.
    - El estado propio de la interfaz **DEBE** usar `useState` local. Un Context nuevo **DEBE**
      justificarse por tener consumidores reales.
    - En listados paginados por categoría, **DEBE** evaluarse el costo de montar N queries en paralelo:
      el tablero del portal monta 7 y su `isLoading` es un `some`, así que la pantalla espera a la más
      lenta.

- **ADR-010: Sass + CSS Modules sin librería**
  - Implementation Rules:
    - Los estilos de un componente **DEBEN** vivir en su `*.module.scss` adyacente. **NO SE DEBE**
      usar CSS global salvo en `globals.scss` y en la capa de tokens.
    - Los valores de color, espaciado y tipografía **DEBEN** referenciar custom properties de
      `_variables.scss`. **NO SE DEBEN** hardcodear valores hexadecimales ni píxeles sueltos.
    - Los patrones visuales repetidos (tipografía, botones, inputs, tags, focus rings) **DEBEN** usar
      los mixins de `_mixins.scss`.
    - Los breakpoints **DEBEN** declararse con los mixins de `_mixins.scss`. **NO SE DEBEN** escribir
      `@media` crudas con valores literales — hoy hay 14 en `web` con 8 valores distintos, y es deuda
      reconocida (NFR-U03).
    - **NO SE DEBE** agregar una librería de componentes ni un framework CSS utilitario sin un ADR que
      lo reemplace.
    - En `opus-web`, las variantes de componente **DEBEN** expresarse con atributos `data-*`, no con
      nombres de clase compuestos.
    - Un valor de token **DEBE** declararse en un solo lugar.
  - **Precisión vigente (convención `styling`, REQ-013):** los tokens se consumen del **tier
    semántico o de componente** (`_semantic.scss` / `_component.scss`), **nunca** primitivos ni hex.
    `_variables.scss` es el sistema viejo: el guardia `features/design-system-migration.guard.test.ts`
    falla si se reintroducen sus tokens, hex literales, radios fuera de 8/10/14/999, `<button>` o
    `<table>` crudos, o tipografía literal en cualquier `.tsx` / `.module.scss` de `web/src`.

### API Context

Todas las llamadas salen de Server Actions con `apiClient` (Bearer inyectado por el interceptor).
El `baseURL` ya incluye `/api`: se llama `apiClient.get('/modules')`, no `/api/modules`.

**`GET /modules`** — `x-roles: [admin, user, external-user]`, `x-jiku-module: docs`

> Estado de los módulos opcionales (hoy solo `docs`). `incompatible` (protocolo no soportado o
> registro inválido) se informa como `not_installed`; `features` se omite con `not_installed`.
> `features.sharing` es `true` solo si `JIKU_PUBLIC_URL` está definida y no vacía. El estado vive en
> memoria por réplica: dos réplicas pueden discrepar hasta 30 s.

```yaml
ModulesResponse:
  type: array
  items:
    type: object
    required: [module, status]
    properties:
      module: { type: string }
      status: { type: string, enum: [not_installed, unavailable, available] }
      features:
        type: object
        description: Se omite con `not_installed`
        properties:
          sharing: { type: boolean }
```

Ejemplos verbatim: `[{ module: docs, status: not_installed }]` ·
`[{ module: docs, status: unavailable, features: { sharing: false } }]` ·
`[{ module: docs, status: available, features: { sharing: true } }]`. Respuestas: 200, 401, 403, 500.

**`GET /docs/documents`** — `x-roles: [admin, user]`. Llama a `documents.list`. Responde el `data`
de jiku-docs **sin transformar**.

| Query param | Tipo |
|---|---|
| `projectId` | integer ≥ 1 — **incluye documentos vinculados a requisitos o tareas del proyecto** |
| `requirementId` | integer ≥ 1 |
| `taskId` | integer ≥ 1 |
| `clientId` | integer ≥ 1 |
| `folderId` | string ULID `^[0-9A-HJKMNP-TV-Z]{26}$` |
| `pathPrefix` | string 1-500 |
| `topic` | string 1-500 |
| `sort` | enum `updatedAt, -updatedAt, createdAt, -createdAt, title, -title, path, -path`, default `-updatedAt` |
| `limit` | integer 1-200, default 50 |
| `cursor` | string ≤ 500 — `page.cursor` de la respuesta anterior; **su ausencia es el fin** |

Un parámetro no declarado es **400 `invalid_fields`**: no mandar claves vacías ni `undefined`.
Respuesta `200 DocsDocumentPage = { items: DocsDocument[], page: DocsPageInfo }`. La api pide
`include: ['lock']`, así que cada ítem trae `lock`. Errores: 400 `ModuleBadRequest`, 401, 403
`ModuleForbidden`, **404 `ModuleNotInstalled`** (`module_not_installed`), 500, **503
`ModuleUnavailable`** (`module_unavailable` | `upstream_unavailable` | `attachments_not_configured`),
504 `ModuleGatewayTimeout` (`gateway_timeout` | `query_timeout`).

**`GET /docs/documents/{id}`** — `x-roles: [admin, user]`. `id` ULID; `version` opcional (integer ≥ 1).
Llama a `documents.get` + `folders.get`. **Única composición de la api:**
`{ ...document, folder: { id, path, effectivePermission, sharingBlocked } }`. Un documento de más de
256 KiB trae `contentUrl` en lugar de `content`. Un `id` mal formado responde **404
`document_not_found`** sin llamar al bus. Errores: 400, 401, 403, **404 `ModuleNotFound`**
(`module_not_installed` | `document_not_found` | ...), 500, 503, 504.

**`GET /docs/attachments/{id}`** — `x-roles: [admin, user]`. Publica
`attachments.{id}.request-download` y **responde 302** (sin cuerpo, sin `Content-Type` ni
`Content-Disposition`), cabeceras `Location: <downloadUrl prefirmada>` y
`X-Content-Type-Options: nosniff`. `HEAD` responde igual. Si la persona no puede leer el documento,
**404 `attachment_not_found`**; un `id` mal formado responde 404 `attachment_not_found` sin
publicar. Otros: 401, 403, 500, 503, 504.

**Cuerpo de error (`ModuleError`):** `{ code: string, message: string, details?: object }` — `code`
es el `errorCode` del módulo sin traducir. El interceptor de `apiClient` lo proyecta a
`ApiError { code, message, status }` (descarta `details`, que esta story no necesita).

**Schemas de respuesta (api.yaml, verbatim de `jiku-docs-queries.yaml` 1.1.0):**

Formato de rutas (jiku-docs): la `path` de una carpeta empieza y termina con `/` (la raíz es `/`,
una subcarpeta `/clientes/acme/`); la de un documento es la ruta de su carpeta más el nombre de
archivo. **La columna "Ruta" de la card es la carpeta**: `path.slice(0, path.lastIndexOf('/') + 1)`.

### Flow Context

El flujo `documentos-desde-la-web` (`docs/flows/documentos-desde-la-web.md`) es **nuevo y todavía
no está escrito** (lo escribe S-085). Se copia el diseño de REQ-016, escenarios B y D, que es la
fuente actual:

**Escenario B — panel de documentos en la ficha de proyecto (CA-16, CA-25 a CA-27)**

**Trigger:** una persona interna abre `/projects/12` en la web.

1. **[web — `useModule('docs')`]** `GET /modules` (Server Action, TanStack Query,
   `refetchInterval: 60_000`; invalidado al recibir `module_unavailable`). `not_installed` → **no
   se monta el panel ni el ítem de navegación** (CA-25).
2. **[web — `DocsPanel`]** `available` → Server Action `listDocuments({ projectId: 12 })` →
   `GET /api/docs/documents?projectId=12` con Bearer.
3. **[api — `docs-documents-get.ts`]** `requireModule('docs')` → `hasAnyRole(['admin','user'])` →
   Joi → `moduleQuery('docs', 'documents.list', { actor: { id: req.user.id }, filter: { projectId:
   12 }, sort: ['-updatedAt'], page: { limit: 50 }, include: ['lock'] })`.
4. **[NATS → jiku-docs]** subject `dev.{apiUserId}.jiku-docs-queries.v1.documents.list`. jiku-docs
   resuelve la clase de la persona del `actor`, filtra por ACL y responde `{ status: "success",
   data: { items: [ { id, title, path, folderId, version, visibility, updatedAt, updatedBy, lock } ],
   page: { limit, returned, cursor? } } }`.
5. **[api]** `200` con el `data` tal cual.
6. **[web]** Panel con título, ruta y fecha de actualización; cada fila abre `/docs/{id}` (CA-26).

**Outcome:** documentos vinculados al proyecto, a sus requisitos o tareas, que la persona puede leer.
**Manejo de errores:** `unavailable` → panel visible con aviso "documentación no disponible" y
acciones deshabilitadas (CA-27); `upstream_unavailable` → 503 con el mensaje de jiku-docs.

### Code Conventions

- **Server Action:** `features/docs/services/{recurso}Api.ts`, `'use server'` en la primera
  línea, tipo de retorno explícito, devuelve `response.data` (nunca el objeto de axios). Filtros
  vacíos/`undefined` se descartan antes de armar los params (la api responde 400 a claves no
  declaradas).
- **Hook de query:** `features/docs/hooks/use{Recurso}.ts`, `'use client'`, un único objeto
  `options` con defaults, `enabled` siempre expuesto, el hook no transforma datos (salvo `select`
  documentado).
- **Query keys:** `['modules']`, `['docs-documents', filters]`, `['docs-document', id]`.
- **Componentes:** carpeta por componente con `Componente.tsx`, `Componente.module.scss`,
  `Componente.test.tsx`, `index.ts`. Clases CSS en camelCase; `cn()` para clases condicionales
  (nunca template strings). El módulo SCSS empieza con `@use '@/styles' as *;` si usa mixins.
- **Route handler:** preámbulo `decodedToken()` → `401 { error: 'Unauthorized' }`; `fetch` nativo
  (no `apiClient`); URL `${process.env.API_URL}api/...` (sin `/` entre medio: `API_URL` termina en

- **Tipos:** escritos a mano, **verbatim de `jiku-docs-queries.yaml`**, con comentario de cita en el
  archivo (R-8). Fechas tipadas `string` (ISO), no `Date`.
- **Textos de UI:** español rioplatense, verbatim de los screen.md.

**Patrón a copiar — `src/app/api/attachments/[id]/download/route.ts`:**

```ts
export const GET = async (
  _request: NextRequest,
  { params }: { params: Promise<{ id: string }> }
) => {
  const token = await decodedToken();
  if (!token?.accessToken) {
    return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });
  }
  const { id } = await params;
  const response = await fetch(`${process.env.API_URL}api/attachments/${id}/download`, {
    redirect: 'manual',
    headers: { Authorization: `Bearer ${token.accessToken}` },
  });
  const location = response.headers.get('Location');
  if (location) {
    return new NextResponse(null, {
      status: 302,
      headers: { Location: location, 'X-Content-Type-Options': 'nosniff' },
    });
  }
  const errorData = await response.json().catch(() => ({ message: 'Download failed' }));
  return NextResponse.json(errorData, { status: response.status });
};
```

- **Versión fijada:** `web` **v4.2.0** (normativo, implementado).
- **Accent color de la superficie:** `color.brand.primary` = verde agua `#61CCB9` (sin cambios entre

**DS Gaps para `web`:**

- **Aceptados** (Revisión UX de REQ-016, resolución "Dejar anotado"):
  - **`alert`** (aviso-documentacion-no-disponible, aviso-no-disponible, aviso-not-found) — *"`web`
    no tiene componente de aviso inline. Se usa en 5 pantallas y 2 overlays de este REQ, así que es

  - `toast` y `modal` — no los usa esta story.
- **Nuevos:** ninguno. `contenido-documento` → `MarkdownViewer` (resuelto en el REQ como
  "Reemplazar"); `lista-vinculos`, `lista-adjuntos-documento` y `breadcrumbs` se marcan con `<ul>` /
  `<nav>` + `Link` (contenedores de layout, no gaps); `lista-temas` → `Badge`.

### Task 6: Route handler `/docs/attachments/[id]` (sesión → api → 302)

**Status:** Completed

#### Description

Link estable de adjuntos de documentación en la web (`{JIKU_WEB_URL}/docs/attachments/{id}`, D-5):
vive **fuera** de `(loggedin)`, valida la sesión por sí mismo, pide a la api con el Bearer y

#### Acceptance Criteria

4. `fetch(\`${process.env.API_URL}api/docs/attachments/${encodeURIComponent(id)}\`, { redirect: 'manual', headers: { Authorization: \`Bearer ${token.accessToken}\` } })` (TS-41).
5. Respuesta con `Location` → `new NextResponse(null, { status: 302, headers: { Location, 'X-Content-Type-Options': 'nosniff' } })` (TS-41). La `Location` no se loguea.

7. Test estructural de ruteo (R-6): el handler está fuera de `(loggedin)` y no hay `route.ts` bajo `(loggedin)/docs/` (TS-46). La otra mitad de R-6 (`/docs/attachments` sin id → `notFound()` en la página) se cubre en T7 (TS-47).

#### Technical Details

**Architectural Context References:**
