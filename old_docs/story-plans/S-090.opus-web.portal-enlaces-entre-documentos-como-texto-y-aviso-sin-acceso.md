# Story Plan: S-090 (opus-web) - Portal: enlaces entre documentos como texto y aviso sin acceso

## Status

**Status:** Completed

## Story Reference

- **Story:** [S-090](../stories/S-090.portal-enlaces-entre-documentos-como-texto-y-aviso-sin-acceso.md)
- **Service:** `opus-web`
- **Origen:** [REQ-019](../requests/REQ-019.actor-completo-hacia-jiku-docs-y-ajustes-del-portal-de-documentos.md)
- **Summary:** En el visor del portal, los enlaces a otros documentos (`/docs/{ULID}`, relativos o con
  cualquier host) se ven como texto, sin `<a>`, y la regla alcanza a todo enlace que el filtro ya
  vaciaba. La sección "Documentación" del tablero y del detalle de requisito distingue "sin acceso"
  (403 o `caller_not_authorized`) de "no disponible" con un mensaje propio.

> **Precondición verificada sobre el árbol (2026-10-25, rama `feat/jiku-docs`):** existen
> `src/features/docs/utils/docsUrlTransform.ts` (exporta `createDocsUrlTransform(documentId)`, S-087),
> `DocumentMarkdown` (override `a` que hoy renderiza `<a href={href || undefined} target="_blank">`),
> `DocsSection` (con `query.isError` hoy: `module_not_installed` → nada; cualquier otro → aviso de no
> disponible), `DocsAlert` y `src/features/docs/constants/docs.constants.ts` (`MSG_DOCS_UNAVAILABLE`,
> `ULID_PATTERN`). Sin cambios de API ni de base de datos. Sin dependencias bloqueantes (independiente
> de S-089, que ya está completada).
>
> **Nota de nombre:** la story dice `docsUrlTransform`; desde S-087 la función es la fábrica
> `createDocsUrlTransform(documentId)` en el archivo `docsUrlTransform.ts`. Este plan modifica esa
> fábrica.

### Fuera de alcance (declarado, para no improvisarlo)

- **El visor del documento ante un 403** (DD-9): `classifyDocumentError` ya lo trata como
  `not_found` a propósito (DD-3 de REQ-016). No tocar `DocumentView` ni `classifyDocumentError`.
- **Comparar el host contra `JIKU_WEB_URL`** (DD-6): el portal no conoce el host de la web interna;
  el criterio es solo el path.
- **Aviso visible en el enlace convertido a texto** ("documento no disponible", tooltip, ícono): la UX
  lo resolvió como texto plano, *"sin aviso"*.
- **Botón "Reintentar" en el estado sin acceso**: el screen.md lo descarta (*"reintentar no lo
  arregla"*).

### Convenciones activas que aplican (extracto)

**error-handling (custom de opus-web):**

- Todo error de red sale del interceptor como `ApiError` plano (`src/lib/axios.ts`):
  ```ts
  export interface ApiError { code: string; message: string; status: number; }
  // errorInterceptor:
  code: error.response?.data?.code ?? 'unknown_error',
  message: error.response?.data?.message ?? 'Error desconocido',
  status: error.response?.status ?? 500,
  ```
- *"Un `catch` nunca recibe un `AxiosError`. Recibe un `ApiError` plano. Por eso el patrón para
  tiparlo es `const apiError = error as ApiError`"*.
- *"Los tres campos siempre existen. Un fallo de red sin respuesta da
  `{code:'unknown_error', message:'Error desconocido', status:500}`"* → un error de red cae en "no
  disponible" (CA-5) sin lógica extra.
- *"El 401 no llega al componente como un error a mostrar"*: el interceptor redirige a `/login`.
- El proxy catch-all `/api/opus/[...path]` reenvía `status` y cuerpo de la api tal cual, así que el
  403 y su `code` llegan al interceptor.

**testing-unit (custom de opus-web):**

- Tests de componentes/utils **junto al código**.
- **Mockear los hooks de datos, no la red** (`vi.mock('../../hooks/useModules')`,
  `vi.mock('../../hooks/useDocuments')`, como el test actual de `DocsSection`).
- *"No mockear `react-markdown` en un test: ya está aliaseado globalmente."* El mock
  (`__mocks__/react-markdown.tsx`) aplica `urlTransform` a `href` y `src` y llama a `components.a({ href, children })`
  como función: un override que devuelve `<>{children}</>` funciona igual en el mock y en react-markdown real.
  El mock soporta `[texto](url)` con `#`/`?` en la URL, `mailto:` e imágenes.
- Aserciones por rol y texto (`getByRole`, `getByText`); no `getByTestId` si hay rol o texto.

**styling:** sin cambios visuales nuevos; no se tocan `.module.scss`. El texto que reemplaza a un
enlace hereda el estilo del párrafo.

### API Context

**Sin cambios de API.** opus-web consume los status y `code` que la api ya devuelve.

`GET /api/opus/docs/documents` (de `docs/apis/api.yaml`, verbatim):

```yaml
/opus/docs/documents:
  get:
    tags: [opus]
    summary: Lista documentos públicos (portal)
    x-jiku-module: docs
    x-roles: [external-user, admin, user]
    description: |
      … Orden de las verificaciones: rol, forma, carga del proyecto o requisito (404 `project_not_found` /
      `requirement_not_found`), permiso de proyecto para `external-user` (403 `access_denied`) y, si filtra
      por requisito, que sea público (404 `requirement_not_found`). jiku-docs aplica además su regla de
      externos (`public`, proyecto permitido, carpeta sin `externalBlocked`).
    responses:
      '200': { DocsDocumentPage }
      '400': { $ref: '#/components/responses/ModuleBadRequest' }
      '401': { $ref: '#/components/responses/Unauthorized' }
      '403': { $ref: '#/components/responses/ModuleForbidden' }
      '404': { $ref: '#/components/responses/ModuleNotFound' }
      '500': { $ref: '#/components/responses/InternalError' }
      '503': { $ref: '#/components/responses/ModuleUnavailable' }
      '504': { $ref: '#/components/responses/ModuleGatewayTimeout' }
```

`ModuleForbidden` (verbatim):

```yaml
ModuleForbidden:
  description: Rol insuficiente (`access_denied`) o permiso que niega jiku-docs (`permission_denied`)
  examples:
    accessDenied:        { code: access_denied, message: Access denied }
    permissionDenied:    { code: permission_denied, message: Sin permiso }
    sharingBlocked:      { code: sharing_blocked, message: La carpeta no permite links compartidos }
    callerNotAuthorized: { code: caller_not_authorized, message: El caller no está autorizado }
```

Otros cuerpos que llegan a `DocsSection`: `404 { code: 'module_not_installed', message: 'El módulo docs no está instalado' }`,
`503 { code: 'module_unavailable' }`, `504 { code: 'gateway_timeout' }`, red caída →
`{ code: 'unknown_error', message: 'Error desconocido', status: 500 }`.

**Regla de clasificación de `DocsSection` (DD-8, verbatim de la story):** con `query.isError`:
(1) `code === 'module_not_installed'` → nada; (2) `status === 403` o `code === 'caller_not_authorized'` →
`DocsAlert` con `MSG_DOCS_FORBIDDEN`; (3) cualquier otro → `MSG_DOCS_UNAVAILABLE`.

**Regla del `urlTransform` (DD-6, verbatim de la story):** nueva regex, evaluada **después** de la de
adjuntos:

```ts
/^(?:https?:\/\/[^/?#\s]+)?\/docs\/([0-9A-HJKMNP-TV-Z]{26})(?:[?#].*)?$/  // → ''
```

No se compara con `JIKU_WEB_URL`. Orden resultante: adjunto → reescrito al proxy; documento → `''`;
`http(s)`/`mailto` → pasa; resto → `''`.

**Decisiones (verbatim):**

- tablero-requisitos: *"**"Sin acceso" deja de verse como "módulo caído".** Hasta ahora cualquier error de la consulta mostraba `"Los documentos no están disponibles en este momento. Probá de nuevo en unos minutos."`; para un externo que no tiene acceso eso es falso, y el consejo de reintentar lo hace volver a algo que nunca va a funcionar. Un estado propio con un texto propio separa "no se pudo saber" de "no te corresponde" [REQ-019 RF-9, DD-8]."*
- detalle-requisito: *"**Mismo estado "sin acceso" que en el tablero, con el mismo texto.** La sección es el mismo componente con `requirementId`; … Dice "de este proyecto" también acá porque el permiso del cliente es por proyecto, no por requisito."*

**documento — contenido-documento, Annotation (verbatim, parte REQ-019):** *"**REQ-019: un enlace a
otro documento se ve como texto.** Todo enlace cuyo path sea `/docs/{id}` —relativo o con cualquier
host, con o sin `?`/`#`— conserva su texto visible y **no se renderiza como `<a>`** (ni siquiera sin
`href`): esos enlaces apuntan a la web interna, que el cliente no puede abrir. Mismo resultado que en
el link compartido. La regla alcanza a todo enlace que el filtro vacía (`javascript:`, `data:`,
`//host`). Los adjuntos, los demás `http(s)` y `mailto` siguen como enlaces [REQ-019 RF-7, RF-8,
DD-6, DD-7, CA-6 a CA-8]"*

**documento — Interacción (verbatim):** *"enlace a otro documento (`/docs/{id}`) en el contenido · sin
evento: es texto, no navega [REQ-019 DD-7]"*

**documento — Decisiones REQ-019 (verbatim):**
- *"**Se reconoce por el path, no por el host.** El portal no conoce el host de la web interna y no tiene por qué; el criterio es el mismo que ya se usa para adjuntos [REQ-019 DD-6]."*
- *"**"Texto" quiere decir sin `<a>`, no un `<a>` sin `href`.** Un ancla sin destino sigue siendo foco de teclado y se anuncia como enlace; un fragmento de texto no. La regla se extiende a los otros enlaces que el filtro ya vaciaba [REQ-019 DD-7]."*
- *"**Los estados del visor no cambian.** El 403 ya se trata como `not found` ("no existe o no está compartido con vos") a propósito [REQ-016 DD-3] [REQ-019 DD-9]."*

## Hallazgos y decisiones de este plan

- **Nombre de la función.** La story habla de `docsUrlTransform`; el código vigente (desde S-087) es
  `createDocsUrlTransform(documentId)` en `docsUrlTransform.ts`. El plan cambia la fábrica y conserva su
  firma.
- **Borde de la regex de DD-6 (TS-7).** Un enlace absoluto `…/docs/{ULID}/algo` no matchea (el ULID
  tiene que cerrar el path) y, por ser `http(s)`, sigue como enlace. Es la regex verbatim de la story; si
  la web interna llegara a generar sub-rutas de documento, habría que ampliarla en otro REQ. La variante
  relativa de ese caso igual se vacía (falla `new URL`).
- **`caller_not_authorized` con status ≠ 403 (TS-15).** La api lo devuelve como 403, pero DD-8 lo pide
  por `code` también; el test fija la rama `OR`.
- **TS-21 existente se ajusta**, como prevé DD-7: hoy asierta "sin `href`", ahora "sin `<a>`".
- **Gap de DS `alert`** — aceptado en la Revisión UX de REQ-019 ("Dejar anotado"); se usa `DocsAlert`.
- **Documentación de arquitectura y flujo** (`overview.md`, `index.md` de `opus-web`, flujo
  `documentos-desde-la-web`) quedan para el servicio `docs` de esta story; el catálogo
  `docs/reusable-code/opus-web/` es del propio servicio y se actualiza en Task 4.
