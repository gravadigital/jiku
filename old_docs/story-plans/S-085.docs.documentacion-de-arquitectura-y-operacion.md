## Architectural Context

> **Esta story no escribe código.** El "servicio" es la documentación del monorepo. El
> Architectural Context de abajo **no es contexto para implementar**: es la fuente de verdad contra
> la que se escribe la documentación, con la ruta del archivo de código que respalda cada
> afirmación. Regla de la story: **si lo implementado difiere de lo diseñado en REQ-016, gana lo
> implementado y se anota en el ADR**. Si `docs/apis/*.yaml` y el código discrepan, **manda el
> documento** y la discrepancia se reporta como bug (no se "arregla" el yaml en esta story).

#### api — registro y estado (`api/lib/modules/registry.ts`)

- `ModuleStatus = 'not_installed' | 'incompatible' | 'unavailable' | 'available'`; hacia afuera
  `PublicModuleStatus` sin `incompatible` (se informa como `not_installed`).
- `SUPPORTED_PROTOCOL = 'v1'`, `MODULE_CHECK_INTERVAL_MS = 30000`, `MODULE_PING_TIMEOUT_MS = 2000`.
- Logs literales: `[modules] docs: {from} -> {to}` (info), `[modules] docs: no se pudo leer el
  registro (...); reintento en 30 s`, `[modules] docs: registro inválido (...)`,
  `[modules] docs: protocolo {x} no soportado (soportado: v1)` (error).
- Decisiones de implementación (S-077, "Resultados"): deduplica entradas idénticas del watch (el
  watch re-entrega el valor vigente); arma el watch **antes** de esperar el primer ping.
- Un fallo al arrancar (bus caído, KV inexistente) → `not_installed` + log + reintento a los 30 s
  (DD-6): la api arranca igual. `docsModule.start()` se llama después de conectar el bus (`app.ts:102`).
- `no responders` en una llamada → `unavailable` inmediato + re-ping. `upstream_unavailable` (core
  no respondió a jiku-docs) **no** marca el módulo.
- Cliente del bus (`api/lib/utils/bus/index.ts:251-258`): `views.kv(MODULES_BUCKET, { bindOnly:
  true, allow_direct: true })`. **`allow_direct: true` no es opcional**: con `bindOnly` nats.js
  2.29 deja `direct = false` y `get()` iría a `$JS.API.STREAM.MSG.GET.*`, que ninguna plantilla
  autoriza (autorizan `$JS.API.DIRECT.GET.*`). Ping: `request(modulePingSubject(serviceName),
  Empty, { timeout })`. El watch nunca rechaza: el registro lo reabre en el próximo tick.

#### api — embudo de llamadas (`api/lib/modules/client.ts`)

- JSDoc verbatim: *"EXCEPCIÓN A ADR-001: acá la api LEE por el bus, porque la documentación no está
  en su base (se documenta como ADR-015 en S-085)."*
- DD-1: siempre `actor: { id }` (solo `id`), inyectado **después** del spread (gana el del token).
  Sin identidad verificada → **401 sin publicar** (falla cerrado: un llamado sin `actor` jiku-docs lo
  trata como el propio servicio, clase `service`, que lee todo). No se reusan `sendCommand` ni
  `withActor` (su sobre es `invalid_fields` para jiku-docs).
- `payload` y `options` nunca se loguean.
- Sin reply: timeout → `504 { code: 'gateway_timeout' }`; inalcanzable → `503 module_unavailable`.
- La opción `anonymous` existe sin llamadores en producción (P-9 de S-080): las rutas públicas usan
  `sendToModule` porque responden HTML, no JSON.

#### api — mapa de errores del módulo (`api/lib/modules/docs/errors.ts`)

Propio del módulo, **no** se mezcla con `STATUS_BY_ERROR_CODE` de core. Cuerpo `{ code, message,
details? }`: `code` = `errorCode` sin traducir; `details` = `errorDetails` verbatim (la clave no
existe si no viene). Código desconocido → 500 conservando el `code`.

| Status | Códigos |

| 400 | `invalid_fields`, `invalid_cursor`, `file_name_invalid`, `frontmatter_invalid`, `invalid_relation`, `content_too_large`, `checksum_mismatch`, `upload_not_found`, `attachment_type_not_allowed`, `attachment_too_large`, `share_expiry_invalid`, `secret_warning_not_acknowledged`, `semantic_search_not_configured` |
| 403 | `permission_denied`, `sharing_blocked`, `unknown_caller`, `caller_not_authorized` |
| 404 | `document_not_found`, `folder_not_found`, `attachment_not_found`, `share_not_found` |
| 409 | `version_conflict`, `document_locked`, `lock_not_held`, `already_exists`, `folder_not_empty` |
| 503 | `upstream_unavailable`, `attachments_not_configured` |
| 504 | `query_timeout` |
| 500 | `internal_error` y cualquier código desconocido |

Locales de la api: `module_not_installed` (404), `module_unavailable` (503), `gateway_timeout`
(504), `sharing_not_configured` (404, `'Los links compartidos no están configurados'`),
`share_not_found` local (`'Link compartido no encontrado'`). Id de path malformado → 404

#### api — cableado en `api/app.ts` (orden real)

1. `app.set('trust proxy', parseTrustProxy(API_TRUST_PROXY))` si viene.
2. **`publicHostOnly` — primer middleware** (DD-10): en el host de `JIKU_PUBLIC_URL` solo pasan
   `GET`/`HEAD` de `/p/docs/<algo>`; todo lo demás, 404 genérico, antes de `validateToken`.
3. `cors()` — por eso `Access-Control-Allow-Origin: *` llega también a `/p/docs/*` (hallazgo 3 de S-080).
4. `app.use('/api/docs', docsWriteJson)`: `express.json({ limit: '768kb' })` solo para `POST`/`PUT`
   bajo `/api/docs` (`DOCS_WRITE_BODY_LIMIT`); el resto conserva los 100 kb de body-parser (S-079).
5. `express.json()`, logger de requests con `ignoreRoute` para `/p/docs/*` (el token va en la URL;
   esas rutas loguean su propia línea con el token enmascarado `jds_…`).
6. `validateToken` global para **cinco** métodos (`get`, `patch`, `post`, `put`, `delete`) — `put`
   desde H-3 (`config/public.ts`); `week-assigned-times-put.ts` ya no declara su propio `validateToken`.
7. `app.use(publicRoutes)` en la raíz; luego el barrel de `lib/routes` bajo `/api`.

`config/public.ts`: **una sola exención**, `get: ['p/docs/']`. Las otras cuatro listas vacías.

#### api — ruta pública `/p/docs/*`

Cadena (`lib/public-routes/index.ts:20`): `publicDocsHeaders` → `publicDocsAccessLog` →
`requirePublicHost` → `publicDocsRateLimit` → handler → `publicDocsNotFound`. En el handler: token
que no cumple `^jds_[A-Za-z0-9_-]{43}$` → 404 sin bus; módulo `not_installed`/`incompatible` → 404
genérico, `unavailable` → 503 genérico; cualquier error de jiku-docs → el **mismo** 404.

Cabeceras de toda respuesta (`api/lib/modules/docs/public-page.ts:11-17`):

```
Content-Security-Policy: default-src 'none'; img-src 'self' https: data:; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
X-Robots-Tag: noindex
Referrer-Policy: no-referrer
Cache-Control: private, no-store
X-Content-Type-Options: nosniff
```

Decisiones de S-080 a documentar: `client` (`ClientInfo` `ip` ≤ 100, `userAgent` ≤ 2000) en
`shares.resolve`/`shares.attachment` para la auditoría de jiku-docs (P-1); `assertPublicUrlConfig`
corta el arranque si `JIKU_PUBLIC_URL` no es URL, no es http(s) o trae path/query/fragmento (P-3);
timeout del bus en la ruta pública → 503 (P-5); falla de `htmlUrl` o reply sin `html` → 503 + log
sin URL (P-6); host comparado contra el `Host` **crudo**, nunca `X-Forwarded-Host` (P-7); **un solo
limitador** para página e imágenes (P-8); rate limit `express-rate-limit`, `MemoryStore` por réplica,
`windowMs 60000`, `limit 60`, `standardHeaders: 'draft-8'`.

Cada fila tiene un destino. Ninguna se pierde: si no entra en un documento público, entra en ADR-015.

### Relevant ADRs

#### ADR-001 — Separación lectura/escritura (excepción nueva)

Implementation Rule afectada (verbatim): *"Un endpoint que lee **NO DEBE** pasar por el bus: la
lectura va directo a PostgreSQL desde la api. **Excepción declarada desde REQ-001 (S-005): la
lectura de archivos.** […] Ver "Revisión: la lectura de archivos"."* Precedente de forma: la sección
`## Revisión: la lectura de archivos (REQ-001 / S-005, 2026-08-19)` del mismo ADR. ADR-015 es la
segunda excepción: la documentación no está en la base de la api.

#### ADR-008 — Deny-by-default (exención nueva)

Implementation Rules (verbatim, las que aplican): *"`validateToken` **DEBE** instalarse globalmente
en `app.ts`. **NO SE DEBE** declarar autenticación ruta por ruta."* · *"Un endpoint público **DEBE**
agregarse explícitamente a `api/lib/config/public.ts`. Cualquier cambio en ese archivo es un
**cambio de seguridad**"* · *"Un endpoint público **DEBE** validar por su cuenta lo que corresponda.
El caso vigente (`GET /api/opus/attachments/:id/public`) …"* (ese caso fue eliminado en REQ-002; el
vigente ahora es `/p/docs/*`) · *"Un endpoint accesible a `external-user` **DEBE** además verificar
permiso de proyecto"* (DD-4: el detalle por id del portal es la excepción anotada).

#### ADR-006 — Dos frontends, una api

DD-3 aplica la regla de superficie del portal (`visibility: public` forzado). DD-4 deja el detalle
por id (`/opus/docs/documents/{id}`, `/opus/docs/attachments/{id}`) sin permiso de proyecto:
excepción anotada, cubierta por la regla de externos de jiku-docs.

#### ADR-009 — Token confinado al servidor

Regla: *"un route handler responde `401 {"error":"Unauthorized"}` si no hay `accessToken`"* y *"Un 401
de la api **DEBE** redirigir el navegador a `/login`"*. Discrepancia F-20.

#### ADR-002 / ADR-007 / ADR-014

ADR-002 (request/reply sin JetStream): jiku-docs replica la gramática
`{instance}.{user-id}.{svc}.{version}.{método}` y el sobre `Reply`. ADR-007 (Zitadel +
auth-callout): el rol `docs` es un rol de Zitadel traducido por `rules.yaml`. ADR-014: el stream
`JIKU_DOCS_EVENTS` es de jiku-docs, no de Jiku; Jiku no lo crea.
