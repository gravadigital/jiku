### Reusable Code

#### `Pagination` — el componente a reutilizar

`web/src/shared/components/ui/Pagination/Pagination.tsx`. **Ya existe y no se modifica en esta
story.** Contrato completo (copiado del código):

```ts
interface PaginationBaseProps {
  readonly totalItems: number;
  readonly limit: number;
}

type PaginationUrlProps = PaginationBaseProps & {
  readonly basePath: string;          // modo URL
  readonly currentPage?: never;
  readonly onPageChange?: never;
};

type PaginationControlledProps = PaginationBaseProps & {
  readonly currentPage: number;       // modo controlado  ← EL QUE USA ESTA STORY
  readonly onPageChange: (page: number) => void;
  readonly basePath?: never;
};
```

Comportamiento observable relevante:

- **La unión es discriminada por `onPageChange`**: pasar `currentPage` + `onPageChange` selecciona
  modo controlado, y TypeScript **prohíbe** pasar `basePath` a la vez (`basePath?: never`).
- **Calcula `totalPages` internamente**: `Math.ceil(totalItems / limit)`. El consumidor pasa
  `totalItems` y `limit`, **no** `totalPages`.
- **Devuelve `null` si `totalItems === 0`** (línea 71-73): con la tab vacía el paginador no se
  renderiza. Esto es un cambio observable respecto del inline actual, que siempre dibuja el `<nav>`
  con un botón "1".
- Renderiza `<nav aria-label="Paginación" role="navigation">`.
- Botones anterior/siguiente con texto **`<` y `>`** (no `‹`/`›`) y `aria-label="Página anterior"` /
  `"Página siguiente"`; `disabled` en los extremos.
- Cada número es un `<button>` con `aria-label="Página N"`, `aria-current="page"` y `disabled`
  cuando es la página actual, más `data-active` para el estilo.
- **No dibuja elipsis**: `getPageWindow` devuelve números contiguos.
- Aunque esté en modo controlado, el componente **llama a `useSearchParams()` incondicionalmente**
  (línea 40). Consecuencia directa para los tests: cualquier suite que renderice este componente
  necesita `useSearchParams` en el mock de `next/navigation`.

#### `getPageWindow` — la ventana deslizante

`web/src/shared/components/ui/Pagination/getPageWindow.ts`:

```ts
const PAGE_WINDOW_SIZE = 10;

export function getPageWindow({ currentPage, totalPages }: GetPageWindowParams): number[] {
  if (totalPages <= 0) return [];
  if (totalPages <= PAGE_WINDOW_SIZE) {
    return Array.from({ length: totalPages }, (__, index) => index + 1);
  }
  const idealStart = currentPage - Math.floor(PAGE_WINDOW_SIZE / 2);
  const maxStart = totalPages - PAGE_WINDOW_SIZE + 1;
  const start = Math.min(Math.max(idealStart, 1), maxStart);
  const end = start + PAGE_WINDOW_SIZE - 1;
  return Array.from({ length: end - start + 1 }, (__, index) => start + index);
}
```

Casos que fijan las aserciones de los tests:

| `totalPages` | `currentPage` | Ventana devuelta |
|---|---|---|
| 5 | 1 | `[1,2,3,4,5]` (todas: ≤ 10) |
| 25 | 1 | `[1..10]` (pegada al inicio) |
| 25 | 13 | `[8..17]` (centrada: `13 - 5 = 8`) |
| 25 | 25 | `[16..25]` (pegada al final: `maxStart = 16`) |

### T-1: Migrar el paginador de la tabla de tareas al componente `Pagination` controlado

**Status:** Completed
**Categoría:** Logic / UI
**Dependencias:** Ninguna

#### Descripción

Reemplazar el bloque de paginación reimplementado inline en
`web/src/features/requirements/components/RequirementDetail/RequirementDetail.tsx` (líneas 228-283)
por el componente compartido `Pagination` en modo controlado, envuelto junto al `<select>` de tamaño
de página en un contenedor `.paginationRow`, replicando el patrón de `ProjectRequirementsSection`.

#### Criterios de Aceptación

- El `<nav className={styles.objPagination}>` completo (líneas 228-283) queda eliminado.
- En su lugar hay un `<div className={styles.paginationRow}>` que contiene, en este orden:
  1. `<Pagination totalItems={filtered.length} limit={objPageSize} currentPage={page} onPageChange={setObjPage} />`
  2. El `<select className={styles.perPageSelect}>` con las opciones `5 por página` y `10 por página`,
     preservando su `onChange` actual (`setObjPageSize(Number(...))` + `setObjPage(1)`).
- El import `import { Pagination } from '@/shared/components/ui/Pagination';` se agrega respetando el
  orden de imports del archivo (los `@/` van antes de los relativos `../`).
- El estado local `objPage` / `objPageSize` **se conserva tal cual**: no se introduce `useSearchParams`
  ni `router.push` para la paginación (CA-2).
- El cálculo de las líneas 180-183 se conserva **sin cambios**, incluido
  `const page = Math.min(objPage, totalPages)` (CA-3).
- **`totalItems` recibe `filtered.length`, no `totalPages`.** El componente calcula
  `Math.ceil(totalItems / limit)` internamente; pasarle un total de páginas produciría una paginación
  silenciosamente incorrecta.
- `onPageChange` recibe `setObjPage` directamente: el componente entrega el número de página absoluto,
  no un delta.

#### Detalles Técnicos

**Referencias del Architectural Context:**
- *Reusable Code → `Pagination`*: contrato de props y unión discriminada por `onPageChange`.
- *Reusable Code → `ProjectRequirementsSection`*: el precedente literal de S-038 a replicar.
- *Code Conventions → `state-management`*: la página de esta tabla es estado local y así se queda.

**Detalle sobre `totalPages` y el reajuste:** hoy `totalPages` se calcula con
`Math.max(1, Math.ceil(filtered.length / objPageSize))`, y ese `Math.max(1, …)` es lo que hace que
`page` valga `1` cuando la lista está vacía. Se conserva porque `page` sigue usándose para el
`slice`. Con `filtered.length === 0` el componente devuelve `null` por su cuenta (no dibuja nada),
así que la variable local `totalPages` deja de tener consumidores en el JSX pero **sigue siendo
necesaria** para el reajuste de CA-3. Si el linter marca la variable como no usada, verificar antes
de borrarla: la usa la línea `const page = Math.min(objPage, totalPages)`.

**Cambio observable a documentar en el commit:** con la tab activa vacía, el paginador desaparece en
vez de dibujar un `[‹][1][›]` inerte.
