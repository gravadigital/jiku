### Lo que la `api` ya hace con estas variables (implementado, plan api)

**`JIKU_PUBLIC_URL`** — `api/lib/modules/docs/public-url.ts`:

```ts
export function publicDocsHost(): string | null {
  const raw = (process.env.JIKU_PUBLIC_URL || '').trim();
  if (!raw) return null;
  try { return new URL(raw).host.toLowerCase(); } catch { return null; }
}

export function isPublicHostRequest(req: Request): boolean {
  const host = publicDocsHost();
  return !!host && (req.headers.host || '').toLowerCase() === host;
}

export function assertPublicUrlConfig(): void {   // llamado en bin/index.ts al arrancar
  const raw = (process.env.JIKU_PUBLIC_URL || '').trim();
  if (!raw) return;                                // vacía = links apagados, válido
  let url: URL;
  try { url = new URL(raw); } catch { throw new Error('JIKU_PUBLIC_URL no es una URL válida'); }
  if (url.protocol !== 'http:' && url.protocol !== 'https:') throw new Error('JIKU_PUBLIC_URL tiene que usar http: o https:');
  if ((url.pathname !== '/' && url.pathname !== '') || url.search || url.hash)
    throw new Error('JIKU_PUBLIC_URL tiene que ser solo el origen: sin path, query ni fragmento');
}
```

Consecuencias directas para el despliegue:

- **Vacía** → `/p/docs/*` responde 404 genérico y `GET /modules` informa `features.sharing: false`
  (CA-22, DD-13). Es el estado por defecto: los links compartidos son **opt-in**.
- **`https://` pelado** (lo que daría `https://${DOCS_PUBLIC_DOMAIN}` sin guarda con la variable vacía)
  → `new URL('https://')` lanza → **la api no arranca**. Ver H-1.
- **El host se compara contra el `Host` crudo** (`req.headers.host`), nunca contra
  `X-Forwarded-Host`. `nginx-proxy` enruta por `Host` y lo preserva, así que en producción el `Host` que
  llega a la api es exactamente `DOCS_PUBLIC_DOMAIN`.
- **DD-10, recíproco:** en el host público la api **no sirve nada más** (404 a todo lo que no sea
  `/p/docs/*`). Si `DOCS_PUBLIC_DOMAIN` fuera igual a `api.${DOMAIN}`, la api dejaría de atender a los
  dos frontends. Ver H-3.

**`API_TRUST_PROXY`** — `api/lib/utils/trust-proxy.ts` (se aplica con `app.set('trust proxy', …)`):

```ts
 *   ausente / en blanco -> undefined (no se setea: default de Express, sin proxy)
 *   '1', '2'…           -> número de saltos (Number). El string '1' Express lo leería como IP.
 *   'true' | 'false'    -> booleano
 *   otro                -> string tal cual (lista de IP/subredes, 'loopback', 'uniquelocal'…)
```

Un valor inválido (`'basura'`) hace lanzar a Express → la api no arranca (deseado). El rate limit de
`/p/docs/*` (60/min/IP, CA-23) usa `req.ip`: **sin `trust proxy` detrás del ingress todas las IP son la
del proxy** y un visitante agota el cupo de todos (DD-11). Con `1`, `req.ip` es la IP que `nginx-proxy`
agrega a `X-Forwarded-For`. **Sin proxy delante** (local, dev) tiene que quedar vacía: si no, cualquier
cliente falsea `X-Forwarded-For` y esquiva el límite.

Texto vigente en `api/.env.dist` / `api/.env.defaults` (no se toca):

```
# URL pública de los links compartidos: {JIKU_PUBLIC_URL}/p/docs/{token}. Solo el origen (sin path,
# query ni fragmento) o la api no arranca. La api sirve /p/docs/* SOLO en este host y, en este host,
# nada más (DD-10). Vacía: los links quedan apagados (features.sharing=false y /p/docs/* da 404).
# Debe coincidir con la JIKU_PUBLIC_URL de jiku-docs. Local: http://127.0.0.1:3100
JIKU_PUBLIC_URL=
# Saltos de proxy de confianza para el rate limit de /p/docs/* (60/min/IP). Vacía detrás de un proxy:
# todas las IP son la del proxy y un visitante agota el cupo de todos. Vacía SIN proxy: correcto
# (un cliente podría falsear X-Forwarded-For y esquivar el límite). Producción (ingress): 1
API_TRUST_PROXY=
```

### Precedente: `OPUS_DOMAIN` → `OPUS_URL` (REQ-015 / S-071)

Es el mismo problema resuelto antes, y este plan copia su forma:

- `.env.dist` declara **solo el host** (`OPUS_DOMAIN=`, vacío, sin esquema ni barra); la URL con
  esquema **no** se declara en el `.env` (dos variables con el mismo dominio se desincronizan).
- Producción arma la URL en el compose: `- OPUS_URL=https://${OPUS_DOMAIN}`.
- Local y dev **no** la derivan del dominio (no hay ingress): va **fija** al puerto publicado
  (`- OPUS_URL=http://localhost:3001` / `http://localhost:3002`).
- Lo cubren tests estructurales que leen los compose por líneas:
  `core/tests/notifications/structure.test.ts` TS-37b / TS-38 / TS-38b, por ejemplo:

```ts
it('TS-38b · OPUS_URL se deriva de OPUS_DOMAIN en producción y es fija en dev/local', () => {
  const lineFor = (file: string) =>
    readFileSync(join(REPO_ROOT, 'deploy', file), 'utf8')
      .split('\n')
      .map((line) => line.trim())
      .find((line) => line.startsWith('- OPUS_URL='));

  lineFor('docker-compose.yml')!.should.equal('- OPUS_URL=https://${OPUS_DOMAIN}');
  lineFor('docker-compose.local.yml')!.should.equal('- OPUS_URL=http://localhost:3001');
  lineFor('docker-compose.dev.yml')!.should.equal('- OPUS_URL=http://localhost:3002');
});
```

**La diferencia con OPUS:** `OPUS_DOMAIN` es obligatorio (sin él no hay portal); `DOCS_PUBLIC_DOMAIN`
es **opcional** (vacío = links apagados). Por eso la URL no puede armarse sin guarda (H-1).

### Hallazgos del planeamiento (completan el diseño de la story)

**H-1 · La interpolación anidada funciona, y la guarda es obligatoria también en `JIKU_PUBLIC_URL`.**
La story pide verificar `${DOCS_PUBLIC_DOMAIN:+,${DOCS_PUBLIC_DOMAIN}}`. Se verificó durante el
planeamiento con Compose v5.6.0 y un compose descartable (`docker compose config`, sin levantar nada):

| `.env` | `VIRTUAL_HOST=api.${DOMAIN}${DOCS_PUBLIC_DOMAIN:+,${DOCS_PUBLIC_DOMAIN}}` | `JIKU_PUBLIC_URL=${DOCS_PUBLIC_DOMAIN:+https://${DOCS_PUBLIC_DOMAIN}}` | `API_TRUST_PROXY=${API_TRUST_PROXY:-1}` |
|---|---|---|---|
| `DOCS_PUBLIC_DOMAIN=` (declarada vacía) | `api.example.com` | `""` | `"1"` |
| `DOCS_PUBLIC_DOMAIN=docs.example.com` | `api.example.com,docs.example.com` | `https://docs.example.com` | `"1"` |
| `DOCS_PUBLIC_DOMAIN` ausente del `.env` | `api.example.com` | `""` | `"1"` |

**Decisión:** se usa la forma anidada (no hace falta el plan B de "dos variables por separado").
`JIKU_PUBLIC_URL` lleva **la misma guarda `:+`**: la forma de OPUS (`https://${DOCS_PUBLIC_DOMAIN}`)
daría `https://` con la variable vacía y `assertPublicUrlConfig` cortaría el arranque de la api en
**todas** las instalaciones que no usan links. La verificación se repite contra los compose reales en
Task 6.

**H-2 · Local y dev: `JIKU_PUBLIC_URL` fija, no derivada de `DOCS_PUBLIC_DOMAIN`.** Mismo criterio que
`OPUS_URL`: sin ingress el host público es un puerto publicado y el esquema es `http`. Valores:

- `docker-compose.local.yml` → `- JIKU_PUBLIC_URL=http://127.0.0.1:3100`. Es el valor de la story (CA-20,
  "Local") y **el mismo que trae `conectores/jiku-docs/.env.dist`** (`JIKU_PUBLIC_URL=http://127.0.0.1:3100`,
  que jiku-docs **exige**: `internal/config/config.go:211`), así que los dos coinciden sin editar nada.
  `http://localhost:3100/api/...` sigue siendo la aplicación y `http://127.0.0.1:3100/p/docs/...` el host
  público: mismo puerto, **otro `Host`**.
- `docker-compose.dev.yml` → `- JIKU_PUBLIC_URL=http://127.0.0.1:3000` (la api de dev publica `3000:3000`;
  los fronts de dev están en 3001/3002, que **no** chocan con el host público porque es otro puerto).
- `DOCS_PUBLIC_DOMAIN` **no aparece** en local ni dev. La fila de la story ("en los tres compose") se
  cumple para lo que cada compose necesita: el dominio solo existe donde hay ingress; `JIKU_PUBLIC_URL` y
  `API_TRUST_PROXY` sí están en los tres. Se deja escrito en un comentario de cada compose para que nadie
  "complete" la variable por simetría.

**H-3 · `DOCS_PUBLIC_DOMAIN` tiene que ser un host propio.** Por DD-10, en el host público la api
responde 404 a todo lo que no sea `/p/docs/*`. Si alguien pone `DOCS_PUBLIC_DOMAIN=api.${DOMAIN}` (o
`DOMAIN`/`OPUS_DOMAIN`), la api deja de atender a los frontends. No se puede validar en el compose (son
valores del `.env`): va **en el comentario de `.env.dist` y en el README**, con la misma fuerza que el
"sin esquema" de `OPUS_DOMAIN`.

**H-4 · `LETSENCRYPT_HOST` con dos dominios = un certificado SAN.** `acme-companion` emite **un**
certificado para la lista. Si el DNS de `DOCS_PUBLIC_DOMAIN` todavía no apunta al servidor, la emisión
(o la renovación) del certificado combinado falla, y con él el de `api.${DOMAIN}` cuando le toque
renovar. Procedimiento a documentar: **apuntar el DNS primero, configurar la variable después**.

**H-5 · `API_TRUST_PROXY` en producción con default `1` en el compose.** `.env.dist` la declara
**vacía** (es la plantilla de los tres entornos: en local/dev no hay proxy) y cada compose decide el
default de su entorno: producción `${API_TRUST_PROXY:-1}` (siempre detrás de `nginx-proxy`, un salto),
local/dev `${API_TRUST_PROXY:-}` (sin proxy; `:-` evita el warning de Compose si falta del `.env`). Quien
tenga **dos** saltos (un balanceador delante del `nginx-proxy`) la sobreescribe en su `.env` (`2`, o la
lista de subredes).

**H-6 · jiku-docs tiene su propia `JIKU_PUBLIC_URL`** (externa, story: "debe coincidir con la de Jiku").
jiku-docs se despliega aparte; el README dice que su `JIKU_PUBLIC_URL` tiene que ser
`https://<DOCS_PUBLIC_DOMAIN>`. Si no coinciden, jiku-docs entrega links a un host que la api no sirve.

### Flow Context

Flujo `lectura-por-link-compartido` (se documenta en S-085). Pasos que dependen del despliegue:

1. Visitante sin sesión abre `{JIKU_PUBLIC_URL}/p/docs/{token}` → **[ingress]** `nginx-proxy` enruta
   `Host: DOCS_PUBLIC_DOMAIN` al contenedor de la `api` (por estar en su `VIRTUAL_HOST`), con TLS del
   certificado que pidió `LETSENCRYPT_HOST`, preservando `Host` y agregando `X-Forwarded-For`.
2. **[api]** host ✓ (`Host` == host de `JIKU_PUBLIC_URL`) → rate limit ✓ (por `req.ip`, correcto gracias
   a `trust proxy = 1`) → formato del token ✓ → módulo `available` ✓ → `shares.resolve`.
3. Las imágenes piden `/p/docs/{token}/attachments/{id}` en el mismo host → 302 a S3 (https).

### Integration Points

- **nginx-proxy**: acepta listas separadas por coma en `VIRTUAL_HOST`; `VIRTUAL_PORT=3000` aplica a
  todos los hosts de la lista. Se conecta a la api por la red `ingress-network` (ya presente).
- **acme-companion**: lista separada por coma en `LETSENCRYPT_HOST` → un certificado SAN (H-4).
- **jiku-docs** (externo): su `JIKU_PUBLIC_URL` debe ser idéntica a la de la api (H-6).

### Code Conventions

- Un cambio de variables se aplica **en los tres compose**, o no está aplicado.
- Los comentarios en compose y `.env.dist` explican **por qué**, en castellano, con la referencia
  `(REQ-016 / S-080)`, siguiendo el estilo de los vecinos (`OPUS_URL`, `NATS_QUERY_TIMEOUT_MS`).
- `.env.dist`: sin secretos, valores vacíos donde el operador decide; no se reordena lo existente.
- `deploy/README.md` está **en inglés** (como todo el archivo).
- Tests (convención `testing` de la api): `should` (sin `assert`/`expect`), título
  `it('S-080 · TS-n: …')`, sin parser de YAML (lectura por líneas, como `api-contract.test.ts`).
- `REPO_ROOT` desde `api/tests/utils/`: `path.join(__dirname, '..', '..', '..')`.

### Reusable Code

No aplica en `deploy/`. Para el test se reusan, de la api: `assertPublicUrlConfig` y `publicDocsHost`
